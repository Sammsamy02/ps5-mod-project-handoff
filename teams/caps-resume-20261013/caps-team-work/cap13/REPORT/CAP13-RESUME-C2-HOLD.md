# CAP13 resume: C2 compatibility path and engineering hold

2026-10-13. Mac source and receipt review only. No new build, test, console run, or modification of the loader, E2E rig, game, or #9 runtime was made for this review. Runtime citations to `NativeModEngineServices.inc` and `UObjectGlobals.cpp` refer to the sibling tree `what/outputs/2026-10-08-l26-runtime/typescan-r4/candidate/src/`.

## Decision

KF established that the staged PE mapper and the all-integer, at-most-four-argument bridge can execute Windows x64 instructions on this Mac under Rosetta. That is valuable M0 evidence. It is **not** an unchanged upstream UE4SS C++ mod pass. The locally available unchanged upstream PE files are `UE4SS.dll` (the framework) and `dwmapi.dll` (its proxy), and both were refused; the executed mod-shaped DLLs are cap13-built samples or fixtures. The closest C++-mod-shaped artifact, `REPORT/evidence/simplest-mod-census/cme_upstream_shape.obj`, explicitly calls itself a reconstruction, uses non-executed STL stand-ins, and is a COFF object, not a linked DLL (`cme_upstream_shape.cpp:1-27`). The file taxonomy is also recorded in `UNCHANGED-UPSTREAM-DLL-PATH.md:57-90`.

The highest-impact local C2 blocker is the absent **UE4SS C++ compatibility surface**, not PE mapping. `native-loader/src/ue4ss_compat.cpp:46-61,74-94` has placeholder MSVC layout and an empty illustrative export map; `native-loader/src/pe_adapter.cpp:64-71,94-121` leaves virtual dispatch and actual PE loading/registration as M1 placeholders. For the reconstructed CheatManager path, construction is a further concrete host-service gap: the real UE4SS export `StaticConstructObject` is ordinal 3562, RVA `0x1224524` (`UNCHANGED-UPSTREAM-DLL-PATH.md:228-252`), and the port runtime has the dispatcher (`what/outputs/2026-10-08-l26-runtime/typescan-r4/candidate/src/UObjectGlobals.cpp:146-197`), but `BUILD/src/sdk/mbm/NativeModAbi.h:203-240` exposes no construct service. None of these C2 steps was exercised by KF's E2E.

## Specific next source-level change and hold conditions

1. **#9 ABI owner:** append a typed `construct_object` callback after `gui` in `mbm_host_v1` (`NativeModAbi.h:203-240`), wire it through the host-service interface and concrete runtime implementation to `UObjectGlobals::StaticConstructObject`, and specify size/version negotiation. Decide explicitly whether the initial service admits only default class/outer parameters or carries the full supported parameter set; the PE shim must refuse unsupported non-defaults. `MBM_ABI_VERSION` is currently integer `1u` (`NativeModAbi.h:45-47`) and `pe_adapter.cpp:94-98` checks exact equality; “v1.1” is a proposal, not an implemented compatible version. Existing readers must never access the new tail without a `struct_size` check. This is a host ABI change, not a cap13 data row.
2. **Admission decision:** object creation changes game state. `MBM_ROUTE_DATA_ONLY_PARTIAL` is explicitly a *data-only* route with a semantic difference (`NativeModAbi.h:135-142`), so that label would be inaccurate for this service. Define a truthful state-changing service admission or keep it refused until such a policy exists; `MBM_HOOK_STATIC_CONSTRUCT_OBJECT` (`NativeModAbi.h:122`) is an observation hook, not construction.
3. **#13 C2 owner:** pin the real SDK-version layouts (`CppUserModBase` including five MSVC `wstring` members, vftable/dtor slots, `FStaticConstructObjectParameters`, and `std::function` invoke/clone/destroy representation) using a compilation unit built against the exact mod SDK headers. The current pin script `native-loader/tools/pin_msvc_layout.sh:26-43` emits layouts/assembly but neither bakes nor validates them; it also masks compiler errors with `|| true`. Implement and evidence the 13 required UE4SS rows (`UNCHANGED-UPSTREAM-DLL-PATH.md:101-132`), including a signature-specific `RegisterHook` bridge. Keep refusal for unpinned or unsupported signatures.
4. **Evidence gate:** obtain an actual unchanged upstream UE4SS C++ mod DLL, record its hash, SDK/CRT tier/imports/TLS/entry policy, then drive that same file through the completed adapter. If no such binary is available, label any linked reconstruction as a reconstruction and retain the C2 hold. KF's M0 receipt can be cited for the loader's narrower executed envelope, with the missing feature-probe case and runner accounting noted above. PS5 J1/J2/J3 remain outside this Mac review.

No credible isolated code edit under `cap13/REPORT` can close the missing host ABI, layout, callback, and adapter wiring. The concrete deliverable here is the source-located hold and C2 acceptance matrix; it does not assert unchanged-upstream mod support.
