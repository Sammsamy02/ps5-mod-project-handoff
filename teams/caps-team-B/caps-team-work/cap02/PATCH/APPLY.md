# cap02 — integration steps (integrator only)

Candidate tree: `outputs/2026-10-08-l26-runtime/typescan-r4/` (call it `<ts>`).
Teams never touch it; only the integrator runs the step below.

## What ships: PATCH/01 only (log-only shadow)

- `new-files/AutoProfileGenerator.hpp` — generic selector + renderer + build-id
  note reader + the shadow compare. No game names. Header-only.
- `new-files/AutoLayoutPacks.generated.hpp` — engine-level layout data,
  regenerated by `tools/build_packs.py` (reads only local evidence).
- `01-shadow-launch-ready.diff` — against `src/UE4SSProgram.cpp`. Adds the
  `#include` and one `[AutoProfile] shadow ...` log line on the existing
  compiled-declaration branch, wrapped in `try { } catch (...)` so it can never
  abort activation. It does not change what is staged: the armed layout stays
  byte-identical to R11.

The three files are sha-pinned in `MANIFEST.json`.

## Apply (one command; dry run first)

```
python3 -B PATCH/apply_cap02.py              # dry run: checks every pin, writes nothing
python3 -B PATCH/apply_cap02.py --execute    # applies
```

It does, in order, and stops before writing if any check fails:
1. checks the 3 patch files against `MANIFEST.json`, `<ts>/candidate/src/UE4SSProgram.cpp`
   = `121f2383…` (R11 snapshot copy), its CHANGES.json row pin = the same sha,
   the two headers not yet present, and `patch --dry-run` applies with no fuzz;
2. backs up `CHANGES.json` to `CHANGES.json.pre-cap02-20261013`;
3. copies the two headers into `<ts>/candidate/include/` (already an include
   dir: every added header's folder is put on `-I` by build_variants.py);
4. `patch -p1 --fuzz=0 -d <ts>/candidate -i PATCH/01-shadow-launch-ready.diff`
   (diff header is `a/src/UE4SSProgram.cpp`; this fixes review F1);
5. checks the result is `642b1988…`, then CHANGES.json row sync (fixes F2):
   the `files` row for `src/UE4SSProgram.cpp` gets the new `candidate_sha256`,
   both headers go into `added_headers` + `added_header_hashes`, and a
   `cap02_row_sync` record is added (same shape as `r11_row_sync`);
6. re-checks the pins the same way gate G2 does.

A second run refuses (base sha moved). Host proof: `tests/run.sh` step 7 runs
this on a scratch copy of the live candidate and checks the G2 pin rule.

Manual rollback before a build: restore `CHANGES.json` from the backup,
`patch -R -p1 --fuzz=0 -d <ts>/candidate -i PATCH/01-shadow-launch-ready.diff`,
delete the two headers from `<ts>/candidate/include/`.

## Gates (integrator, unchanged)

- `fs_throw_gate.py`, `no_detour_gate.py` before compile. The patch adds no
  filesystem call and no detour (host test step 8 compares patched vs unpatched).
- `field_gate.py`: same counts before and after (49 read / 48 proven /
  0 unproven / 1 accepted) — host test step 8.
- After packaging: `verify_build.sh --manifest` for the exact PRX.
- Record the build sha in the build ledger with label `+cap02-shadow`.

## PATCH/02 — NOT SHIPPABLE

`02-NOT-SHIPPABLE-firstlaunch-auto-followon.diff` is the planned first-launch
AUTO path for a game with no compiled declaration. It is never applied to the
candidate tree. It applies (for reading) on top of PATCH/01 in a scratch copy,
but it does not compile and must not ship until all of these exist:

1. `m_native_context.detected_engine` (live engine cell + identity from two
   independent detectors: the in-tree `EngineVersion` / `scan_version_stores`
   resolver and the axes verdict; build-id via `read_gnu_build_id()`).
2. A profile-side generator (the BuildProfile / LayoutPreflight gate reads the
   compiled `kProfile`; a new game needs it generated from the live image).
3. A pack cleared for arming (review F5). `generate()` now refuses any pack with
   single-source or config-dependent rows. The UE5.6 pack has 11 single-source
   rows and `UObject::ProcessEvent` depends on `UE_WITH_IRIS`, so it is refused
   for every image. Clearing it needs either per-image verification of every row
   on the new image, or config axes (at least IRIS) in the cell.
4. A decision on build-id width: 20-byte note (AUTO path) vs 16-byte R11 form
   (review F9).
