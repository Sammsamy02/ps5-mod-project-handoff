# Sound mods and video / cutscene mods on PS5: Team H design

Team H, 2026-10-13. Everything here was done on the Mac only. Nothing touched the
console, the runtime tree, frozen builds, mod files or other teams' folders.
Every claim is **Mac-only**: it comes from the game's own files that were already
on the Mac. Nothing in this document is console-proven yet.

---

## 0. Summary

**Sound.** Townfall's sound runs on **FMOD**, an audio library made by another
company. It does not use Unreal's own sound system and it does not use Wwise. The
game's PS5 settings switch Unreal's own sound system **off**. Every sound lives in
22 FMOD "bank" files, which are loose files in a `FMOD/Banks/PS5` folder.

The PS5 copy of FMOD is the **same version as on PC (2.03.13)**. It also contains
the same decoders that PC sound banks use (Vorbis, FADPCM, plain PCM). So a PC
sound mod (a replacement `.bank` file) should play on PS5 **as it is, with no
conversion**. The installer only:
- puts the file in the PS5 bank folder in place of the original (a backup is kept),
- checks first that it is built for the same FMOD version, uses a decoder the PS5
  has, and carries the bank ID the game looks for.

**Video.** The game plays **Bink 2** movies (`.bk2`) through 73 movie players:
logos, the title sequence, TV screens, tapes and projectors. Bink 2 files are the
same on every platform, so a PC replacement `.bk2` should also play **as it is**.
The game's own code accepts Bink 2 versions f to n. It does **not** support the
old Bink 1 (`.bik`); the game's code contains the message "No Bink 1 support.".
There are also 19 MP4 movie sources played by Unreal's "Electra" player. We do not
yet know whether the PS5 build actually ships those MP4 files.

**What is still unknown.** Exactly which codec and file-format version the game's
own PS5 bank and movie files use. That needs **one small read-only console fetch**
(a folder listing plus the first bytes of each file, about 3 MB). The integrator
runs it with the game closed. After that, one launch with one sound mod and one
movie mod proves it.

**Prototype.** A Mac tool reads the game's files, writes the fetch plan, checks mod
files and plans the install with a byte-exact undo. It ran a dry run on the game's
own data. 36 host tests pass. One independent review was done and its findings
are fixed (section 7).

| Mod type (PC) | Verdict | Why (short) |
|---|---|---|
| FMOD `.bank` replacement, Vorbis or PCM | **YES, as-is** | same FMOD 2.03.13; PS5 FMOD has the same Vorbis/PCM code as PC |
| FMOD `.bank`, FADPCM or Opus | **PARTIAL** | the decoder is in the PS5 FMOD; accepted only by an explicit decision until a console test or a base bank proves it |
| FMOD `.bank` built by a newer FMOD Studio | **NO** | a bank cannot be rebuilt for an older format without FMOD Studio (closed tool) |
| FMOD Master / strings bank | **PARTIAL** | holds the PS5 mixer (speaker, haptics, TV ports); refused by default in v1 |
| New extra banks (not in the game) | **NO (v1)** | the game only loads banks it has assets for |
| Loose `.wav` / `.ogg` / `.mp3` sound files | **NO** | must be built into a bank first (FMOD Studio) |
| Unreal SoundWave / MetaSound mods (in paks) | **NO for Townfall**, PARTIAL for other UE games | the game switches Unreal's sound off on PS5 |
| Wwise `.bnk` / `.wem` | **N/A for Townfall**; not profiled | refused until a Wwise game is profiled from its own files |
| Bink 2 `.bk2` replacement | **YES, as-is** | same file on all platforms; the game's code accepts KB2f to KB2n |
| Bink 1 `.bik` | **NO** | the game's code says "No Bink 1 support." |
| MP4 replacement (Electra) | **PARTIAL** | only if the PS5 build ships that MP4 and the codec matches the game's own MP4 files |
| Swapping a Bink movie for an MP4 (or the reverse) | **NO** | needs asset edits, not file swaps |

## 1. Evidence (all Mac-only, from the game's own files)

Inputs and their sha256 are listed in `evidence/base-profile-ps5.json` → `inputs`.
Main inputs:
- the game's main classic pak `pakchunk0-ps5.pak` (sha256 `ee145cbc…cd867`), which
  holds the config `.ini` hierarchy, `Townfall.uproject` and `AssetRegistry.bin`;
- the IoStore directory indexes `pakchunk*-ps5.utoc`;
- the readable copy of the executable `decrypted-eboot.bin` (sha256 `3b6cfad4…22fc`);
- the FMOD runtimes the console runs: `tf-libfmod.prx.self` (sha256 `b5f565c6…2eb2`)
  and `tf-libfmodstudio.prx.self` (sha256 `df7ebb56…21db`). These are fake-signed
  copies whose content is the game's own libraries (POSTMORTEM.md).

Raw lines are saved in `evidence/config-lines.txt`, `evidence/exe-strings.txt` and
`evidence/fmod-runtime-strings.txt`. The full machine profile is in
`evidence/base-profile-ps5.json`; it is regenerated by `av_profile.py`.

### 1.1 The audio system is FMOD Studio (4 independent sources)
1. `Townfall.uproject` enables the `FMODStudio`, `FMODStudioNiagara` and `NCFMODTools`
   plugins.
2. `DefaultEngine.ini` has a `[/Script/FMODStudio.FMODSettings]` section:
   `BankOutputDirectory=(Path="FMOD/Banks")`, `MasterBankName=Master`,
   `bLoadAllBanks=False`, `bLoadAllSampleData=True`, `StudioBankKey=` (empty, so the
   banks are not encrypted), `OutputFormat=Surround_7_1_4`, and locales EN + JP.
3. `AssetRegistry.bin` holds 22 `FMODBank`, 2769 `FMODEvent`, 229 `FMODBus`,
   139 `FMODSnapshot`, 14 `FMODVCA` and 2 `FMODPort` assets (the Haptics and
   Speaker ports). Each bank asset carries its bank GUID.
4. The console's `prx/` folder holds `libfmod.prx` and `libfmodstudio.prx`. Their
   strings show PS5 build paths (`studio_api/platforms/ps5/...`).

Wwise: there are no `AkAudio` assets and no Wwise plugin or library.

### 1.2 Unreal's own sound system is OFF on PS5 (1 config source + supporting facts)
- `Engine/Platforms/PS5/Config/PS5Engine.ini` sets `AudioMixerModuleName=PS5AudioFeatures`.
- The game's own `Townfall/Platforms/PS5/Config/PS5Engine.ini` sets
  `AudioDeviceModuleName=` and `AudioMixerModuleName=` to empty. This is the highest
  layer, so the empty value wins (trace in the profile: `audio.engine.mixer_trace`).
  Without a mixer module, Unreal loads no audio device.
- Supporting facts: there are 0 MetaSound assets. The 22 `SoundWave` assets are
  editor or developer leftovers (VR editor sounds, a developer footstep test,
  starter content), and all of them have `SoundAssetCompressionType=ProjectDefined`.
- **Still needed:** one boot-log line from a normal launch that shows no Unreal audio
  device. Until then this is single-source, so the installer does not rely on it to
  accept anything; it only uses it to refuse SoundWave mods.
- For other UE games: the executable contains `BinkAudioDecoder`, `VorbisAudioDecoder`,
  `AdpcmAudioDecoder`, `OpusAudioDecoder`, `RadAudioDecoder` and `Atrac9Decoder`, so
  the PS5 can decode the PC formats too (BINKA/ADPCM/OGG/OPUS/RADA).
- The Sony config sets `PlatformFormat=AT9`, which applies to waves marked
  "platform specific". This game's waves are `ProjectDefined` and follow the
  project default. Fetch step D reads two SoundWave packages, and those show which
  format was actually cooked.

### 1.3 FMOD version 2.03.13 (2 sources, they agree)
- `Engine/Plugins/FMODStudio/FMODStudio.uplugin`: `"VersionName" : "2.03.13"`.
- `libfmod` string: `FMOD WATERMARK VERSION:0x00020313 BUILD:161495`.

### 1.4 Where the banks live (config, PC vs PS5)
- PC (`DefaultGame.ini`): `+DirectoriesToAlwaysStageAsNonUFS=(Path="FMOD/Banks/Desktop")`.
  The banks are loose files on PC as well, so PC sound mods are loose `.bank`
  replacements.
- PS5 (`PS5Game.ini`): removes `FMOD/Banks/Desktop`, `FMOD/Banks/PC Headphones` and
  `FMOD/Banks/PC Stereo`, and adds `FMOD/Banks/PS5`. So the PC build has three bank
  variants, the PS5 build has one, and on PS5 the banks are loose files under
  `content/fmod/banks/ps5/`.
- `ForcePlatformName=` is empty, so FMOD picks the platform folder. The file names
  are confirmed by the LIST step (section 3); the `BankLookup` asset is a second
  source.

### 1.5 Decoders inside the PS5 FMOD (libfmod strings)
- Codec names: `FSB`, `Vorbis`, `FADPCM`, `Opus`, `AT9`, `Raw`, `MPEG`, `Wav`,
  `Ogg Vorbis`, `FLAC`, and others. **No XMA.**
- Source files:
  - Common code, the same as on PC: `fmod_codec_fsb5.cpp` and
    `fmod_codec_fsbvorbis.cpp` under `core_api/src/`.
  - PS5 hardware code that imports `libSceAjm`: `fmod_codec_at9.cpp` and
    `fmod_codec_opus.cpp` under `core_api/platforms/ps5/src/`.
- **32 embedded Vorbis setup headers** (`\x05vorbis…BCV`), plus a **table of
  161 known setup IDs** at file offset `0x17c1f8`. Each record is
  `{u32 size, u32 crc32, …}` with a 32-byte stride. All 32 embedded headers have a
  record whose crc32 equals zlib-crc32 of the header's own first `size` bytes, so
  the table is validated. The other 129 records carry a flag (1) and a second size;
  they are most likely variants that FMOD builds from a stored header (an
  inference, not proven).
  FSB5 Vorbis streams name their setup header by this CRC32. A PC Vorbis bank
  therefore decodes on PS5 only if every setup ID it names is in this table, and
  the installer now checks exactly that (second source for Vorbis).
- Profile result: `fsb_codecs_decodable = PCM8…PCMFLOAT, VORBIS, FADPCM, OPUS, AT9, MPEG`.
- The game's UE side has `EFMODCodec::VORBIS/FADPCM/AT9/OPUS/XMA` and the functions
  `IsBankLoaded`, `LoadBank`, `UnloadBank` and `LoadBankSampleData`.

### 1.6 Which codec the game's own PS5 banks use: NOT YET KNOWN
The bank files are loose on the console and are not in any pak on the Mac. The
read-only fetch (section 3) reads two things from every bank:
- the `FMT ` version (the bank format version),
- the FSB5 codec field.
The expected answer is AT9, Opus or Vorbis. It does not change the verdict for PC
Vorbis banks, because the decoder is present either way. It does decide whether a
codec counts as "proven on this platform".

### 1.7 What PC Unreal sound mods ship, compared with what the game uses
| PC mod ships | Used by Townfall? | Result |
|---|---|---|
| FMOD `.bank`: RIFF `FEV `, sample data in an FSB5 inside the `SND ` chunk; Desktop banks are usually Vorbis (codec 15), sometimes FADPCM (16) or PCM16 (2) | **yes**, the only sound path | pass-through, gated |
| Wwise `.bnk` + `.wem` (Vorbis 0xFFFF, Opus 0x3040/0x3041, ADPCM, PCM) | no | refused (`middleware_mismatch`) |
| Unreal SoundWave in a pak (BINKA / OGG / OPUS / ADPCM / RADA format container) | engine audio off | refused for this game (#8 intake should flag it) |
| Loose `.wav` / `.ogg` | no | refused (`raw_audio_needs_authoring`) |

### 1.8 Video: Bink 2 for 73 players, Electra MP4 for 19 sources
- Plugins (`.uproject`): `BinkMedia` and `ElectraPlayer` are enabled; `PS5Media` and
  `WmfMedia` are disabled.
- AssetRegistry: 73 `BinkMediaPlayer` assets. They cover:
  - the logos: `Konami_Ident_TEMP`, `Annapurna_Ident_TEMP`, `Screen_Burn_Ident_TEMP`,
    `SB_Ident_Slowmo_V1`;
  - the title sequence `TF_TitleSequence`;
  - the CRTV signal movies, the cutscene tapes, the projectors and
    `Full_Screen/Vid_PainfulVision_Flood`.
  The registry also holds 6 `BinkMediaTexture`, 19 `FileMediaSource` (all
  `FilePath=./Movies/….mp4`), 7 `MediaPlayer` and 8 `MediaTexture` assets.
- The executable's Bink header check: `cmp edi,'KB2f'`, `'KB2g'`, `'KB2h'`, plus the
  range check `add edi,-'KB2i'; rorx; cmp ecx,5; ja`. Together they accept
  **KB2f to KB2n** (4 sites, offsets in `evidence/exe-strings.txt`). Bink 1 magics
  are recognised only to print `No Bink 1 support.`.
- Movie sound goes through FMOD. There is a `BinkAudio` bank, and the 25
  `FMOD/Events/Cinematics/CRTV_Videos/SEQ_CRTV_*` events mirror the movie names
  (for example `…MissingParts_10thFloor` ↔ `Mov_CRTV_10thFloor`). So a movie mod
  that changes only the picture swaps only the `.bk2`; a mod that also changes its
  sound replaces the FMOD bank too. This is an inference from names (Mac-only).
- The executable has Electra strings for AVC/HEVC/AAC/VP9 and `OpusDecoderElectra`.
  Which of these the PS5 decoder really plays is decided by the game's own MP4
  files, which the fetch reads.

## 2. Feasibility per format, and the exact target format

The rule for every path: the PS5 build must already decode the format. We never
encode to ATRAC9, never use a Sony encoder and never use FMOD Studio. The only
conversion tools allowed are public lossless or standard ones, and so far none is
needed.

### 2.1 FMOD bank, from a PC mod to PS5: YES, as-is, by identity copy
The target file is **the mod's bank bytes, unchanged**, written at the exact name
of the game's PS5 bank (`content/fmod/banks/ps5/<name>.bank`, spelled as the
console LIST shows it). The installer checks:

| Check | Required | Evidence source |
|---|---|---|
| Container | RIFF form `FEV `; `FMT ` first; exactly one RIFF walk ends on the RIFF end | public layout + the parse of the game's own bank heads |
| Vorbis setup | every Vorbis setup ID is in the PS5 runtime's table of 161 | libfmod table (validated 32/32) |
| Bank format | mod `FMT ` version == the game's bank (older only by decision; newer refused) | base bank heads (fetch) |
| Sample data | `SND ` chunk → zero padding → `FSB5` (version 0 or 1); a missing magic means encrypted → refused | the game's `StudioBankKey=` is empty |
| Codec | FSB5 mode is in `fsb_codecs_decodable` **and** is proven: either a game bank uses it, or the decision `accept-unproven-codec` is given and flagged "needs console proof" | libfmod strings + base banks |
| Identity | the mod bank's metadata (before `SND `) holds the game's bank GUID right after the same chunk header that precedes it in **every** game bank, in the one byte layout all game banks use | AssetRegistry `Guid` tag + base bank heads (self-check: `bank_guid_encoding` + `bank_guid_anchor`) |
| Which file | under a PC bank folder from config; the default PC variant (`Desktop`) wins; the bank must already exist in the game | config + LIST |
| Not touched | the Master bank and its `.strings` bank (PS5 mixer/ports) need `allow-master-bank` | config `MasterBankName` |

For Vorbis there is one more check, and it runs even before the fetch: every
setup ID that the mod's FSB5 Vorbis streams name (extra chunk 11) must be one of
the 161 IDs in the PS5 runtime's own table (§1.5). If the table is not found or
not validated, the gate refuses (`vorbis_table_unvalidated`). An unknown ID gives
`vorbis_setup_unknown_to_runtime`.

### 2.2 Bink 2 movie: YES, as-is, by identity copy
The target file is **the mod's `.bk2` bytes, unchanged**, written at the game's
movie path (`content/movies/…`, spelled as the LIST shows it). The installer checks:
- The header is valid and its size field equals the file size.
- The magic is in the executable's accepted set (KB2f–KB2n), **and** it is a revision
  the game's own movies use. Otherwise the decision `accept-unproven-bink-revision` is
  required.
- Notes only, which do not refuse the file:
  - the frame size differs from the game's movie;
  - the movie has audio tracks while the game's movie has none (its sound normally
    comes from FMOD);
  - the length differs by more than 0.5 s (the FMOD sound event is timed to the
    original).

### 2.3 MP4 through Electra: PARTIAL
The mod file is copied as it is only when all of these hold:
- the PS5 build ships that `.mp4` (LIST);
- its codecs (for example `avc1` + `mp4a`) are among those of the game's own MP4s;
- its profile and level are no higher than the game's.

Otherwise it is refused. A public re-encode (ffmpeg + x264 + AAC-LC into the game's
envelope, `+faststart`) is possible but lossy. It is not in the prototype; it is a
next step if PC mods for these movies show up.

### 2.4 Paths that stay NO, and why
- Bink 1: the game's decoder refuses it.
- Bink 1 → Bink 2, or MP4 → Bink: the encoders are closed (RAD).
- A bank from a newer FMOD Studio, or loose WAV/OGG to a bank: needs FMOD Studio, a
  closed authoring tool.
- A possible future job is rebuilding an FSB as PCM16 from decoded samples (public
  formats only). It is large and not needed for PC mods, which already ship banks.

## 3. Fetch plan: one read-only console session, run by the integrator

Run it with **the game closed** (reads under game load come back incomplete). The
steps use LIST and ranged RETR only: no write, no rename, no SITE. Nothing in it is
an executable, so the decrypt-on-download behaviour does not matter.
`<IP>` is the console's LAN address; never put it in shared reports.

```
W=/WORKSPACE/.codex/worktrees/translation-core/caps-team-H/caps-team-work/sound-video   # run from the main worktree root
H=outputs/2026-10-08-l25-prep/harvest
CONTENT="/data/homebrew/Silent Hill Townfall PPSA33286/townfall/content"
PAKS="$CONTENT/paks"            # = paks_dir in pak-overlay/records/townfall.record.json
OUT=outputs/2026-10-08-l25-prep/evidence/capH-av-fetch-<UTC>

# A. listing (LIST only; CWD fallback if the server rejects a path argument): content/ one level + fmod/, movies/ recursively
python3 -I $W/av_fetch.py list --host <IP> --port 2121 --root "$CONTENT" \
        --subdirs fmod movies --out $OUT/listing.json
# B. heads: 64 KiB of every .bank/.mp4, 4 KiB of every .bk2/.bik   (about 2-3 MB)
python3 -I $W/av_fetch.py heads --listing $OUT/listing.json --out $OUT/plan-heads.json
python3 -I $H/ftp_range_fetch.py --plan $OUT/plan-heads.json --host <IP> --port 2121 \
        --remote-dir "$CONTENT" --out $OUT/fetched
# C. hops: chunk headers up to the sample data / the mp4 'moov' box, when past the head
python3 -I $W/av_fetch.py hops --plans $OUT/plan-heads.json --dir $OUT/fetched --out $OUT/plan-hops1.json
python3 -I $H/ftp_range_fetch.py --plan $OUT/plan-hops1.json --host <IP> --port 2121 \
        --remote-dir "$CONTENT" --out $OUT/fetched      # repeat C with all plans until it plans 0 chunks
# D. small packages (already planned on the Mac: 119 chunks, 80,746 bytes, each with its TOC IoHash)
python3 -I $H/ftp_range_fetch.py --plan $W/evidence/fetch-plan-packages.json --host <IP> --port 2121 \
        --remote-dir "$PAKS" --out $OUT/fetched
# E. check (Mac): parse everything, verify packages by IoHash, write the base media facts
python3 -I $W/av_fetch.py check --listing $OUT/listing.json --dir $OUT/fetched \
        --plans $OUT/plan-heads.json $OUT/plan-hops1.json $W/evidence/fetch-plan-packages.json \
        --profile $W/evidence/base-profile-ps5.json --out $OUT/base-media.json
```

Hops: the first round reads the chunk headers or `moov` header that lie past the
head. A second round is needed only when a `moov` box is larger than the first
read; it is capped at 8 MiB, and a larger one fails for that file only. A bank with
no sample data (the strings bank) needs no hop once its chunk walk reaches the end
of the file.

What each step decides:

| Step | Reads | Decides |
|---|---|---|
| A | directory listing | the exact bank/movie names and sizes on PS5; whether the MP4s and `master.strings.bank` ship |
| B + C | file heads | each bank's `FMT ` version and FSB5 codec; the GUID byte layout (self-check across all banks); each movie's Bink revision, size, frame rate and audio tracks; the MP4 codecs and levels |
| D | 115 media/bank packages + 2 SoundWaves | the `.bk2` file each `BinkMediaPlayer` opens (its URL string), bank lookup names, the SoundWave cooked format (second sources) |

All tools print counts and exit non-zero on zero items. `check` fails on any short
read, size mismatch or IoHash mismatch.

## 4. Generic design (mirrors #12)

```
mod files (read-only) ──► detect by files ──► classify ──► map to the game's file ──► gate ──► derive ──► plan (+sha) ──► apply ──► verify
                                                                                                   │
                                                                     undo: move ours aside ◄───────┘ rename the original back, check its sha256
```

- **Per engine, not per game.** Every rule comes from two inputs. Neither contains
  game or mod names in the code.
  1. `av_profile.py`, the base profile, built from the game's own files:
     - the config hierarchy (Base → platform → Default → platform), computed with
       UE's `+ - ! .` semantics;
     - the NonUFS staging folders, PC versus platform;
     - the FMOD settings (bank folder, master bank, key);
     - the AssetRegistry classes (FMOD, Wwise, Bink, Electra, SoundWave, MetaSound);
     - the executable's decoders and Bink header check;
     - the codec table of the audio runtime library.
  2. `av_fetch.py check`, the base media facts, read from the game's own bank and
     movie headers.
  The same code profiles any UE game that ships FMOD or Bink. Wwise and SoundWave
  are detected and refused cleanly until a game that uses them is profiled.
- **Detect by files.**
  - By extension and magic: `RIFF…FEV ` (bank), `KB2`/`BIK` (Bink), `ftyp` (MP4),
    `BKHD` and `RIFF…WAVE` (Wwise), raw audio.
  - Paks and IoStore files are handed to #7/#8 (paktx). Readmes and Lua scripts are
    ignored.
- **Map.**
  - A bank must sit under one of the profile's PC bank folders. It goes to the one
    platform bank folder, and the default PC variant wins.
  - A movie must sit under a media folder, or match exactly one game movie by file
    name.
  - Matching against the console LIST ignores case (the console stores lower case);
    the LIST spelling is what gets written. **Replacement only:** a target must
    already exist.
- **Derive.** Today it is an identity copy. Each kind has a slot for a converter
  (MP4 re-encode or an FSB rebuild later). The output is still a derived copy with
  its own sha256 and readback, and the mod files are never written.
- **Fail closed.** A refusal of any sound or video file refuses the whole plan
  (`REFUSED`, exit 2, nothing changes). A missing base fact or a provisional listing
  gives `DRY-RUN ONLY` (exit 4) and cannot be applied. Refusal codes include:
  - bank checks: `bank_format_newer_than_game`, `bank_format_older_than_game`,
    `codec_not_in_runtime`, `codec_unproven_on_platform`, `bank_guid_mismatch`,
    `bank_guid_method_unproven`, `mixer_bank_refused`, `master_bank_unknown`,
    `non_default_pc_variant`, `bank_outside_pc_bank_folder`,
    `conflicting_files_for_one_target`, `vorbis_setup_unknown_to_runtime`,
    `vorbis_table_unvalidated`;
  - path checks: `target_not_in_game`, `target_ambiguous_case`;
  - movie checks: `bink1_not_supported`, `bink_revision_not_accepted`,
    `bink_revision_unproven`, `mp4_no_tracks`, `mp4_tracks_differ`,
    `mp4_codec_unproven`, `mp4_codec_differs_from_target`,
    `mp4_video_facts_missing`, `mp4_profile_level_above_game`,
    `mp4_audio_profile_differs`;
  - other file kinds: `middleware_mismatch`, `wwise_not_profiled`,
    `raw_audio_needs_authoring`, `unknown_file_kind`;
  - parser errors, prefixed `mod_file_…`; any parser crash becomes
    `mod_file_unparsable`.
- **Plan binding.**
  - The plan is deterministic. Its `plan_sha256` covers the profile, the listing,
    the base media facts, the decisions and every operation. `apply` needs
    `--confirm <plan sha>`. It refuses a tampered plan, and a tool that changed
    since the plan was made (`tool_changed_since_plan`).
  - Before the first change, every target is checked: the size matches the LIST,
    the sha of the head matches the fetched head, and every backup and aside name
    is free.
- **Apply** (per file):
  1. record the full sha256 of the original in the journal, before any change;
  2. rename the original to `<name>.original-<nonce>-<apply id>.bak` (same folder;
     `.bak` is never loaded; the apply id is random per apply, so a second apply
     after a restore never collides with names left by the first);
  3. upload the derived copy under the original name;
  4. check the size and the full sha256 on readback.
- **Byte-exact undo.**
  - `restore` is driven by the journal and safe to repeat.
    - It refuses a tampered plan, and journal names that the plan does not
      produce.
    - It acts only on targets the apply recorded.
    - If our backup exists, whatever sits at the target is moved aside
      (`.mod-<nonce>-<id>.aside`, or `.unknown.aside` for a partial upload);
      nothing is ever deleted.
    - Then the backup is renamed back, and its sha256 must equal the one recorded
      in step 1.
  - The original bytes are never rewritten, only renamed, which is the same law as
    paktx.
- **What the runtime needs: nothing.** Banks and movies are loose files that the
  game opens by name at play time (bank folder from FMOD settings, movie path from
  the player asset), so no C++ change, hook or rebuild is needed. Optional
  Lua-only probe (fast deploy, no rebuild): after the first level load, a zzdiag
  step calls `FMODBlueprintStatics.IsBankLoaded` for each replaced bank's
  `FMODBank` object and logs the result. Its log line plus any `LogFMOD` error line
  (`LogFMOD=Log`, `LoggingLevel=LEVEL_ERROR` in the game's config) are the proof.
- **The console backend comes later.** The prototype has no FTP writer on purpose.
  The integrator wires paktx's `FtpBackend` pattern (LAN only, journal, hash gate),
  with two write surfaces only: `content/fmod/banks/<platform>/` and
  `content/movies/`. They need their own gate, the same way paktx guards `paks/`.

## 7. Independent review

One independent reviewer (a fresh agent with no shared context) reviewed all four
tools and the tests for fail-closed gaps, undo safety, the read-only guarantee and
the format facts. The findings and the fixes are listed below.

First pass: **not ready to ship.** It found 3 HIGH, 3 MEDIUM and 6 LOW items. All
of them are fixed, and each has a regression test (`ReviewRegressions`):

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | HIGH | A second apply after a restore reused the backup/aside names, so the next restore refused and left our file in the game | names get a random per-apply id that the journal records; every name is checked free before the first change |
| 2 | HIGH | The mixer-bank guard turned off when the config names no master bank | no master bank in the config → every bank is refused (`master_bank_unknown`) |
| 3 | HIGH | The MP4 gate accepted a file with no tracks, an audio-only file in place of a video, and a missing level | track handlers must equal the game file's; each codec must be in the game file; profile/level are required on both sides |
| 4 | MEDIUM | Odd inputs crashed the parsers instead of being refused | bounds checks; Bink revision a–z only; exact length math; any crash becomes a refusal or a check failure |
| 5 | MEDIUM | Restore trusted an edited undo list | restore recomputes the plan sha, follows the journal, and acts only on recorded targets |
| 6 | MEDIUM | `check` passed with facts missing (hop not fetched, SND payload just past the head) | missing pieces and missing facts are failures; a hop goes to the SND payload; MP4 reads the whole `moov` box |
| 7–12 | LOW | GUID check not tied to a position; case-twin names; `.partial` leftovers; jump type in the Bink scan; relative lister root; small items | GUID tied to the chunk header that precedes it in every game bank; ambiguity counted; upload behaves like STOR and restore moves partials aside; only `ja`/`jae` count; root must be absolute; `.m4v`, tool sha binding, `.lua`/`.ini`/`.json` handed to the mod manager |

Format facts, the read-only lister (a fake server logged only USER, PASS, TYPE,
PASV, LIST, CWD, QUIT), interrupted apply/restore (failures injected at every step:
the originals came back byte-exact every time), path traversal and plan-sha
binding were all confirmed OK.

The fix check (same reviewer) confirmed 11 of 12 fixed and found one new bug that
blocked every install: a game bank with no samples (`master.strings.bank`) made
`check` fail. It also found one small issue: an oversized `moov` aborted the hop
plan for every file. The reviewer's verdict was "OK once the strings-bank case is fixed and has a
regression test". Both items are now fixed and tested (36 tests). The reviewer has
not re-checked that last fix.

1. **Integrator:** run the read-only fetch (section 3, game closed), then `check`.
   Read the self-check:
   - `bank_guid_encoding` must be exactly one layout;
   - `bank_codecs_decodable_by_runtime` must be true;
   - `bink_magics_accepted_by_exe` must be true.
   If any of these fails, the matching gate stays closed and Team H fixes the
   parser.
2. Re-run `av_install.py plan` with the real listing and `base-media.json` on a real
   PC sound mod and a real movie mod, chosen by the user from the mod site. Expect
   `READY`.
3. **One launch per capability**, after the current queue:
   - one replaced content bank (not Master) and one replaced logo or TV movie;
   - the user listens and watches;
   - the harvest greps `LogFMOD` and reads the optional zzdiag `IsBankLoaded` line;
   - then restore and check the sha.
   This is the first console proof. Until then every verdict here is Mac-only.
4. If the game's own PS5 banks use Vorbis, `check` already confirms that their setup
   IDs are in the runtime table (`base_vorbis_setups_in_runtime_table`). If any is
   missing, `check` fails, because the table reading would then be wrong. That
   validates the method on the game's own data.
5. The integrator wires the FTP backend (paktx pattern) and gates for the two new
   write surfaces, and adds the sound/video plan to the mod manager.
6. Later:
   - MP4 re-encode slot (public ffmpeg/x264/AAC), only if mods need it;
   - Wwise profile, when a Wwise game comes up;
   - SoundWave derived packages for UE games that keep Unreal audio on;
   - `.wav` → PCM16 FSB rebuild.
   None of these block Townfall.

### 8b. Launch card (draft, for after the fetch, and only when the queue reaches it)

- **Precondition.**
  - `base-media.json` shows `checked > 0` and no failures, and its self-checks are
    all true.
  - `av_install.py plan` on the chosen mods says `READY`.
  - The user gives an explicit OK for each console action (upload, launch, restore).
- **Change.**
  - One content bank, not Master; a UI or music bank is the easiest to hear.
  - One logo or TV `.bk2`.
  - No runtime rebuild. The optional zzdiag `IsBankLoaded` probe is a fast Lua
    deploy.
- **Pass.**
  - The user hears the new sound and sees the new movie.
  - There is no `LogFMOD` error line for that bank, and the probe line says it is
    loaded.
  - `restore` puts both originals back, with the sha256 verified against the
    recorded values.
- **Fail.**
  - Silence, a missing bank error, or a black movie means restore immediately.
  - The logs decide whether the cause is the bank format, the codec, the Bink
    revision or the path.
- **Rollback.** `restore` (rename back). No build is involved.

## 9. Risks and open questions

- **FMOD may reject a bank built for the Desktop platform.** As far as we know FMOD
  has no platform lock: the codec and the format version are what matter, and both
  are gated. But this is exactly what the first launch proves.
- **PC and PS5 FMOD versions.** If PC Townfall ships a different FMOD patch version,
  the `FMT ` version gate catches it. Equal versions are expected, since it is one
  project.
- **Bank variants.** A mod that ships only `PC Headphones` or `PC Stereo` banks is
  refused unless the user decides. The PS5 mix sits closest to Desktop (7.1.4
  surround).
- **Memory.** `bLoadAllSampleData=True` means a much larger replacement bank costs
  RAM. The plan notes when a mod bank is more than 2× the game's.
- **Bink audio.** If a mod movie carries its own audio track and the game's movie
  did not, the sound may stay silent on PS5 as well as on PC, because the game plays
  movie sound through FMOD. The plan flags it.
- **Unreal audio off.** This is single-source (config) until a boot log confirms it.
  It is only used to refuse SoundWave mods.
