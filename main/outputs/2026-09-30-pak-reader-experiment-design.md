# Generic PAK reader experiment

Implement a reusable read-only C operation for the standard unencrypted PAK v11 footer and primary-index metadata. This follows the existing container proposal with a concrete first module. It advances the engine-format path alongside native Nexus transport; it does not grant installation or asset compatibility.

Use a single synchronous call with a versioned caller-owned provider, exact uint64 logical size, trusted read-at callback and explicit caller-asserted snapshot scope. Retain no provider pointers or session state after return. For this experiment the fixtures use immutable owned memory/procedural providers; native filesystem stability is not claimed. No pagination or cache is implemented, so the previous proposal's session/cursor alternatives do not apply yet.

Parse the standard221-byte v11 footer by bounds-checked little-endian fields, then verify the complete declared primary-index SHA1 with an actual pinned portable implementation. Parse bounded FString mount, file count, hash seed, secondary-index declarations, encoded-entry blob geometry and the nonencoded-count field. The standard schema comes from the pinned [footer](https://raw.githubusercontent.com/FabianFG/CUE4Parse/28f385e622468c4ab84997d596b46bb1c3adfcfa/CUE4Parse/UE4/Pak/Objects/FPakInfo.cs) and [primary-index reader](https://raw.githubusercontent.com/FabianFG/CUE4Parse/28f385e622468c4ab84997d596b46bb1c3adfcfa/CUE4Parse/UE4/Pak/PakFileReader.cs). Do not copy game-specific branches or use a game name/mod ID as parser selection.

Use a fixed caller workspace rather than metadata-sized allocation. Read/hash/skip sequentially in bounded blocks. Reserve cumulative byte/read/work limits before callbacks and decoding; validate ranges by subtraction. Initial defaults:64KiB maximum read,4MiB primary metadata,8MiB aggregate reads,256 reads,65,536 declared files,1024 mount bytes. Make limits explicit and preserve resource exhaustion separately from malformed/unsupported/provider errors. Validate actual callback counts and exact lengths; a callback cannot overrun its trusted caller buffer. Cooperative cancellation/deadline is a caller/provider contract, not a hard synchronous timeout.

Return owning scalar metadata and bounded raw mount bytes with explicit encoding/length. Expose primary-index checksum validation and secondary declared ranges/hashes independently. For unsupported nonencoded records, unknown version/flags/compression names or malformed strings, preserve the reason and withhold complete-primary facts. Secondary-index checksum validation, full inventory, entry decoding, payload extraction, IoStore/AMPR mapping, writers and game acceptance remain false/unresolved. Mount traversal prefixes are engine namespace metadata, never filesystem destinations.

Focused fixtures use independently generated Python bytes/hashlib SHA1: valid empty and nonempty primary metadata; real observed-size/count geometry with procedural payload; wrong checksum; truncated/overflow/overlap ranges; unsupported version/encryption/nonencoded data; malformed strings/counts; byte/read limits and faulting/short/changed providers. Validate whole-result ownership and no filesystem/network writes. Compile/link the same C operation for the SDK target if straightforward; do not execute on the console. Preserve the pinned SHA1 source/config identity without rebuilding or changing unrelated crypto caches.

The lighter experiment process applies: focused checks and a short note, no default full review, sanitizer sweep or checksum bundle. Promotion into the application or any game/system writer requires review of the actual combined code and failure paths.
