## Exact current integration blockers

1. **Actual mappings lifetime/protection authority is missing.** The current VmScan supplier explicitly records `Retention::None`; `validate_retention()` returns `AlreadyReleased` unless it has a genuine `LoaderReference`. The shared_ptr conversion owns the supplier/metadata, not a loader reference on this route. `ModuleSnapshot` and `NativeProgramContext` expose no independent contract preventing external unmap/protection changes. `ReadLease` protects the OwnedMemory service registry; its documented caller obligation still excludes external lifetime/protection changes and direct writes. Static frozen-snapshot bridge registration, readable-range metadata, a path/base, or process-lifetime registry objects cannot satisfy that missing ownership premise. No supported independent process/main-image residence contract was found in the exact current source contracts examined. The adapter does not bypass `Retention::None` or manufacture a lifetime assertion.
2. **The new static libkernel import needs independent provider/packager admission.** The reader's only callable route is `extern "C" int32_t scePthreadGetthreadid(void)`, not a caller-supplied function pointer, a game PLT callback, or `pthread_getthreadid_np`. Native saved-image PLT/dataflow and the SDK's unique NID/export correlate `EI-5-jlq2dE` to `scePthreadGetthreadid` in `libkernel`. The saved OpenOrbis signature is third-party PS4 corroboration, not an official PS5 prototype. The actual target object imports the symbol. New PRX provider/NID/library binding, import delta, and static-provider residence have not been packaged/admitted. Current `ModuleSnapshot::FindExport` is intentionally unset and throws; the candidate does not use it as an alias or fallback.

`StartupWait::IsCancelled` is a genuine available cooperative cancellation seam, passed from Program into Config and retained by the initializer. It establishes neither mapping residence nor import admission. `SelectedThreadAuthorityAdapter.cpp` reports it separately, verifies `NativeScanSource->source_owner()==ModuleSource`, and fetches `bridge_code_cache_context` only during initializer ownership. It never requests that initializer-only cache from a callback. With the current Config it supplies neither missing proof, so preparation refuses. It does not publish an authority or a native thread identity.

`candidate/UnrealInitializer.cpp` differs from the exact selected R4 initializer by two includes and one preflight call. Under `__PROSPERO__ && bSeedsArmed`, after existing BuildProfile checks and **before** seed consumption/map publication, it throws an explicit thread preparation blocker through the existing initializer-bank retirement catch. The unarmed scan path does not execute this insertion. This is an isolated diagnostic overlay, not a selected-source admission. A future usable adapter needs genuine supported owner/import inputs and a retained authority holder/ticket on actual callback work; simply promoting this current refusing adapter would not make the menu usable.
