# Game-independent PAK candidate validation

The reusable read-only classic-v11 validator is implemented in [pak_candidate.h](ps5-mod-bridge/native-host/pak/pak_candidate.h). The first console test game can change; this API has no game-name, title-ID or mod-ID branches. Engine/format support determines eligibility. A successful archive check does not authorize installation or establish PC-to-console asset compatibility.

One call validates captured primary metadata, both declared raw secondary SHA1s, the complete strict UTF-8 directory and every compact record. Counts must agree; every directory row must reference a real record start exactly once, with no orphan records or duplicate exact directory/filename tuples. Empty inventories are supported. The path-hash index is hashed but its semantics remain opaque.

For one selected directory row, the validator checks indexed extents against archive metadata and other entries, reads its physical header, reconciles offsets/sizes/method/block geometry, then verifies the stored-byte SHA1 and exact None/Zlib output. The explicit unencrypted producer profile hashes raw None bytes or stored compressed Zlib blocks in order. It does not verify other payloads, try alternate hashes, authenticate the author, map filesystem destinations or convert assets.

One operation owns one aggregate read ledger: defaults are 20 MiB requested bytes, 4096 calls and 64 KiB per request. Secondary verification reserves directly against that ledger; a noncharging tee captures the exact hashed directory bytes. Other reads use a charging proxy. Every provider callback sees one prior deduction, with no refunds or later subtraction of child counters. One caller-initialized codec budget carries consumption across blocks. Bounded graph work and cancellation are cooperative, without a hard CPU or provider-latency deadline.

Whole success publishes complete rows and the optional selected output. Operational failures clear full row/name/output capacities and all mutable scratch while retaining spent budgets and constant causes. Invalid known aliases leave every output untouched. Installation, authenticity, game acceptance and path-hash-semantic markers remain zero.

Focused verification passed **9771 C checks**, including all eight independent upstream payload comparisons, primary/secondary/stored hashes, altered references/counts/late records/names/headers, exact and one-short aggregate budgets, later provider/codec failures, cancellation and aliases. Late-failure controls observe already decoded output before checking full rollback. Separate local fixtures cover a complete empty candidate and a two-block Zlib candidate with second-block corruption, truncation, changed source and exhausted shared step budget.

The missing implementation compiled and failed the actual caller before implementation. A subsequent test oracle incorrectly expected six callbacks; the retained trace established twenty field-sized callbacks with exactly the original expected byte sum, and only that call-count expectation was corrected. Other incorrect synthetic tombstone/step-budget expectations were corrected against the actual parser/codec source, with failed logs retained.

The same composed caller and 20 C units compile and link for pinned PS5 SDK v0.43 / LLVM21.1.8. The promoted flat library was then verified through its own focused host and target commands: 9771/0, matching source identities, and a 217192-byte target ELF. **Neither composed ELF was executed.** Fixture-runner imports include libc file I/O; an ELF link is not a console app or loader/game test.

Run `make test-pak-candidate` with explicit `PAK_MBEDTLS_SOURCE` and `PAK_ZLIB_SOURCE`, or use [verify_candidate.py](ps5-mod-bridge/native-host/pak/verify_candidate.py). This command uses retained pinned dependencies/fixtures and local generated test inputs. It performs no console, account, network or game-file operation. The existing smaller payload API remains available; consumers needing complete reference/selected integrity gates should use the candidate API.

Native Nexus login/browse/download integration, additional engine/format adapters, asset conversion, install mapping and game acceptance remain unfinished. UE4SS, Mod Engine 2 and other injected PC tools remain Unsupported. No game's runtime mod compatibility is demonstrated by these fixture checks. Universal app coverage remains the architecture goal, with Unsupported results for unproven adapters.
