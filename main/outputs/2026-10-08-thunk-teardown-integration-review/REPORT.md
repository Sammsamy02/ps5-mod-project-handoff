# Bounded thunk teardown integration review

The selected R4 shutdown sequence does not admit safe thunk integration without additional stop and Lua-teardown gates. Joining the runtime initializer and draining current callbacks are separate facts from native-engine quiescence. Neither proves that an engine caller cannot still hold or enter a published thunk.

The concrete selected path is:

1. runtime_module_entry.c:375-395 calls modbridge_runtime_stop while runtime_active is set, clears that flag even after failure, and proceeds to probe_lifecycle_stop. The latter reaches fini arrays and DSO finalization. Root is preparing a separate minimal return-before-finalization correction; this review did not edit it.
2. runtime_start_bridge_r14_diag_spanpub.cpp:1601-1625 calls StopRuntimeWithAck. Its exception branch resets the owner and releases startup resources.
3. runtime_ack_supplier.cpp:55-64 calls RuntimeOwner::stop and then resets the owner unconditionally. RuntimeOwner.cpp:48-82 requests shutdown and joins the initializer. Its actual header explicitly states that this does not certify engine-hook quiescence or safe unload.
4. Owner reset destroys UE4SSBackend's unique_ptr program. UE4SSProgram.cpp:509-577 calls shutdown_native_program, joins the event loop, clears queued events, uninstalls mods, clears their owners and shuts down input/output.
5. UE4SSProgram.cpp:2256-2317 uninstalls each Lua mod before C++ mods. LuaMod.cpp:7480-7643 joins the async worker and takes m_thread_actions_mutex, marks its hook userdata scheduled, unregisters pre/post IDs, clears pending actions, resets Lua threads, closes the Lua state and erases the owning hook-data unique_ptrs. It does not call UFunction::UnregisterAllHooks. LuaMod::global_uninstall at :971-973 is empty.

## Minimal source recommendations

- **Refuse module finalization before any destructive step when code residence is required.** For a published permanent thunk, active callbacks zero, restored Func and an empty callback map do not prove that no native caller cached that thunk. Check the residency rule before owner reset/destruction and before module_stop's lifecycle finalization. The no-owner early return and runtime_active=false path must not bypass an existing code-residence obligation. If no native retention/quiescence proof is available, retain the module code; do not convert a local drain into unload permission.
- **Preserve the runtime owner on a refused or exceptional stop.** StopRuntimeWithAck should return false without owner.reset when owner->stop returns false. A residency/quiescence refusal must occur before a successful stop can trigger reset. The bridge's catch branch must retain slot and owned resources rather than destroying them while reporting an error. A negative module stop result must preserve runtime_active and skip fini, DSO finalization, input release and diagnostic-channel release. The root's separate entry candidate addresses the last boundary; supplier/bridge admission is also required.
- **Place Lua capture cleanup and borrower admission checks after unregistering this mod's callback IDs, before invalidating any Lua state.** The narrow insertion boundary is after LuaMod.cpp:7583 and before :7616 clears m_hook_lua, :7621/:7626 reset threads, :7631 closes Lua and :7638 erases raw userdata. Stop new Lua callback admission, establish that already admitted borrowers have completed, then destroy affected retained callable captures while their Lua state is still valid. Preserve the thunk's original forwarding identity/code residence separately. A global cleanup routine must not remove other mods' live callbacks or free original thunk nodes required for late dispatch.
- **Do not use the action mutex or scheduled flag as the script-callback lifetime token.** The pre callback dereferences its raw CustomData at LuaMod.cpp:174, then checks scheduled_for_removal at :177. The post callback dereferences at :277 and can luaL_unref at :287/:293/:297. Neither entry takes m_thread_actions_mutex. The thread-local NativeLuaActionDispatching check at :7487-7489 protects action dispatch, not every admitted script callback. R5's callable cleanup must preserve raw LuaUnrealScriptFunctionData owners until those script borrowers finish. Per-callback removal alone can mark an executing callback but cannot revoke a copied callable already admitted outside the registry lock.

These recommendations intentionally distinguish four obligations: stop/join the initializer; suspend and finish Lua borrowers; release Lua-dependent captures before Lua closes; retain thunk code until independently established native quiescence permits unload. Only the first is certified by existing RuntimeOwner::stop. Existing stopped acknowledgments mean initializer completion, as documented, and must not be relabeled as native quiescence.

## Two bounded actual-source controls

CONTROLS.json retains exact source and binary hashes, compiler arguments and raw sanitizer output.

- The exact selected module_stop body, with an explicit loader seam returning stop refusal -37, still cleared runtime_active, invoked lifecycle finalization, released input/channel and returned zero. This confirms the insertion point for the root's stop-result correction. It does not model a complete runtime destructor.
- The exact sealed prototype callback/dispatch bodies plus the selected Lua pre callback's first userdata dereference/check were run with an explicit host scheduling seam. Teardown marks/removes the callback and deletes its raw userdata after callable admission but before that dereference. Fatal ASan reports heap-use-after-free. This is a concrete borrower-lifetime counterexample, not a full Lua uninstall or native engine test. The atomic scheduled flag does not protect the object after deletion.

The immutable R4 entry, runtime owner/backend/supplier, Program, LuaMod and sealed prototype were only read. Root's separate stop candidate and forthcoming R5 sources remain outside this review's edit scope. No compiler/package rebuild, console contact or unload experiment occurred.
