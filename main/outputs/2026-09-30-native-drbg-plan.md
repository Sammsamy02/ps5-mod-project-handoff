# Bounded native CTR-DRBG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the owned native host with one cached, metadata-only entropy/CTR-DRBG startup checkpoint using the real pinned crypto library and a shared four-attempt OS budget.

**Architecture:** A fresh isolated crypto builder applies the same owned configuration overlay to library and consumers. The native host then observes raw32, seeds the SHA-512-accumulated AES-256 CTR-DRBG once, generates32 once, and clears caller-owned private storage before listening. Task reviews precede a whole-phase review and any console dispatch.

**Tech Stack:** Existing C11/C++20 SDK host, pinned Mbed TLS3.6.7, Python offline build/tests, LLVM21.1.8, PS5 payload SDKv0.43.

**Spec:** `outputs/2026-09-30-native-drbg-next-design.md` (authoritative design); exact implementation interfaces below refine it.

## Global Constraints

- Finished application operations run on the PS5 alone. This development checkpoint establishes no game installation or translation support; `installation_supported:false` remains unchanged.
- No console, FTP, manager, Nexus, account, game, or external network calls by workers. Owned local loopback fixtures are allowed for verification. Root alone may perform a reviewed, uniquely identified console checkpoint. Never control the user-owned FTP service.
- Preserve pinned SDK/tools, all historical dependency spikes/artifacts, and user untracked files. Use a fresh owned crypto build directory. No staging/commits by workers; root serializes Git.
- Pin Mbed TLS commit `068ff080b369adfac81509f9b57b2afabaf82dc5`, archive SHA256 `ca6bd316bbec49ef20088f39b8755fcaec0b7e45781506de55b17cd191ae6937`; framework commit `dde0c4a0e448a0552f18817dcea633bb851fd288`, archive SHA256 `3b0d4864fa877dc9165b90ff3d5b68505c6176c0b22d317d99fe8c89a993e9fd`.
- Effective library AND consumer configuration must define `MBEDTLS_NO_DEFAULT_ENTROPY_SOURCES` and `MBEDTLS_NO_PLATFORM_ENTROPY`. Retain SHA512/block64/gather128/AES256-key32/default-seed48/default-nonce0/PR-off/reseed10000. Compile assertions reject alternate entropy, threading, hardware/NV sources, forced SHA256, AES128-only, and alternate/PSA CTR-DRBG paths.
- One shared limit4 reserves before each OS attempt. Raw consumes1, normal seed consumes2 source polls of32, generation consumes0 entropy: total3. Every OS error consumes an attempt; never reset/retry/fallback/reseed in the production flow.
- Strict source accepts only rc0, captured errno0, returned length32; nonzero rc, success-with-errno, zero/short/oversized/SIZE_MAX fail. Preserve actual scalar failure metadata separately from library error codes and budget denial.
- Never inspect, encode, hash, print, persist or publish production entropy/generated bytes. Clear full owned buffer/context capacity with non-elidable writes, independent of returned lengths; no expired-local cleanup assertions.
- No hard syscall deadline, worker thread, TLS/x509/curl/DNS or retained production RNG is added. `hard_deadline_enforced:false`, operation-only scope, and downstream TLS/login/install limitations must remain explicit.
- Preserve exact existing routes, Host/Origin/framing/shutdown gates, CSP, exact response text, cached core results, firmware/game `not_queried`, and version/profile/origin/build identity. Desktop production performs no target entropy/crypto operation.

## Review Focus

1. Tampered or stale extracted dependency/config/object bytes: reject before linking; identity must include the exact linked crypto archive and effective recipe/configuration.
2. Invalid callback storage/capacity and dishonest returned size: avoid OS calls for invalid input, clear only validated owned capacity, preserve canaries, never trust returned size for clearing.
3. Seed failure on the second source poll or budget denial: fail without generation/retry, preserve actual counts and reason, and clear live owned storage.
4. Configuration mismatch across consumer/library or accidentally linked default platform poll: compile/config/source and real-library negative tests must reject it.
5. Startup/report failure or unavailable clocks: report null results honestly, preserve report/shutdown after returned failures, never interpret missing readiness as syscall timeout or redispatch automatically.
