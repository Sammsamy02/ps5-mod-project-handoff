# Original-container preparation example

`compose_original.c` connects the portable range reader, v5 header merger, None packer, directory merger and TOC overlay in one ordinary host process. Its inputs are:

```text
compose_original ORIGINAL_MOD.utoc ORIGINAL_MOD.ucas ORIGINAL_BASE.utoc \
  CAPTURED_BASE_HEADER.bin OBSERVED_BASE_UCAS_BYTES FRESH_OUTPUT_DIRECTORY
```

The destination directory must exist. Each output is created exclusively; partial output remains unpublished on failure. The example opens originals read-only and keeps their descriptor identity/size/time snapshots stable. It never opens the large base UCAS, contacts a console or publishes output to a game. The captured base header is bound to the source-derived header row by logical size and BLAKE3 digest. A production job still needs to acquire that header from the selected game's original container.

The program derives the mod's chunk order, paths and container header from its original TOC/UCAS. It extracts the incoming header through range reads, merges package records, omits the foreign header and appends the merged header under the base container ID. Directory entries are remapped by chunk ID. Asset payloads stream directly into the new sidecar; all emitted asset digests must match the incoming TOC. Expected artifacts, extracted raw chunk files, premerged headers and per-mod chunk facts are not accepted as preparation arguments.

Output names are fixed local artifacts: `generated-small.utoc`, `generated-sidecar.ucas`, `merged-container-header.bin`, `generated-directory.bin` and `generated-final.utoc`. The final TOC preserves the original base block descriptors and redirects changed chunks into the sidecar. The small TOC is an intermediate artifact. Successful preparation does not authorize installing these files or establish runtime compatibility.

The caller bounds requested allocations to 512 MiB and releases all allocations/descriptors on exit. This historical command-line example uses a process-lifetime allocation ledger. The same preparation algorithm is now exposed by `original_file_job.h` as a reusable borrowed-descriptor job. Its six arguments are original input observations, not a title-specific recipe. Incoming containers must fit the modules' strict single-partition v8 Indexed/None profile; the broader range-reader API can inspect two partitions, but this example intentionally admits one incoming UCAS only.

Compile as C11 with this directory's parent IoStore directory and `vendor/blake3` on the include path. Link `compose_original.c`, `none_range_reader.c`, `container_header_merge.c`, `none_packer.c`, `directory_merge.c`, `toc_overlay.c`, `toc_reader.c` and the three portable BLAKE3 sources. Use the SIMD-disable definitions in [portable_preparation.md](../../portable_preparation.md). macOS also needs `_DARWIN_C_SOURCE` for these host file flags. No SDK or target build is involved.

The retained original-input Leon run completed preparation in 0.461 seconds on the Mac, reading 185,446,608 source bytes through 2,948 callbacks. It verified 161 asset digests plus the incoming/captured headers and produced 162 chunks with a 38,500-package merged header. Peak requested allocations were 279,458,434 bytes; all 23 allocations were released. This is job-managed allocation size, not resident memory or PS5 performance.

Unlike the earlier fixture composition, this program uses incoming TOC row order. The new sidecar is 187,713,168 bytes instead of the prior build's 187,713,177 bytes because of ordering and tail-padding differences. The independent post-job oracle passed all 162 chunks by ID across 187,713,164 logical bytes, all 56,993 path-to-ID mappings and 38,500 package-store entries. It also checked required padding, changed final mappings and appended block descriptors, preserved base descriptors and all 59,411 unaffected base mappings. It opened zero base UCAS bytes. Logical contents and mappings match; whole-file hashes intentionally differ with physical layout.

Preparation success and independent comparison are recorded separately under `.superpowers/native-dependency-spike/iostore-original-input-composition-1/` and `iostore-original-input-oracle-1/`. This example starts at an already extracted container pair. The newer [original-archive example](../archive_input/README.md) adds automatic archive discovery/extraction; app download/install integration remains separate work. No new in-game acceptance of these particular generated bytes is claimed.
