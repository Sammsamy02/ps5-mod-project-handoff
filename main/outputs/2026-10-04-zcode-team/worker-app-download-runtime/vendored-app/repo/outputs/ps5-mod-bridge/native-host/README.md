It embeds the game-independent controller UI at `/app`, with exact `/app.js` and `/style.css` assets; `/` remains the diagnostic page. Explicit configured builds expose browser sign-in and Nexus catalog routes. An additional archive profile enables file download and read-only analysis jobs. The format-dispatch, captured-metadata decoder and read-only single-candidate source capture have separate PS5 compile/link evidence, without execution or actual provider integration. Native title paging remains disabled and uses the unavailable v1 preview response.

## Native browser sign-in configuration

The download composition includes a private fixed authorization-code POST and process-owned PKCE/account context. With explicit compiled registration/trust, the existing UI can bootstrap its browser session, start authorization at `users.nexusmods.com`, return to `/auth/callback`, verify live userinfo, report the account and disconnect. Cookie/state/CSRF and token credentials are separate; passwords and client secrets never enter this app. Access/refresh tokens remain private in memory for this first version and are erased on disconnect or process shutdown. Refresh and persistent sign-in are unfinished.

Pass `--oauth-config /absolute/public-oauth.json` to `build.py` together with `--download-profile` and `--curl-source`. The JSON requires these public fields:

```json
{
  "client_id": "YOUR_REGISTERED_CLIENT_ID",
  "scope": "",
  "redirect_uri": "http://127.0.0.1:8085/auth/callback",
  "ca_pem_path": "/absolute/trusted-certificates.pem",
  "users_resolve": "",
  "timeout_ms": 10000,
  "connect_timeout_ms": 5000
}
```

Supply your registered public client and its exact registered callback, with a certificate-only CA bundle. The initial configured profile is loopback; native callback port is 8085, and a desktop fixture's compiled callback must match its runtime `--port`. Missing configuration leaves auth/account capability false. The builder validates the public settings and includes their values and CA digest in the source/artifact identity. It does not read a production credential store or obtain a Nexus registration automatically.

An optional `api_resolve` field defaults to an empty string. Nonempty `users_resolve` and `api_resolve` values must map only their fixed respective Nexus hostname on port 443 to one IP address. They are compiled trust configuration, not caller-supplied redirect URLs; owned fixtures use them to keep HTTPS URL, Host, SNI and certificate checks intact.

`/api/capabilities` issues an HttpOnly, SameSite=Lax browser cookie and CSRF token. Start/disconnect require that cookie, CSRF and exact Origin; callback requires the same pending cookie and one-use state. Auth POST framing accepts one canonical Content-Length and at most 16 bytes of an empty JSON object, without Transfer-Encoding or excess frames. Provider work has its own bounded budget and a fresh response-send window. Account GET verifies live userinfo; failed replacement keeps the prior account. Catalog GET routes require the current cookie and an unexpired account, with private credentials injected by the auth owner. Games/latest mods/files return `{items:[...]}`; direct mod lookup returns `{item:{...}}`. Hidden mod parents cannot expose their files.

The owned fixture uses fake credentials and a local TLS service while preserving the production URL/SNI and CA/name verification. Production registration, trust configuration, console stack/runtime and same-device browser return still require validation. Account sign-in never establishes mod compatibility, install authority or UE4SS/DLL execution. Prerequisite installation and game deployment capabilities remain false.

Local verification of this sign-in slice passed 32 actual-app HTTP/TLS checks over nine owned token/userinfo transfers, including timeout response/reuse and failed-account replacement. The final host and PS5 app compositions compile/link; the PS5 include closure has no host headers. The app has not performed a live Nexus sign-in or run this flow on the console. Reproduce the fake public configuration with `python3 tests/nexus_auth_verify.py --mode prepare-config`, build a fresh download profile with the returned `oauth-config.json`, then run `tests/nexus_auth_verify.py --mode full --app-profile /absolute/fresh/desktop_fixture-download --oauth-config /absolute/fake/oauth-config.json`. The verifier checks current sources, objects and include bytes before reusing the app. Its TLS socket mapping exists only in a separately linked test copy.

## Native download and analysis jobs

Select `--archive-profile /absolute/verified/archive-profile` and `--job-directory /absolute/private/downloads` together with configured OAuth and download dependencies. The builder validates retained libarchive, zlib and LZMA identities without fetching or rebuilding them. At runtime the directory must already exist, belong to the current process user, and have mode 0700. Jobs are disabled without this explicit configuration.

`POST /api/jobs` requires cookie, CSRF, exact Origin, a canonical Content-Length and at most 4096 bytes of JSON. The intent accepts only `kind:"download_analyze"`, `game`, positive `mod_id`/`file_id`, and `idempotency_key`; NXM and target references are currently rejected. Eight process-lifetime records expose cookie-scoped list/status responses. Matching repeated intents reuse one job; a changed intent with the same key is refused. A free account reaches `needs_nexus_authorization` without downloading an archive.

The app attempts its HTTP 202 response before processing one queued job on its serial main loop. An admitted job can still run if the client disconnects or response transmission fails; retries with the same intent remain idempotent. Status polling is unavailable while that synchronous job runs. Cancellation, durable receipts and restart recovery are unfinished. The archive transfer uses no account headers, writes an exclusive generated 0600 scratch leaf, checks complete readback, and reopens the same file read-only before analysis. The source archive is unchanged. Successful files stay privately owned until process shutdown; failed files are removed. Cleanup failure retains ownership and makes shutdown fail.

Analysis calls the real archive scanner and grouping code without extracting or placing files. Its bounded report includes source hash/size, member/group counts, and filename-derived PAK/IoStore/INI/Lua/DLL candidates. Candidate names establish no compatibility. ZIP completeness requires an ordinary central directory and complete footer; ZIP64 forms are refused in this slice. Every report keeps runtime and installation false. The UI labels native PS5 analysis separately from desktop preparation.
