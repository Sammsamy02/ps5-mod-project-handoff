# Config request host example

`request_config_job PRIVATE_INBOX REQUEST_REF` consumes the separate `MBCFGREQ1`/`MBCFGCTX1` preparation format. The inbox must be private and exclusively owned for the call; all original inputs stay immutable. Profiles carry target entry, mount, hash seed and selected sections. The unchanged downloaded archive supplies its selected member through completed intake and a checked materialization journal. No member SHA/size, pre-extracted content or mod-specific content rewrite is an input.

This caller creates an exclusive claim, materialization directory, unpublished output and receipt under bounded relative names. It checks original PAK identity, calls the reusable borrowed-FD config job, syncs and reads back its output, then saves a request/context-bound receipt. Failures retain private artifacts. This example has no retry/resume or crash-recovery publication protocol; an already claimed request refuses. A complete preparation receipt plus successful process exit is required. It never installs into a game.

Compile this translation unit with `archive/config_request.c`, `archive/private/fd_io.c`, `format/config_file_job.c`, `format/config_target_selector.c`, the neighboring archive-config example's `config_archive_scope.c`, and the same archive/format/PAK modules and pinned host dependencies described in that example. Include archive/private for `fd_io.h`. The retained `ps5-config-job-integration-2/trial-1/receipt.json` records the exact successful build and invocation against byte-identical component sources.

The actual unchanged RAR→request→prepared PAK run matched the previously independently extracted canonical archive byte for byte. All 19 requested job allocations were released, with a 25,354,216-byte requested peak. A claimed replay refused without changing any inbox file. The request/schema carries preparation data only; it grants no installation or runtime capability. Receipt fields distinguish a returned status from an initialized job result and distinguish a present partial file from verified output.

This is a host composition example, not an HTTP/download producer, resident app queue, default build target or PS5 execution result. Existing app/UI work stays paused. Target `pwrite` behavior, native durability/publication, setting effects and UE4SS/DLL execution remain unproved.

`stream_config_job.c` is a second entry point for the local byte-stream composition. Build the existing caller translation unit with `-Dmain=pm_request_config_job_host`, then link that object with the stream entry point, `archive/config_request_producer.c`, `archive/private/file_sink.c`, and the dependencies above. Its CLI takes an unchanged local source location and base/profile data; the file sink measures raw archive size/SHA, and the C producer generates request/context bytes before calling the existing preparation entry point in-process.

Before calling it, the development caller must create a private exclusive inbox and stage the immutable original as `base.pak`; downstream preparation checks the supplied base identity. The stream example does not discover/capture the base. A missing base refuses preparation after private stream/request artifacts have been retained. Local successful EOF/stat stability supplies the stream completion event. This example contains no HTTP client, credential handling, network transport or native-target assertion; the prior curl transport upgrade stopped by automatic review was not retried. Its full compile/invocation is retained in `stream-config-request-composition-1/trial-1/receipt.json`.

## Automatic target discovery

`auto_stream_config_job.c` and `auto_request_config_job.c` exercise v2 without a caller-supplied project, full config path, PAK mount or seed. The caller supplies platform, selected sections, base identity and archive member-selection policy. The structural selector requires exactly one `ROOT/Config/DefaultEngine.ini` anchor and its corresponding `ROOT/Platforms/PLATFORM/Config/PLATFORMEngine.ini`. It excludes `Engine` and refuses missing, duplicated or ambiguous candidates. This is a bounded layout rule, not proof of config load order.

Build `auto_request_config_job.c` with `-Dmain=pm_auto_request_config_job_host` and link it with the auto stream entry point and the same modules above. The updated request producer and decoder expose separate v2 APIs using `MBCFGCTX2`; explicit-layout v1 remains available. Auto mode rejects supplied target, mount and seed fields. The borrowed-FD v2 job derives them from verified original metadata after decoding entries.

The actual unchanged RAR→C-generated auto request→target discovery→canonical PAK composition passed in 2.303 seconds on the Mac. Its 297,483,249-byte output matched the existing canonical archive exactly, including all 4,698 untouched payloads. No extracted mod file or prepared game layout was provided. The retained `unreal-auto-config-composition-1/trial-1/receipt.json` records the build, invocation, derived target and source identities. All private inbox, borrowed-FD and preparation-only limitations above still apply; this was not PS5 execution or an in-game effect test.
