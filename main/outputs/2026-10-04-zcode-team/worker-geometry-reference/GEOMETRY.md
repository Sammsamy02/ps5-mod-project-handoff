## 3. THE mapping model: uniform slide, `runtime = p_vaddr + 0x400000`, all LOADs

**Confidence: very high — the only model that fits every pinned observation.** The image occupies
runtime `[0x400000, 0xc0602c8)` (page-rounded end 0xc064000), ~192 MiB, contiguously except the
sub-page phdr gaps. There is no per-LOAD slide, no hole between the segments.

## 6. The giant readable span [0x8018c000, 0x100118000) — classification

- **OUTSIDE the image extent** [0x400000, 0xc0602c8) by ~1.8 GiB. It is not an eboot segment (largest
  LOAD is L0 at ~116.5 MiB); do not map any seed or window into it by arithmetic.
- **Real as observed at its vintage** (igf `g5_vmmap` and igf2 `v1_vmmap_full`, both structsize-aligned
  φ=0 reads; byte offsets of the end literal: ingame-v1-facts byte 2384, ingame-v2-facts byte 2384;
  adjudicated REAL by worker-span-arbitration VERDICT §5.4).
- **Not stable geometry:** the igf3 clean walk contains NO ≥1 GiB readable span anywhere; at that
  vintage 0x8018c000 is covered by a 32 KiB R-- span inside a dense mixed-prot (4/1/3) neighborhood
  starting 0x80000000. So the giant span is a vintage-transient, coalesced state of non-image memory.
- **Plausible identity (NOT asserted):** a large data/heap-reservation-class mapping in the game's
  2-GiB neighborhood (module/JIT/plugin band). Identity is **UNKNOWN**.
- **Live consumers that must be corrected or re-gated:** `worker-initializer-integration/SEED-TABLE.json`
  `fname_remedy.heap_span = [0x8018c000,0x100118000)` (inherited from this span — re-derive from a
  fresh same-invocation mapscan before any allocation depends on it); host mock
  `worker-polyhook-prospero-layer/host/prospero_platform_host.cpp:452` ("allocator must hint into the
  gap [0x787c000,0x970c000)") encodes the false hole — on the live map that range is L1+L3+L7 image
  memory.

## 8. Known-false claims (RETRACTED — do not cite any of these)

1. **"Continuous hole [0x787c000, 0x8018c000)" — FALSE, RETRACTED.** It stitched the v1/v2-era exec
   span end (0x787c000, valid) to the v1/v2-era giant span start (0x8018c000, valid but non-image and
   vintage-transient) and treated "nothing recovered between" (an artifact of the 1160-stride vmmap
   corruption — worker-span-arbitration §2) as emptiness. Reality: the igf3 clean walk tiles
   [0x400000, 0x9a34000) with 7 contiguous kernel spans; igf7 byte-matched reads sit inside the
   alleged hole at [0x787c000,0x82bc000); igf4 read+write GUA inside it at [0x970c000,0x9a34000);
   launch-9 counted 6 readable spans intersecting the image extent. The only genuinely unmapped
   stretch below 2 GiB at igf3 vintage begins at 0x9a34000 (after L7's BSS) and includes all of L8's
   range. Any fix prioritized by the hole model was mis-prioritized; the actual launch-9 code=1 root
   cause was the supplier's containing-base anchor rule (worker-facts-geometry-fix CLAIM.json), not a
   hole.
2. **"Single global bias DISPROVEN" — FALSE, REVERSED.** See table row 5. Uniform bias 0x400000 is
   confirmed for L0/L1/L3/L7.
3. **"LOAD7 file+0x400000 would start 0xd13c000" (controller seed) — FALSE.** 0x913c000+0x400000 =
   0x953c000 (0x4000000 was added instead of 0x400000). The observed fragment fits L7 exactly.
4. **"Image extent [0x400000,0xfc602c8)" — FALSE digit.** Extent end = 0xc0602c8
   (`runtime_start_bridge_r13.cpp:493` computes it correctly at runtime; the `0xfc602c8` string exists
   only in a comment typo at `:509`). Count fact "6 readable spans" stands.
5. **"LOAD3 memsz=0x12800000" (controller seed) — FALSE.** It is 0x1280000 (phdr bytes, record @file 0xe8).
6. **"GMalloc label 0x9350950 with delta 0x3B0488" — FALSE.** True delta 0x970add8−0x9350950 =
   0x3ba488 (seed digit slip); label rejected; correct derived label 0x930add8.
