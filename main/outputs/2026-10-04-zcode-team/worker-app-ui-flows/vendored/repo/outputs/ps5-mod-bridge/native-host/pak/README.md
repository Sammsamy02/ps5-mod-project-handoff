# Read-only classic PAK v11 library

The separate [v3 None reader](#classic-v3-none-reader) additionally handles the older flat-index layout found in a downloaded mod. It does not relax the v11 parser below.

These C modules implement bounded, reusable archive staging for the native manager. They are tracked copies of the verified experiment components, with local header includes. They have no game-name or mod-ID branches, network calls, install destinations, filesystem writes or controller UI integration. `pak_read_v11_selected_payload` always returns `installation_supported == 0`.

`pak_validate_v11_candidate` is the composed read-only operation. Select its explicit `CLASSIC_V11_UNENCRYPTED_STORED_SHA1_V1` profile and a directory row, or request metadata only. It validates the captured primary and both raw secondary SHA1s, parses the exact hashed directory bytes, walks every compact record to establish real starts, and requires matching counts, unique references and unique exact UTF-8 directory/filename pairs. Empty inventories are supported. Negative/nonencoded/tombstone references and unsupported codecs are rejected.

For one selected row, it checks indexed extents against archive metadata and other indexed extents, parses and reconciles the physical header, and verifies stored-byte SHA1 plus exact None/Zlib output. The unencrypted profile hashes raw None bytes or compressed Zlib blocks in order. It accepts a repeated stored offset of zero or the indexed archive origin and applies explicit single/multiple-block nominal-size rules. It does not try alternate hashes or framing. Path-hash contents remain opaque; other payloads are not verified.

Large unselected entries do not prevent metadata validation or selection of a small entry. Stored metadata sizes are bounded by the logical archive size and the format's signed size limit; decoded metadata sizes use that signed limit. These scalar fields allocate no payload memory. Selecting an entry still applies the existing 4 MiB stored/decoded cap before any physical-header read, with the codec and caller-output limits described below. An oversized selection fails at `SELECTED_EXTENT`, retains spent metadata budgets and clears outputs.

The composed operation accepts uncompressed `None` selections through that 4 MiB ceiling, subject to caller capacity and remaining budgets. It reads into existing scratch in chunks of at most 64 KiB, checks the exact stored SHA1 and charges each copy before publishing a result. It allocates no whole-entry input buffer. Zlib compressed/decoded blocks remain capped at 1 MiB. Provider cancellation is handled at each read; the generic candidate cancellation callback is checked at stage boundaries and before publication, without a hard interruption guarantee during a payload read.

The caller supplies disjoint typed state, scratch, complete row/name/output buffers and one initialized codec budget. One operation initializes one read ledger; defaults are 20 MiB requested bytes, 4096 calls and 64 KiB per request. Secondary verification reserves directly against that same ledger and captures the directory through a noncharging tee. Other stages use a charging source proxy. Every original callback sees one prior deduction, including failed provider attempts; no child counter is deducted again. Reference validation has bounded steps/name comparisons and cooperative cancellation. Whole success publishes rows and optional selected bytes; every operational failure clears full row/name/sink capacities and all scratch, retaining spent budgets and causes. Invalid known aliases leave all outputs untouched. Installation, authenticity, game acceptance and path-hash-semantic markers remain zero.

The primary reader verifies the declared primary SHA1 and permits only the supported unencrypted classic v11 layout. Both secondary-index presence fields are LE32 0/1 values. The entry pipeline captures the exact primary bytes already read and hashed, then decodes one caller-selected compact record. The directory parser separately reads a supplied classic directory span into caller-owned rows and UTF-8 names. A directory offset inside the encoded span does not establish a valid record start or a safe install path.

The older raw `pak_read_v11_selected_payload` adapter produces bytes for exact `None` and `Zlib` methods. Its caller-owned output is at most 4 MiB; each compressed or decoded block is at most 1 MiB, as is its implicit uncompressed entry. Those older adapter limits are unchanged; use the composed reconciled operation for larger bounded None selections and stored-SHA1 validation. The raw adapter carries the metadata reader's requested-byte/call counters into payload reads, charges requests before provider callbacks and passes one caller-initialized codec budget across all blocks. Failed reservations are never refunded. Preflight rejects invalid or overlapping objects without writes; every subsequent failure clears the entire supplied output capacity, publishes no completed bytes and clears supplied scratch. Provider snapshot immutability is the caller's assertion, not a property proved by the library.

The Zlib adapter accepts one exact RFC1950 stream, complete expected output, checksum and end-of-stream, with no trailing input, raw DEFLATE, Gzip or external dictionary. Its cooperative work/step/allocation budget applies to codec work and uncompressed copy operations. It does not interrupt an upstream call or account for all metadata/cleanup CPU work. Build all codec units with `Z_SOLO`, `NO_GZIP`, `ZLIB_CONST` and the tested Clang `-fno-strict-aliasing` arena profile.

Owned modules use no heap allocation or retained caller pointers. This is not a heap-free executable/import claim: the linked unchanged Mbed `platform_util.c` includes an unused helper importing `free`, and development fixture callers use libc file I/O. Source providers may have their own implementation behavior.

## Offline verification

Provide already acquired, exact Mbed TLS3.6.7 and Zlib1.3.2 source directories. The command checks the dependency lock and fixture provenance, fails on absent/mismatched inputs and performs no download, account or console operation:

```sh
python3 native-host/pak/verify.py --mbedtls-source /absolute/mbedtls-source --zlib-source /absolute/zlib-source
```

Or run `make test-pak PAK_MBEDTLS_SOURCE=/absolute/mbedtls-source PAK_ZLIB_SOURCE=/absolute/zlib-source` from the project directory. This dedicated target is not part of a default full test sweep.

For the composed candidate operation, run `make test-pak-candidate` with those same source variables, or invoke `verify_candidate.py` with the source paths and `--output-dir`. This dedicated command verifies both upstream archives/all eight outputs, targeted hash/reference/header failures, exact and insufficient aggregate budgets, late provider/codec failures, cancellation and whole-buffer rollback. It also generates separate local empty/two-block test inputs. A virtual large-entry regression uses the retained upstream fixture with only a small original prefix and relocated metadata backed by the provider; it verifies metadata success, exact small selection and oversized-selection rejection without reading the unavailable large payload. The focused C caller passes 10,232 checks. Add the same SDK/LLVM/resource options for PS5 compile/link without execution; the updated composed caller links successfully. No old full matrix, sanitizer or console operation is part of this target.

The same driver compiles the 19 common units once and links a separate large-None caller. Eight small, generated fixtures supply independently hashed deterministic payloads; they contain no original assets or large on-disk payloads. Its 21 cases pass 4,138 checks, including 1 MiB + 1, 2,742,265-byte and exact 4 MiB selections, prephysical oversized rejection, late corruption/provider/budget failures with whole-output rollback, alias rejection and retained Zlib limits. The earlier caller keeps its small buffers. PS5 mode links both callers without running either.

The host command builds the actual tracked source closure, parses both independently produced upstream repak v11 archives and compares all eight selected decoded payloads with their four retained original files. It also rejects a stale primary digest without publishing payload bytes. Verification uses explicit checks and remains active with Python optimization. The Make target adds three optimized-driver rejection controls and an actual host probe output-flush failure control. The diagnostic callers accept only local bounded fixture input; they do not install files. Additional focused experiment checks cover invalid-width flags, later read/codec failure rollback and shared budget exhaustion.

For compile/link evidence only, add `--ps5-sdk /absolute/sdk`, `--llvm-config /absolute/llvm-config`, `--resource-dir /absolute/clang-resource`, and a separate `--output-dir`. Both diagnostic ELF callers are linked without execution. This command does not dispatch, load or contact a console.

Dependencies remain unmodified external sources. [dependency-lock.json](dependency-lock.json) identifies selected source/header inputs; [Mbed notice](notices/Mbed-TLS-LICENSE) and [Zlib notice](notices/Zlib-LICENSE) retain their licenses. Fixtures retain pinned [repak provenance](tests/fixtures/provenance.json) and both upstream licenses. The repository associates the archives with its Unreal4.27 generator configuration; this project did not independently run UnrealPak.

## Remaining boundaries

The composed candidate API establishes supported metadata consistency and one selected raw payload, not archive authenticity or all-payload verification. It does not handle encrypted archives, IoStore, game-specific container variants, arbitrary codecs, PC-to-PS5 asset conversion, injected Windows tools or runtime hooks. No mod has run in Stellar Blade. Successful raw payload decoding is not an installation or game-compatibility decision.

## Classic v3 None reader

`pak_v3_none_reader.h` exposes `mb_pak_v3_read_none_v1` over the existing immutable `pak_source_v1` callback. Caller-owned buffers hold the index, entries, decoded names, sorting workspace, transfer scratch and optional selected payload. The reader allocates no heap, opens no files and has no installation authority. Known input/output aliases are rejected before writes; operational failures clear unpublished buffers while retaining spent read counters and the failure stage.

The admitted profile has a 44-byte version-3 footer, a SHA1-verified flat index ending at that footer, bounded UTF-8/UTF-16 FStrings, and 53-byte uncompressed entries with zero flags and block size. The reader reconciles every physical header with its index record, rejects duplicate exact paths and overlapping extents, and verifies the selected payload's SHA1. Metadata-only success does not verify unselected payload bytes. An embedding streaming writer must verify each payload it consumes.

Limits are 512 MiB per archive, 4 MiB for index and names, 8192 entries, 1024-byte paths/mount, 4 MiB for a selected payload, 64 KiB reads and a shared 20 MiB/32768-call read allowance. Unsupported versions, methods and flags are refused. Paths remain archive metadata; they are never filesystem destinations.

This route was added after the original v11 diagnostic refused a real 5849-byte Nexus download's older footer layout. The standalone reader recovered its exact 5643-byte config entry. The focused `tests/v3_reader_control.c` passed 56 assertions covering that sample, malformed offsets, index/payload hashes, unsupported methods, physical-header disagreement, short reads, repeated metadata-only use and alias refusal. The control takes that separately acquired sample as an argument; no mod content is committed. The pinned repak implementation independently identified the same v3 mount and entry. The private source receipt is `pak-v3-none-reader-1/receipt.json` beneath the retained dependency-spike directory.

Build the reader/control with C11, the existing PAK includes, Mbed TLS `sha1.c` and `platform_util.c`, and `-DMBEDTLS_CONFIG_FILE="pak_mbedtls_config.h"`. This is ordinary host format-processing evidence. Console execution, mounting and gameplay effects require separate evidence.

The [v3-to-v11 host example](../format/examples/v3_pak_transcode/README.md) connects metadata-only reading to the existing streaming writer. It verifies every consumed payload SHA1. Independent repak extraction of the original sample and converted archive recovered identical paths and all 5643 payload bytes. The conversion preserves content; it does not merge base-game files or prove PS5 acceptance.
