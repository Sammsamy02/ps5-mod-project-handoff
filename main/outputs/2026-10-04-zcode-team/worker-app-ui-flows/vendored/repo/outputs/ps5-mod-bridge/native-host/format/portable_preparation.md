# Portable config and streamed PAK preparation

`ini_scalar_merge.h` exposes pure C11 `pm_ini_merge`. It consumes an immutable base, ordered source byte views and caller-selected ASCII sections, and writes into caller storage after complete syntax validation and capacity measurement. It preserves the BOM and unrelated raw lines, matches selected keys case-insensitively, chooses the last source/line value, collapses overridden base duplicates at their last occurrence, and appends new keys to the last matching section. No game paths, section names or CVar names are compiled into it.

This is a bounded scalar subset: UTF-8 input with optional BOM, LF/CRLF and ASCII headers. Selected arrays, structures, mixed quoted syntax and continuations are refused. Unicode values and non-header opaque lines are preserved. Each input is at most 1 MiB, output 2 MiB, with 16 sources, 64 selected sections, 16K lines per input and 4,096 distinct scalar winners. The typed workspace occupies 704,784 bytes. The caller owns valid immutable backing and mutually disjoint output, result and workspace; no heap, I/O or pointer retention occurs.

`pak_stream_writer.h` provides a separate `mb_pak_stream_write_v11_none` API. It leaves the existing small in-memory writer and its ABI unchanged. Trusted mount/path-hash-seed metadata and immutable logical file descriptors are supplied by the caller. Synchronous callbacks read payload ranges and write an unpublished archive; the writer uses a 64 KiB transfer buffer and caller-owned index/record storage rather than a resident full archive. Optional expected payload SHA1 values are checked during streaming. The caller must provide an immutable source and a separate unpublished destination, and discard or preserve failed partial output without publishing it.

The streamed prototype admits unsigned, unencrypted classic v11 / None archives with printable ASCII paths, at most 8,192 files and 512 MiB total output. Metadata is bounded by an 8 MiB arena. Unsafe paths, ambiguous names, path/hash conflicts, exceeded limits and callback failures refuse publication. Only an OK result with `archive_complete` establishes a prepared artifact. SHA1 checks corruption; they do not establish authenticity.

Retained host controls reproduced the actual scalar conversion exactly (3,626 bytes; two replacements and 28 additions), then rebuilt a captured 4,699-entry main PAK through the streamed writer. Independent pinned repak extraction retained every path and all 4,698 unmodified payload SHA256 values, with only the caller-selected config entry changed. The canonical writer emits a four-byte empty pruned-map count and a separate full directory map, populating 232,145 metadata bytes. This removes 119,022 redundant bytes from the first prototype. Shared sources here are byte-identical to the tested experiment sources.

Preparation uses C callbacks only; repak was the independent host oracle. An actual RAR-to-config-to-PAK host composition produced a 297,483,249-byte archive identical byte for byte to the retained repak artifact already installed for the console trial. Its 4,699 paths and 4,698 unchanged payloads also passed independent extraction. This establishes serializer parity for that profile without another console install. These modules are not wired to the app's download/job path and have not executed on the PS5. Successful bytes do not prove CVar availability, an in-game effect, PC asset/shader compatibility, or a Windows/Lua runtime. Original-game mutation and rollback belong to a separate reviewed install transaction.

The retained [one-process host example](examples/archive_config_job/README.md) connects raw archive intake and automatic member identity discovery to these modules. Member size/hash come from the completed inventory, rather than per-mod preparation arguments. It is a bounded single-config example with process-lifetime allocations, not a resident app job implementation.

Private recipes and results are retained in `unreal-config-portable-c-1`, `unreal-main-pak-portable-writer-1`, `unreal-main-pak-portable-writer-2` and `unreal-archive-config-pak-composition-1` under `.superpowers/native-dependency-spike`. The existing pinned reader's SHA1-only Mbed TLS configuration also supplies this writer's hash primitive. No target build or game operation was performed during source promotion.

## Reusable borrowed-descriptor job

`config_file_job.c/.h` now composes the existing PAK reader, scalar merge and canonical writer as `pm_config_file_job_v1(params, result)`. Inputs are immutable, read-only original/member descriptors and explicit profile spans; output is a distinct empty unpublished descriptor. It returns a typed status instead of terminating its caller. Every owned allocation is released through one cleanup path, and borrowed descriptors remain open with unchanged positions. The caller retains responsibility for sync, readback, publication and installation.

`archive/private/fd_io.c/.h` supplies bounded exact positional callbacks using ordinary `pread`/`pwrite`, including short-progress and `EINTR` handling. Its standard libc error semantics have host coverage. The previous target archive experiment exercised `pread`; it did not import or exercise `pwrite`, so target behavior remains unproved.

The retained `unreal-config-file-job-1/trial-1/receipt.json` records one actual 297,483,249-byte canonical rebuild in 0.503 seconds on the Mac, 25,354,216 bytes of peak requested job allocations and 19 allocations/19 releases. This is requested job-managed memory, not total process or codec heap. Malformed input, a distinct descriptor aliasing the original inode, and a forced third-write failure all returned without leaking job allocations or closing borrowed descriptors. Failed output can contain partial bytes and must remain unpublished.

The separate `MBCFGREQ1`/`MBCFGCTX1` decoder in `archive/config_request.c/.h` carries raw download identity, original PAK identity and profile data without per-mod member facts. A host composition proved request-to-archive-to-file-job output equality and refused an already claimed request without changing its files. This is ordinary preparation code, not an HTTP/download route or native installer. The existing `MBARREQ1` decoder and paused app/UI work are unchanged. Native standalone execution, target durability/publication, actual setting effects and other mod/runtime classes remain separate work.

## Automatic config layout mode

`pm_config_file_job_v2` adds a platform-only layout choice while preserving the v1 API. It calls `config_target_selector.c` over the verified logical inventory, requiring one project `DefaultEngine.ini` anchor and one matching platform config path. Mount and hash seed come from the original PAK metadata. No game name or full target path is compiled into shared code. Unsupported or ambiguous layouts return an unresolved status before output writes; they are not guessed.

The separate v2 request/producer APIs encode `MBCFGCTX2` with selection mode and platform, refusing legacy layout fields. The actual raw-archive stream composition generated those records in C and rebuilt the canonical PAK byte for byte in 2.303 seconds on the Mac. The generated context contains no game name, full target path, mount or seed. Focused selector controls cover the real 4,699-path inventory, ambiguous and missing targets, and a synthetic different project/platform. The FD job also refused an absent platform without writes. This establishes automatic preparation for the admitted layout and format subset, not cross-game runtime compatibility or native installation.

## Source-derived PAK replacement and addition

The [PAK union host example](examples/pak_mod_union/README.md) accepts a classic v11 None base and a v3 None mod PAK directly. It derives paths, mount and seed from both archives, rebases the mod's virtual paths, replaces exact matches and adds absent paths. It performs raw file replacement, with no INI scalar interpretation or platform-path substitution. Every chosen payload is streamed with its expected SHA1 checked. A real pair produced a 4699-file union with one replacement and 4698 preserved base files; independent decoded-content hashes matched every result. Focused authored fixtures also cover additions and rejection of mount/case/ancestor conflicts and corruption.

The same preparation now exposes a borrowed-FD entry point and a reentrant original-archive job through `pak_archive_job.c/.h`. The caller owns its workspace, source/base/quarantine descriptors and output acquisition. The job discovers one resolved standalone PAK without member-name/ordinal recipes, retains every regular member, and requires explicit component-only policy when extras remain unhandled. Its optional output callback runs once, after complete materialization and pinning of the selected member. Default-policy extra-member refusal never requests output. Recovery journals and diagnostics survive admitted failures; the job closes only its own member and directory-iteration descriptors. Output sync and publication belong to the caller.

The thin host CLI delegates to that job and retains its finalization checks. The original ZIP produced an output byte-identical to the independently checked union while preserving all three regular archive members, in about 0.62 seconds on the Mac. Ten focused job cases passed, including two fresh-workspace jobs in one process, borrowed descriptor/cursor preservation, invalid output refusals and preservation of an existing recovery journal. Ambiguous PAK choices and incomplete IoStore companions remain refused. Private evidence is `pak-archive-job-1`. App download/job integration, native execution, console installation and runtime compatibility remain unproved.
