# Pad error 0x80920004 — source check, 2026-10-07

**High confidence: `0x80920004` is the pad “already opened” error class.** Its unsigned value is `2157051908`; the signed 32-bit form is `-2137915388`. No pad implementation, import, handle ownership, or retry code was changed for this check.

## Public primary sources

1. The PS5 backend maintained by `ps5-payload-dev/SDL`, pinned commit `ee4c47dc0d617b3bc8f35108f9956baf228a1322`, defines `PS5_PAD_ERROR_ALREADY_OPENED` as `0x80920004u` at header line 10. This is the exact header already pinned by the local pad provider. [Pinned PS5 SDL header](https://github.com/ps5-payload-dev/SDL/blob/ee4c47dc0d617b3bc8f35108f9956baf228a1322/src/joystick/ps5/SDL_ps5joystick.h#L10).
2. The same backend opens the standard port using `scePadOpen` and treats a negative result as an error. This supports interpreting the captured return as an open failure; it supplies no documented PS5 ownership or borrowing contract. [Pinned PS5 SDL open call](https://github.com/ps5-payload-dev/SDL/blob/ee4c47dc0d617b3bc8f35108f9956baf228a1322/src/joystick/ps5/SDL_ps5joystick.c#L355).
3. Independently, shadPS4's pad error header defines `ORBIS_PAD_ERROR_ALREADY_OPENED = 0x80920004`. Its emulator implementation returns that code when its map already contains the `(userId, type, index)` tuple. These are primary sources for the emulator's behavior, corroborating the error name; emulator semantics do not establish the PS5 firmware contract. [shadPS4 error constants](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/pad/pad_errors.h#L10), [shadPS4 open implementation](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/pad/pad.cpp#L287). Accessed 2026-10-07; these `main` links are mutable.

Targeted searches for the literal code/name on `playstation.com` and `sony.com` returned no official public documentation in this search. These sources are public community implementations, **not Sony SDK documentation**. Search absence is not proof that official documentation does not exist.

## Local SDK and pinned provider

The retained `sdk-v0.43/ps5-payload-sdk/target/include` contains no pad-named header and no `80920004` / `PAD_ERROR_ALREADY_OPENED` definition. `target/lib/libScePad.so` exports `scePadOpen`, `scePadOpenExt`, `scePadOpenExt2`, and `scePadGetHandle` at the same stub address `0x3334`; those linker symbols give no error or ownership semantics. The pinned provider's separate SDL header contains the definition at line 10, SHA-256 `16436774be2082a3fa4fd6ca4e9792ce45bbfcac64de676d5a56a7b0e6f1a706`. Exact paths, SDK-library hash, numeric conversion, and inspection results are in [pad-sdk-inspection.json](../receipts/pad-sdk-inspection.json).

## Confidence boundary

- **High:** the numeric mapping to `ALREADY_OPENED`, including the signed/unsigned conversion.
- **Supported inference:** the logged `scePadOpen` attempt encountered an already-open pad resource/port condition.
- **Unproved:** which component owns the existing handle, whether the exclusivity scope is per tuple or process, whether another argument tuple could work, and whether borrowing is valid on this PS5. The code alone cannot establish those facts.

Existing checklist shorthand “host holds exclusive pad” should be read as a hypothesis, not a fact established by this error alone. This research authorizes no pad-code change or console experiment.
