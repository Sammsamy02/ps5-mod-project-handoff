# R4 selected-path XOM addendum (local source analysis)

Plain answer: no successful write to GAME instructions is identified as a prerequisite
for the original Item Spawner's first menu or first spawn in the retained selected path.
This is source reachability, not runtime execution, menu or spawn proof.

The R4 Program delta selects authenticated compiled layout declarations before the
retained parser/binder. Initializer and binding source bytes are unchanged from R3;
their actual target compiles select the new profile. The owner fix changes tagged
owner-pointer data reads/writes/traversal, not instruction reads/writes. Profile and
layout declarations are PRX-owned metadata. No new instruction patch or permission
provider was added.

The complete R3/l18 XOM table remains the analysis baseline: authenticated on-disk
function prologue checks; admitted pool/metadata DATA reads; object/vtable DATA reads
and native EXECUTE calls. The required game-thread event carrier swaps UFunction::Func
in GAME OBJECT DATA, not instructions. Exact writable-data coverage, callback/thread
and lifecycle behavior remain unproved on console after the new layout binding.

Eager SCO and deferred LoadMap inline-detour attempts remain rejected by the owned-memory
layer before game-text copying/patching. Their normal refusal allows the first action
queue to continue. Successful original LoadMap reset delivery over later map changes
remains unavailable under this implementation. Other mods requiring inline hooks are
not established compatible. No claim that the entire unchanged mod or every UE4SS API
is XOM-complete follows.

No controller, settings, original mod, game executable, kernel, console or timing changes.
