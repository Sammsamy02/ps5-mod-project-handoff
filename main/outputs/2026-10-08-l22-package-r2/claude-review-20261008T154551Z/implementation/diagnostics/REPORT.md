# l22 diagnostics overlay

Implemented item 4 in six copied .cpp units, the copied LuaType/LuaUObject.hpp shared error boundary, and one new inline logging helper. [CHANGES.json](CHANGES.json) maps exact original/candidate paths and hashes and supplies the include directory. Original hashes are unchanged. Parent owns full target compilation, header-dependent rebuilds, import comparison and final integration review.

Error visibility now covers UFunction validation/dispatch, caught native exceptions, existing protected Lua errors, FText construction, modern SCO failure/null paths, UObject/property pushers and nested ScriptStruct property lookup/set errors. Each completed original error message is logged before the same Lua error is raised. Native exceptions are logged then rethrown. The protected UFunction wrapper preserves numeric/table error objects without string coercion. Logging runs through a no-throw observer so a logger/formatting exception cannot replace the original return or error. A propagated failure may appear at more than one boundary; it is not counted as separate failures.

Progress markers report main.lua returning successfully (`Lua mod started`), synchronous RegisterKeyBind returning with key/count and modifier values, keybind callback entry, ExecuteInGameThread insertion and drain/callback return, and non-null StaticConstructObject results with class/object pointers. SCO messages say `widget/object constructed` because they establish a non-null object return, not successful initialization or concrete widget identity.

AddToViewport is labeled using the member name/index already present in Lua lookup and its resolved function pointer. The marker is emitted after ProcessEvent returns and explicitly says `void return; not visual proof`. No additional FName construction, ToString, UObject field lookup, or engine call was added merely to label it. The label cache is diagnostic-only; it records the most recently resolved matching function.
