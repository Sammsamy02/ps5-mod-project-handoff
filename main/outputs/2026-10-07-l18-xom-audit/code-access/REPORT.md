## Other selected accessors and exclusions

The optional native JMap collector reads vtable entries as data (JMapGenerator.cpp:1868) after Native::MemoryChecker readable admission and tests the function pointer's executable classification; it does not disassemble the pointed-to code in that loop. Its Windows VirtualQuery implementation at729 is inactive on Prospero. Its object/script bytecode/property dumps concern data and are not evidence of writable vtables. It is an optional generator, not an obligatory ItemSpawner startup step established by this audit.

Selected LuaLibraryOwned.cpp:36 deref_to_int32 uses owned safe_mem_read, registering only its destination and returning nil for an unregistered source. This applies to an address interpreted as code too; no arbitrary live-code read fallback exists. P:336's string_scan example is commented out. No selected standalone VTableSwapHook/VFuncSwapHook translation unit was found in the receipt selection; generic Unreal virtual wrappers read a vptr/slot then execute its value. Changing UFunction::Func is an actual data-side pointer swap and was audited separately above. Asmjit/Zydis internal buffer manipulation and generated owned trampolines are not live game instruction reads solely because the libraries are linked.

## Evidence limits and build decision

The earlier independent l16 review verifies the saved original ELF hash 3b6cfad47dd17fea17d429bce80ae374d1fd2ef8894672cce63f5a26853622fc, linked ctor0x23d590, file offset0x241590 and observed base0x400000 -> runtime0x63d590. Live constructor VirtualQuery protection was not logged, although the gate obtains a query; static X-only plus EFAULT does not positively prove live XOM. The new allowed cache branch must expose and validate mapping/identity/base facts, acquire bytes at module_start while filesystem is available, label file/live verification paths and retain terminal real faults. It must not silently make cached bytes satisfy an unchanged fresh-live gate.

For the current sources: preserve l16 EFAULT terminal/zero native calls and l17 cleanup/owner restrictions. Before claiming an XOM-capable functional build, retain and verify the saved decoder-disable configuration pin, and resolve the unproved readable vtable / writable Func-slot coverage. Remaining SCO and LoadMap hooks cannot be advertised as installed by a signature cache. Their normal refusal can leave initialization running, but callbacks are absent. This audit does not establish whether those missing callbacks independently prevent this particular original ItemSpawner menu or spawn behavior; that requires the separate actual-mod call-chain review and future authorized runtime evidence. No source mutation is recommended or made for this build by this audit.
