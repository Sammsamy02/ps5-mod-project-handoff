Let A be the entrant's counter addition, R its second Ready load, C the destructor's Closing store, Z a destructor counter load reading zero, and S the entrant's decrement. The entrant's program order is A < R < owner access < S, so its SC operations satisfy A < R < S. The destructor's program order is C < Z < managed state destruction, so its SC operations satisfy C < Z. The SC order is consistent with these program-order constraints; the non-atomic owner accesses themselves are not SC operations.

If R precedes C, A precedes C and Z. While that entrant still accesses managed state, S has not happened. The SC counter load therefore includes its increment, so Z cannot read zero until that entrant (and every other admitted entrant) has decremented after finishing. The destructor waits.

If C precedes R, the second phase load observes Closing or AfterDestruction: there is no intervening Ready store in this one managed lifetime. The entrant decrements and returns -1 without touching managed state. An entrant paused between the first phase check and A likewise either joins the counted set before closure or observes the closed phase at R and refuses. This covers a late addition after a destructor zero-read: it cannot subsequently pass R.

The Ready store occurs after owner-state construction. An SC load observing Ready has acquire semantics, so construction is visible before owner access. The Closing marker is declared after the managed owner fields and is destroyed first, so its counted-entry wait precedes those fields' destruction.
