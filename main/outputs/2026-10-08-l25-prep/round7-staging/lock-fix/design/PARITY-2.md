# PARITY-2: DESIGN-2 threading and locking against upstream UE4SS (Mac-only)

Labels: every statement here is **Mac-only** (source reading, no console data). Nothing is "console-proven".

Sources:
- **U** = PC upstream RE-UE4SS `.superpowers/native-dependency-spike/ue4ss-binding-research-1/upstream/RE-UE4SS/UE4SS/src/Mod/LuaMod.cpp` (and `.../UE4SSProgram.cpp`).
- **O** = the "original" tree `outputs/2026-10-08-l26-runtime/typescan-r4/original/src/LuaMod.cpp` (the l23 port; it is not PC upstream, and it already contains the PS5-only dispatch scope).
- **C** = candidate tree `.../typescan-r4/candidate/src/LuaMod.cpp` (sha256 prefix 4d6bc63b7a90a802) = build B4.
- **D2** = this design.
- Lock names: **H** = `LuaMod::m_thread_actions_mutex` (kept, narrowed to registry operations). **Q** = new leaf queue lock. **M** = new per-mod Lua lock.
- Entry classes for M: **Try** (queue-run, never waits, defers the item; forced after 2 s of continuous deferral), **Bounded** (cannot defer: waits at most a fixed time, then runs anyway and counts it), **Block** (start/stop of a mod: waits up to 5 s, then runs anyway and counts it).

Upstream facts I checked in the source this session:
- Keybind callbacks run on the UE4SS event-loop thread: `m_input_handler.process_event()` is called inside `UE4SSProgram::update` (U UE4SSProgram.cpp:1229); the callback takes H and then calls Lua (U LuaMod.cpp:1653).
- `RegisterKeyBindAsync` runs on the same thread but takes no lock (C 2085-2201; U:1534 per MAP-1).
- The upstream game-thread pump (`process_event_hook`, `engine_tick_hook`, U:4090-4157) takes H only in two short blocks and runs all Lua with no lock held. It has **no game-thread filter** (it fires on whatever thread calls ProcessEvent).
- Upstream `ExecuteInGameThread` takes H for `make_hook_state` plus the enqueue (U:4368).
- Upstream async loop (`update_async` / `process_delayed_actions`, U:7240-7313) runs Lua with no lock except the per-mod `m_actions_lock` splice.
- Upstream NotifyOnNewObject: the StaticConstructObject post-callback takes H and, on the game thread, **calls Lua directly under H** (U:6631-6680); other threads queue; the game-thread drain also runs Lua under H (U:3849).
- Upstream `lua_unreal_script_function_hook_pre/post` (U:132, 236) take no lock.

## 2. Net list of deliberate differences from PC upstream

1. Key callbacks normally run on the game thread (fallback: a non-game thread after 400 ms).
2. Callbacks of one mod are mutually exclusive across threads (PC allows overlap). Exceptions: a `Bounded` or `Block` entry whose wait expires runs anyway (counted).
3. `RegisterHook` and its siblings validate and raise before taking H (PC raises inside the guard).
4. NotifyOnNewObject keeps upstream shape (Lua under H) but is inactive in the current marshal world.
5. Game-thread-only pump filter and the absence of any detour stay as in B4 (platform).
6. No keyboard input source on PS5 (unchanged, separate gap).
