## 2. UObjectDeleteListenersCritical — verified but deliberately NOT published

AA/AE verify the engine locks it at +0x78 (Add/Remove/dispatch; lazy mutex ptr
+0x80, recursion +0x88), and ObjObjectsCritical=0x30 / ObjAvailableList=0x48.
None of the three were added to the profile. Grounds:
- `NativeLayoutSchema.inc` (.superpowers/native-dependency-spike/
  ue4ss-native-layout-binding-1/include/NativeLayoutSchema.inc:88-101) has NO
  rows for these names; `NativeLayoutBinding.cpp:74` THROWS "Unknown native
  member" for any INI key without a schema row → an INI key would refuse startup
  at StageNativeLayoutTexts.
- `require_layout` (BuildFactsChecks.hpp:62) REFUSES absent kRequiredMembers
  pins (`.present` check) → a pin without an INI key also refuses.
- No consumer: the port/l25 never lock the listener critical section
  (LockGUObjectArray/UnlockGUObjectArray are commented stubs, l25
  UObjectArray.cpp:811-818), and ObjAvailableList getters have zero callers
  (AL §4). AL's fix table: "do NOT publish without FTransactionallySafeCritical-
  Section layout proof".
- Publishing would need schema+binding+MemberOffsets machinery — outside the
  value-only 4-file scope (task rule: "add missing ones only if the schema
  supports it without new machinery").
AM's template would have added the Critical as a new fact+INI key+preflight row;
the values file documents this as the "drop path in PROCEDURE.md if absent" —
PROCEDURE.md is absent, and the drop is what AL's consumer map prescribes. The
verified values are preserved in CHANGES.json `listener_unpublished_offsets`
(0x78 / 0x30 / 0x48) for any future engine-native locking work (AA §4 records
the engine-native alternatives: AddUObjectDeleteListener @ runtime 0x8841A0,
Remove @ 0x884240).
