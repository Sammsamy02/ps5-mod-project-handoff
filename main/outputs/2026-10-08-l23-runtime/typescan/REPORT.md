# L23 type scan and pointer getters — local candidate

Status: five affected target translation units compile; four host suites pass in plain and fatal ASan/UBSan modes. Full runtime closure/package, final import comparison, official container calibration and console execution remain parent work. No console contact, upload, commit, pusher registration, mod change or original-source mutation occurred.

## Changes

- The actual TypeChecker field loop catches only `std::runtime_error` whose complete text matches the existing generated missing-member diagnostic. It retains unique fully qualified keys in encounter order, continues other fields/objects, prints every missing key, and reports scan completion before evaluating explicit core availability. All unrelated runtime errors, allocation failures and pointer-read refusals propagate.
- Each UE >= 5.6 nested string discovery is isolated: Array Inner, Set ElementProp, Map KeyProp and Map ValueProp. A missing key no longer prevents the other map key or later fields from being tried. No Ansi/Utf8 Lua pusher is added. A missing next-field traversal key ends only that object's unreachable chain; other objects are scanned. Repeated field pointers refuse cyclic chains.
- PS5 Map KeyProp/ValueProp, Set ElementProp and Array Inner generated header and source wrappers return pointer values rather than engine-slot references. Every const/non-const accessor looks up the current published map with `find`, then runs the shared guard. Missing map entries are never inserted. Searches of selected port sources found no assignments through these getter results. All dependents of the changed declarations must be rebuilt; old objects are not ABI-compatible with changed return semantics.
- Guard code lives in TypeChecker's translation unit. It checks readable pointer-slot bytes, target ClassPrivate bytes, validated class metadata and full base FProperty bytes before returning. Null, self-reference, unaligned/overflowing addresses, unreadable/partial ranges and foreign/unknown class targets refuse with a non-layout error. Known class means FFieldClass belongs to authenticated module data, its safely read FName matches an explicit supported property name and CastFlags contains FProperty. This uses neither Map/Set static discovery nor mutable class-map insertion; no superclass walk is required. TypeChecker's native bootstrap class helper also uses the guard.
- Initializer installs static callbacks only after native layout publication. The read callback reuses `PoolAdmissionEngine::coverage`, the existing VQ ABI and recorded copyin-fault ledger. It requires fresh whole-range committed CPU-read permission; no owned capture authorizes later direct heap reads. There are no copyin probes, startup bank accesses, blocking retries or `CheckStartupWait` calls in runtime use. Each call has a bounded monotonic 1-second proof budget, normally one VQ. Authenticated current-base cache metadata and observed readable module mappings additionally bind class metadata to a data PT_LOAD.
- Both existing startup failure disarms revoke the guard; an Initialize scope guard also covers failures including PostInitialize. Parent Program teardown must revoke after engine-facing cleanup/consumers have retired. Callback state is process-lifetime and captures no owner; install is single-shot and published atomically.

## Explicit core gate and selected-runtime basis

The core gate checks class presence and, for concrete property types, a positive discovered value size. It does not require every type the scan knows about. The exact candidate lists are visible in TypeChecker.cpp beside `require_type`.

| Core group | Selected-runtime reason |
| --- | --- |
| UObject, UField, UStruct, UClass, UEnum, UFunction, UScriptStruct | Object lookup, object/function/struct/enum Lua dispatch and reflected invocation in selected LuaUObject.cpp (dispatch at 507–528; invocation/property marshaling earlier in the same unit). |
| AActor, UWorld, UPackage | Selected object dispatch and runtime object/world/package operations; AActor and UWorld dispatch appear at 532–536. |
| FField, FProperty, FObjectPropertyBase | Foundation of field traversal, IsA/cast checks and property access used by all reflected APIs. |
| FObjectProperty **or** FObjectPtrProperty | Accept either supported object storage representation, with a positive value size; require their shared base. The actual discovery uses cast flags to select one representation. Tests cover each alternative alone. |
| FClassProperty, FStructProperty, FArrayProperty | Reflected class arguments, struct/table conversion and array iteration in selected LuaUObject.cpp. Array/struct checks are unconditional in argument marshaling at 339/397. |
| FBoolProperty, FIntProperty, FByteProperty, FFloatProperty, FDoubleProperty, FNameProperty, FStrProperty, FTextProperty, FEnumProperty | The selected runtime's fundamental scalar/name/text/enum conversion surface, also used by the unmodified menu/spawn API calls. Selected UE4SSProgram.cpp registers these named pushers at 1783–1811; selected LuaMod.cpp exposes property metadata at 1121–1149. |

The original immutable TownfallItemSpawner main.lua requires FName object construction (line 50), enum conversion (163), vectors/rotation/transforms (234–303), FText (434/469), struct colors/margins (364/460/534–544), integer Z-order (631), bool wrapping (476), and visibility enums (632/655/660). These ground the core property subset, rather than treating all 39 discoverable classes as mandatory. Source evidence hashes are in `results/CORE-SOURCE-EVIDENCE.json`.

Map, Set, narrow/wide unsigned numeric variants, delegates, soft/weak/lazy references, FieldPath, Optional and Ansi/Utf8 discovery are not blanket startup prerequisites. Their consumers retain their existing per-API refusal behavior. UCanvasPanel is intentionally **not** a generic core type: the mod's checked class lookup and construction at 527 already supply the appropriate mod/API admission; games without UMG must not fail this generic scan. The host core-gate test leaves CanvasPanel and optional string types absent and succeeds. This candidate establishes startup type availability, not completeness of every optional API or proof that the actual menu will work.

## Limits

Readability proof follows the project's existing VQ-then-read mechanism. It cannot freeze engine memory against concurrent engine mutation/unmapping; metadata use relies on normal stable reflection lifetime. Unknown classes fail closed. Root class metadata must be in authenticated module data and observed mappings; missing proof refuses rather than inferring heap readability. No new pointer layout value is inferred here. The current candidate must not package/deploy until the separate official/image evidence agrees on every promoted container fact. No console behavior is claimed.
