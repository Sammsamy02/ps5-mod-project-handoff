# Automatic downloaded IoStore preparation

The resident download job now accepts unchanged IoStore mod archives through
the existing shared container composer. Explicit `download_prepare_iostore`
and automatic `download_prepare` both use the original read-only archive, one
captured metadata profile and deterministic generic selection. No per-mod
rewrite, subprocess, AI conversion or expected output input is involved.

The owned HTTPS integration passed18 checks across22 requests and five jobs:

* Original camera RAR:8,043,992 bytes,26 verified incoming assets,27 emitted
  chunks. This preserves its original keyboard bindings; it is not the earlier
  D-pad adaptation.
* Original Leon ZIP:105,647,244 bytes,161 verified incoming assets,162 emitted
  chunks. All five physical artifacts match the retained original-source oracle.
* Automatic Leon selection chooses the IoStore group before its empty PAK and
  content-verifies both that companion and the plaintext README. Its five
  outputs also match the oracle.
* The same valid group plus an unknown regular member refuses without creating
  quarantine/output directories. A different source game remains unresolved.
* Idempotency and kind conflicts, credential-free archive requests, original
  source/profile identities and complete shutdown cleanup passed.

Evidence: `.superpowers/native-dependency-spike/native-iostore-prepare-jobs-1/green-2/receipt.json`.
The historical A196 app refused these new intents; RED evidence is `red-2/receipt.json`.
The existing INI/PAK owned HTTPS suite also passed all26 checks on this same new
host, including its independent full-container comparison (`config-regression-1/receipt.json`).

Five private artifacts are journaled by inode at exclusive creation before any
write. Their writable handles are closed by the core; uncertain close prevents
cleanup publication. The owner records a SHA256 stream for every physically
ordered write, then reopens and hashes every byte of each artifact against that
stream, including the entire sidecar. A final deadline check follows readback
closure. Unknown/substituted identities are retained for cleanup retry and are
never unlinked as owned files. Originals and captured game data remain unchanged.

The additive single/batch control APIs preserve old ABI layouts and entrypoints.
Ten focused controls passed304 assertions, including latched stop, partial
output, post-allocation ownership, final physical release past deadline and
uncertain close. The old single55/batch60 controls passed; all five batch outputs
still match retained canonical bytes. An SDK indentation correction changed
only formatting; current-source legacy proof is `core-gates-1/legacy-format-2/receipt.json`.

This proves private format preparation and SDK composition. The ELF was not
executed on the console, no game/system files changed, and no live account was
contacted. The captured profile contains development Mac paths; automatic
on-console capture/discovery, publication and launch are unfinished. Formats
remain constrained unsigned/unencrypted None/v8 IoStore and the documented v5
header subset, without asset recooking or shader conversion.

Each job prepares independently. A selected multi-mod generation must use the
existing strict batch composer and an explicit original-source set; the queue
does not establish conflict resolution. Prerequisite metadata, authorization
handoff, persistence and the final console Nexus UI remain unfinished. UE4SS
needs a real engine/game-thread provider, and Windows DLL execution is not
implemented. The full goal remains active.
