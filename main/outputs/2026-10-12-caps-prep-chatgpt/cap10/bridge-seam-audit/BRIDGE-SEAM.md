## Minimal concrete integration proposal for root

Single exact target: the candidate UE4SSProgram.cpp TU, hash pinned in SOURCE-RECEIPT.json. Add two genuine C exports and a tiny TU-local thread-local admission scope. Place that RAII scope immediately around the existing on_engine_initialized invocation at843–845, inside its existing mutex/shutdown check, with braces around the conditional callback body. Bind the actual `this` plus the actual shutdown atomic pointer; no static singleton lookup, fabricated engine addresses or global ready constant.

The exports would follow the existing proposed header:

- `modbridge_cap10_abi_version`: return1 for this bridge **contract** version, not a claimed UE4SS/Mono/runtime build version.
- `modbridge_cap10_runtime_probe(int32_t cookie,int32_t* reply)`: reject null reply with-4 before touching it; reject absent admission scope, shutdown requested, or false actual is_program_started with-3. On admitted success, write exactly cookie and return0. Keep reply unchanged on failure. Enclose the C boundary so no C++ exception escapes; define any exception-to-status policy explicitly before code is staged. This diagnostic cookie echo has real meaning only when gated by those actual state/lifetime checks.

The scope is non-owning but valid for the synchronous callback under the existing owner/init-return contract. It must restore prior TLS state on return/throw, and either explicitly refuse nested scope creation or define nesting restoration; it must not leak readiness beyond callback return. It carries no engine pointers through the C ABI. The same-thread shutdown flag check matters because the mutex is recursive: a callback can request shutdown itself. Other-thread shutdown requests wait on the callback mutex. No bridge operation invokes shutdown, scheduler, hooks, GUI, Lua or engine object access.

Future host calls Probe.Run synchronously inside this callback. Ordinary synchronous PInvoke must remain on that same native callback thread. Async work, arbitrary managed worker imports and cached readiness after callback return are refused; they require a separate real host admission/drain design. Native testing of this scoped component can precede Mono port work; it would prove only native diagnostics/admission. This deliberately narrower admission contract must be added to native_bridge_contract.h and the future host plan before implementation. It is not a general-purpose managed plugin API.
