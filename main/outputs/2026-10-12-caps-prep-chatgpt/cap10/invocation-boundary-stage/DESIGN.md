# Genuine managed invocation boundary: scoped design for root review

Design before code. No helper, host, runtime patch or test implementation is present. Existing reviewed bridge/observer and genuine sources remain unchanged. This proposal uses real Mono APIs and actual native observer windows; it does not implement a Mono port. B7 remains independent.

## Feasible component and exact missing integration

A small **native embedding-side** helper is source-specifiable, conditional on a genuine initialized/attached/retained Mono owner. It can invoke actual Probe methods, validate returned object class/value and deliberate exception class, and gather reviewed native observations. It cannot honestly auto-detect or safely repair an absent runtime/attachment/GC port. The current candidate callback owns UE4SSProgram, not a Mono runtime/domain/image/attachment. There is no genuine source call site that supplies these objects today; therefore no cumulative runtime replacement or call insertion is justified. An additive helper may be staged without a caller, explicitly disabled from target build by default, if root accepts conditional useful source prep. A compile opt-in only excludes accidental integration; it is not evidence of the real port contract and must never be labeled runtime fail-closed validation.

A future call belongs inside the actual synchronous ready callback *after* the genuine Mono owner initializes/attaches that same thread, loads the hash-associated admitted assembly, resolves imports to the retained same-image provider, and retains all owners through return. No standalone host struct, fake readiness callback, empty GC callback, attach-on-demand or ambient process lookup is proposed.

## Proposed smallest additive helper flow

Interface remains a same-image C++ embedding function with genuine MonoDomain*/MonoImage* arguments, int32 cookie and caller-owned fixed native report. It does not create an initialized-state boolean or retain caller pointers. Caller retains real domain/assembly/image/Mono/provider; no Mono pointers cross a public C/PRX ABI. It rejects null inputs/nonzero-cookie violations before work, but this does not validate arbitrary pointers or missing runtime initialization. Source integration must stay disabled until real owner/signature/root-scanning admission exists; no stub success branch.

1. Enter the real public outer GC-unsafe scope; restore its actual cookie on all ordinary native exits. Resolve/check actual Probe class belongs to supplied retained image, actual expected Int32 class and actual corlib InvalidOperationException class. Require genuine caller's admitted method/signature/loaded-artifact association. Do not assert static-call safety from name/arity alone. No host initialization, thread attach/detach, domain set/cleanup or module unload.
2. Run: construct params[0]=address of actual native int32 cookie; exc storage initialized NULL. Open reviewed RunImports immediately before actual mono_runtime_invoke(Run,NULL,params,&exc); on return inspect whether exc is nonnull first (ignore result if so), then consume finish immediately, before handle/type queries or unrelated imports. Finish bool and native report describe actual native calls only. Abort on ordinary early exits if window remains open.
3. Preserve result/exception in actual compiler-visible native root storage across the immediate finish and handle acquisition. This relies on the admitted native-stack/context scanning contract; no fake GC/host callback is sufficient. For no-exception result, require nonnull; acquire real short-lived pinned strong handle, reacquire target, require actual mono_object_get_class(target)==mono_get_int32_class(), unbox and memcpy exactly int32 to native scalar, then free. Require scalar0 AND accepted RunImports observations for Run pass. On exception, safely retain it if needed for reporting exact class, ignore result, and fail Run. No exception string conversions/managed accessors.
4. Throw: open reviewed NoNativeCalls immediately around actual mono_runtime_invoke(ThrowForHostBoundaryTest,NULL,NULL,&exc), initialize separate exc storage, check actual exc first, consume finish immediately. Require real nonnull safely retained exception with exact actual expected InvalidOperationException class and accepted zero-call observation. The native observer alone cannot prove managed origin/throw. Require no native calls during this actual invocation, not during a manufactured diagnostic throw.
5. Free every acquired handle, abort any unconsumed observer token, restore real GC cookie on every ordinary exit. Never interpret handle0 as a failure sentinel without actual source contract. Catch unexpected native C++ exceptions only for native cleanup/report; this does not catch Mono fatal assertions, OS faults, asynchronous teardown or establish target unwind support. Do not claim allocation-free invocation: actual Mono invocation/boxing/handles allocate.

Further real fresh-cookie Run after Throw is required for exception recovery proof, followed by actual game continuation and owner teardown/quiescence evidence. This can reuse the genuine Run helper once implemented; no synthesized recovery success or host lifecycle is added here.

## Fail-closed scope and resolver limits

The existing observer genuinely refuses missing actual callback admission, mismatch/nesting, native failures, readiness/shutdown loss and wrong sequences. The helper can refuse missing typed inputs, missing resolved classes/methods, wrong actual result/exception class/value and rejected observations. It CANNOT safely invoke arbitrary Mono pointers, discover a missing initialized runtime, dynamically attest native-stack scanning, or supply provider ownership. Those are hard genuine-host admission prerequisites. Default build exclusion is the only honest source-stage guard while they are absent; it is not target safety proof.

__Internal normally resolves process symbols; fallback registration alone is not an import allowlist. Future actual host must bind exact Probe import metadata/names/addresses to the retained same-image provider and exclude ambient accidental providers. The internal observer header links in that same provider image; a token is not a module lease. Source helper alone cannot prove final symbol retention, resolver selection, actual assembly load identity, managed origin or correct PInvoke transition.

## Root decision before code

Recommended useful next step is a conditional additive embedding helper only if root accepts explicit real-owner/loaded-signature/root-scanning preconditions and default build refusal. No automatic existing-runtime insertion exists. If the requirement is a self-contained helper that runtime-checks every prerequisite and is safe without a genuine Mono host, it is currently impossible; report that blocker instead of fabricating an owner interface. A complete public signature-validation implementation additionally needs genuine metadata.h declarations/implementation retained or a real owner's source-backed resolution contract; this task permits no new downloads. No tests or independent reviewer are triggered before this design decision.
