# Group requirements, discovery only

`group_plan.py` revalidates a chosen type8 manifest through exact SHA-pinned manifest-v1 bytes, including the original parser/TOC/intake and actual whole-chunk BLAKE3 checks. It reads no UCAS/group payload. Supplied manifest4MiB, catalogue8MiB, selections1–16, compressed group4MiB each/8MiB total and output8MiB are bounded. Existing manifest reader retains its bounded32MiB original TOC profile, full lookup checks and explicit reserved-header relaxation. Source format: ../group-intake-audit/DESIGN.md and source-receipt.json; MIT retoc d034ade1ae8117d4786eaf6b0418d4cf48474d7f. No source code is copied here.

Use `python3 group_plan.py --help`. Supply `--payload chosen.bin --receipt intake.json --chunk-id <exact type8 ID> --catalogue saved.json --catalogue-sha <SHA256>` plus repeated `--map <full20Bhash>` or `--group <raw12BID>`. Optional `--owner rawID:tocSHA:containerID:row` disambiguates one exact saved row. Optional `--out` must be a new file inside this directory; without it stdout reports a bounded summary. The synthetic command is saved in synthetic-command.json (change output to a fresh filename to replay). All synthetic inputs are small generated fixtures, not captured game bytes.

Output preserves manifest identity, full member stored hashes/packed metadata and offset-based spans, sizes, catalogue owner alternatives and chosen owner geometry/IoHash/blocks/method indexes. Missing captured rows yield INPUT_REQUIRED; multiple owners yield OWNER_SELECTION_REQUIRED. Wrong explicit owners or lengths refuse. Raw09 is exact; internalC9/legacy0C never normalize. Group codec requirements and transport codec requirements are independent. Equal group sizes establish only the stored-size profile, not payload validation.

Every group remains ID_DERIVATION_UNCHECKED and writer_profile_admitted=false. An ordered zero-prefix layout is only a candidate; disordered members remain false. No exact shader-format string, ID recomputation, code hash definition, plain member SHA1 assumption, object+216 mapping, code decompression or compatibility result is supplied. Saved catalogue geometry is discovery evidence; actual group intake must independently validate the original full TOC and actual whole logical bytes with SHA/IoHash. Compression methods are indexes; this tool does not infer codec names.
