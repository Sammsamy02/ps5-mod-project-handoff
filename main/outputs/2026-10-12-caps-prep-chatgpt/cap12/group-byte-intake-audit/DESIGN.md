# Next component: verified logical group buffer

A small useful next component can verify an explicitly supplied whole logical raw09 `.bin` against the actual decoded type8 manifest and original full TOC. It needs no UCAS read, transport reconstruction, codec probing or additional format parser. This design reads source/metadata only; no utility or tests are implemented here.

Source basis is pinned MIT retoc d034ade1ae8117d4786eaf6b0418d4cf48474d7f, shader_library.rs lines94–96,249–305,1029–1057,1109–1173, and the existing hash-pinned overlay/manifest/planner utilities. Exact paths, hashes and line ranges are in SOURCE-RECEIPT.json. No public source is copied into this folder.

## Meaning of stored groups and spans

The public reader's sizes-equal branch consumes the logical group buffer without group decompression (249–265); the writer retains compressed data only when strictly smaller (1156–1169). Together these support treating a fully admitted sizes-equal buffer as uncompressed under this source-specified format profile. Equal sizes alone do not validate a supplied buffer or establish target-format applicability. Require complete length, full source TOC/lookup admission and actual whole-buffer BLAKE3-20/SHA verification first. Unequal sizes remain opaque with CODEC_REQUIRED; no member views or guessed codec.

The reader validates packed group membership, sorts members by uncompressed offset and takes each end from the next offset, with the last end at declared uncompressed_size (267–305). Existing manifest-v1 uses the same rule and additionally rejects duplicate offsets, empty/invalid membership and out-of-range starts. Therefore labelled byte-range views do not require member-array order to equal offset order or first offset0. A positive prefix must be reported as unassigned bytes, never attached to the first member. Disordered arrays remain valid for offset-based views but remain unadmitted for the writer-order group-ID derivation profile. For an optional stricter complete-cover profile, require zero prefix and strictly positive contiguous sorted spans ending exactly at whole buffer length. Writer-order attribution separately requires original member-array order equal sorted order; this is not a prerequisite for the reader's views.

The reader assigns extracted bytes to library shader indices; it does not recompute or compare stored shader hashes. The writer copies stored full20-byte hashes from the source archive and uses them, sizes and the exact shader-format string in group-ID derivation (1029–1057). This does not define which bytes/normalization generated a shader's stored hash. Do not assume plain SHA1 of a member span. A SHA256 of an extracted view may be labelled only a newly computed view-content fingerprint. Whole-buffer IoHash verification is integrity of the admitted logical chunk against the pinned TOC, not member shader identity, group-ID derivation, instruction decoding or target compatibility.

## Reuse boundary and recommended minimal refactor

Current `manifest_v1.verify_and_parse(payload, receipt, chunk_id)` does stable bounded reads, source-hash-pinned parser execution from verified bytes, full TOC parse/lookup, exact row/ID/IoHash/length/SHA/BLAKE3 checks, then calls the type8 parser. It hardcodes type8. Passing type9 through it is unsupported. Current `local_shader_intake.extract_verified(...)` reconstructs bytes from an already-local UCAS handle, which is outside this new provided-logical-buffer interface; do not call its main or reopen its UCAS provenance paths. The old intake main also uses a reopen-for-execution loader, so it should not be reused as a dependency loader.

Preferred implementation, requiring explicit coordination for edits outside the new folder: extract the existing manifest whole-logical-buffer gate into one shared `verify_logical_chunk` helper, keeping its bounded stable reader and verified-byte overlay loader. Keep `verify_and_parse` a type8 wrapper with its original behavior. The group adapter calls the same helper with expected_type9 and the exact owner. This avoids maintaining a second format/identity implementation. Extend the shared attestation with actual TOC container_id and explicit raw-byte type equality; preserve strict_admission=False's reserved-header-only relaxation and full lookup validation. No existing implementation has been edited in this audit. If that shared refactor is not authorized, defer implementation rather than silently weaken receipt verification or copy the gate into an independent verifier.

Proposed signatures (own API design, not source excerpts):

- `verify_logical_chunk(payload_path, receipt_path, raw_chunk_id, *, expected_type, expected_owner, limits) -> (immutable_bytes, binding)`
- `verify_group(manifest_payload, manifest_receipt, manifest_id, group_payload, group_receipt, group_id, exact_owner, *, selected_shader_indices=[]) -> metadata`

The wrapper revalidates the actual type8 bytes with the pinned manifest-v1 reader. It resolves exact group membership through that result; it never trusts editable saved decoded JSON or planner statuses. Planner output is an optional pinned discovery crosscheck, not admission evidence. The chosen owner is explicit `(TOC_SHA256, actual_container_id_bytes, row)`. Its TOC can differ from the manifest owner; never infer same container. The group receipt must bind that exact TOC, parser pin and unique raw09 row. A receipt is a provenance declaration, not cryptographically authenticated execution history. Rechecking actual whole group bytes/full TOC establishes the local integrity assertion independently; preserving original UCAS/slice scope avoids promoting receipt claims to full-store provenance.

## Exact gate and output

1. Stable-read/hash-pin all dependency bytes before execution; execute only verified bytes in a spec-created namespace preserving __file__/__name__. Bound receipt JSON2MiB, manifest/group each4MiB, TOC32MiB as existing profile, catalogue/planner optional8MiB, combined supplied payload bytes8MiB, selected group1 and member selections1–16 if supplied, output8MiB. Read no UCAS paths. Recheck bound identity `(device,inode,size,mtime)` and hashes after planning/verification.
2. Require exact manifest group ID12B, final raw byte09, unique manifest group, and strict owner triple. Reject internalC9, legacy0C and prefix-only matches. Require unique receipt row/count/schema/type9/iohash_verified declaration. Verify its parser source SHA equals the fixed original overlay pin; hash-check full owner TOC bytes; perform v8 parse and validate_lookup; compare actual container_id, row, complete raw ID, logical range and supported metadata flags.
3. Require `.bin` to be a whole logical buffer, not UCAS/partial header/physical compressed block. Actual length must equal receipt bytes, TOC logical length and manifest compressed_size. Verify actual SHA256 against receipt and actual BLAKE3-20 against TOC and receipt. Reject wrong-owner same-offset payloads even if length matches. No byte evidence is obtained merely from filenames or owner selection.
4. Report whole-buffer verification before the group codec decision. Sizes unequal return GROUP_BUFFER_VERIFIED plus CODEC_REQUIRED with no member spans applied to bytes. Sizes equal require full uncompressed buffer length and validated manifest offsets before range views. Preserve unassigned leading prefix, original member order and sorted-view order separately. Empty/duplicate/invalid span selections refuse; unknown shader indices refuse.
5. Default output metadata only: source pins/scopes/immutability checks, actual owner/chunk/IoHash/SHA/length, manifest source identity, full stored member hashes and indices, packed offsets, validated view ranges and optional newly computed SHA256 fingerprints. Explicit `stored_shader_hash_verified=false`, `ID_DERIVATION_UNCHECKED`, `target_format_proven=false`, `compatible=false`. No payload copies in the minimal version. A separately authorized optional copy mode could use exclusive new owned files with aggregate byte bounds; it adds no shader identity evidence and is unnecessary for the first adapter.
6. New output exclusively inside its own folder; no overwrites/clobber of sources, all checks before output. Ordinary local-filesystem threat model, not adversarial directory-race hardening.

## Focused proposed tests before implementation

One small TDD suite: a generated type8 plus generated whole raw09 buffer and genuine-format synthetic intake/fullTOC receipts. Assert exact nonidentity map/group/member resolution and whole-byte SHA/BLAKE3; source immutability; wrong SHA, wrong IoHash, partial bytes, wrong compressed-size length, wrong row and same-offset wrong owner; raw09 versus C9/0C; duplicate receipt/selection; malformed/seed-zero full lookup; pinned dependency replacement never executes changed bytes; changed sources after verification; read/selection/output caps and existing/output-input refusal. For sizes-equal, assert actual sorted views for disordered members and positive-prefix accounting; reject duplicate/outside/end-invalid offsets via manifest gate. For sizes-unequal, verify whole-buffer integrity then CODEC_REQUIRED with zero member views even if requested offsets fit compressed bytes. Assert neither stored shader hashes nor group IDs become verified.

Only this new suite and one synthetic CLI replay are needed after implementation. Real inputs remain absent. The next action is root authorization of the small shared-gate extraction and adapter, not payload acquisition or compatibility promotion.
