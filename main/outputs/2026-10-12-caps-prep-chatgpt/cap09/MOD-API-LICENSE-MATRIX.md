## Source-to-native plan (no build performed)

1. Retain published source untouched; record upstream commit, source hashes, exact UE4SS headers, toolchain/runtime identity and all transitive licenses. Existing SOURCE-RECEIPT.json is only the inspected mod subset, not a complete build manifest.
2. Audit every required hook and field against the current verified layout and `harvest/field_gate.py`; audit byte width, strings, exceptions/RTTI, STL, paths, thread ownership and input. Two independently verified sources for every shipped engine value; unknown values refuse.
3. Prefer initial same-runtime static composition to avoid assuming injected-module symbol resolution. It still needs registration plumbing and evidence: static linking is not proof of working lifecycle/GUI. Derived artifact provenance must state source adaptation if any, with originals retained.
4. Native dynamic artifacts require compatible C++ toolchain/libraries and a verified loader/gateway. `extern C` export names do not eliminate returned C++ object/vtable ABI requirements. Do not implement broad invented gateways from this prep.
5. Admit both candidates only when their complete required surfaces pass. Keeping hooks disabled can prove UI/load subsets but cannot prove full original mod support. Record precisely which function is demonstrated.
