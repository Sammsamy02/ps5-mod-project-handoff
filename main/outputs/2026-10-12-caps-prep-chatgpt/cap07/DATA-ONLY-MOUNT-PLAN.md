# Data-only mount plan for Claude — design-only

This is an input to future staging, not permission or a ready runtime implementation. Current B7 + hooks + 15-fields work keeps its existing inputs and schedule. No runtime patch script is emitted while the hook ABI/read seam is unresolved.

1. **Immutable intake.** Capture a complete inventory of base containers with path, version and hash; bind source mod hashes, relevant package stores, UCAS geometry and generated artifact hashes. Use discover_containers.py to report package ownership in captured files. Unknown inventory/store coverage remains UNKNOWN, never “new package”. Refuse unsupported, ambiguous, empty or multi-container plans unless the chosen route has corresponding tested support.
2. **Resolve pin geometry and sources.** Use PIN-AUDIT.md. Keep table storage start and object vptr address point separate. Require two source records per shipped engine value, authenticated saved-image identity, relocated live object/table agreement, readable-range guards and exact call/return ABI. Do not read XOM code or publish hardcoded title offsets.
3. **Observation contract.** Establish a common clock and coverage start for module entry, chain readiness, first Paks enumeration, index opens, partition opens and read completion. Record layer/instance, normalized path and handle route. Installing a logging vptr hook still mutates engine object data; it is not a mutation-free observation. No mount calls or file substitution in this arm. Unresolved async ABI means no async thunk; use further offline analysis before proposing that arm. A callback observed after boot cannot prove the first open was intercepted.
4. **Route selection after evidence.** Prefer B1 native discovery only if armed before first scan and foreign-container acceptance is established. A1 can rehearse classic loose-file mounting, but does not by itself prove Leon IoStore support. B2 requires coverage of both index and sidecar opens/reads, including actual async routes, before first cached reader consumes the index. An arm installed after initial reads cannot repair existing handles. The captured Leon case spans two base owners: prove unified-container precedence or support the required per-container store/geometry closure; do not silently use only one owner. A2 late-add stays blocked on package-store semantics. If none is admitted, stop with evidence; no kernel fallback or dump edits.
5. **All-or-nothing generation.** Build derived artifacts only in our mod root, retaining original mod bytes. Check all base identities before publication. Bind derived index/sidecar identities together; missing, stale or incompatible inputs keep the entire arm disabled. Once an overlay generation has issued handles, keep that immutable generation alive through last close; do not mix new real bytes into old overlay handles. Partial publication, unknown callbacks or concurrent retirement fail admission. Base partition 0 stays original. Full path identity must come from discovered live paths, not just a basename.
6. **Lifecycle.** Marshal work through the verified engine thread; publish only at a demonstrated safe lifecycle point. An aligned vptr store alone does not prove quiescence. Retire by ownership-checked restoration and drain callbacks/handles before freeing copied tables or storage. Preserve untouched slots and header. No game-code writes, detours, mod edits or game-dump writes.
7. **Staging when ready.** Any eventual runtime code is supplied as exact-once replacement scripts against exact candidate files, with all matches validated before writes and refusal on mismatch; Claude applies them and runs existing gates. We do not apply, compile, upload, launch or alter harvest inputs.

Observation correction from branch-selector-audit/ and sorted-handoff-audit/: distinguish the complete heap factory from the static file receiver. Record actual factory setup/queue-sort configuration and scheduling conditions alongside handle-route identity; a constructor zero is not evidence of the running queue mode. The saved positive sort setting leads to flag==1 after setup, for which only a conditional priority-0 singleton handoff is now closed. Queue ordering does not identify the direct/pooled transfer provider. No saved-image offset from these audits is admitted as a shipped value.
