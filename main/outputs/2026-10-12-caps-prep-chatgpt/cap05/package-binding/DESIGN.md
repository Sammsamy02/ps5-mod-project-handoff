# Package-layout binding design

The final-symbol producer is still the source-only stage in ../final-symbol-producer-audit/. Its staged Program.cs HARNESS_POST emits exact bare_elf_sha256/bytes plus final ELF VMA ranges, input and producer-assembly hash declarations. It is unapplied/uncompiled; no genuine producer receipt exists. This verifier accepts a future explicitly SHA-pinned receipt, checks its bare bytes and bounded declared FUNC ranges, and produces ELF_LAYOUT_BOUND_ONLY. It cannot establish that declared functions came from a genuine executed producer or authenticate assembly/build provenance without a normal-build record.

The actual retained package_prx_l19.py:905–911 runs finalize_sdk then make_fself with input/output only. The default wrapper profile is paid0x3100000000000002, fake ptype, app/fw version0 and no auth-info; defaults are supplied by the exact hash-pinned retained implementation, not restated in executable logic. No extension documentation or SDK research was used: only the genuine script already named by the packaging pipeline was inspected. No wrapper source is copied here.

The existing symbolizer's ELF helpers are section/dynsym readers; retained dynsym_from_packaged_self has a fixed ELF-header location and is insufficient for proving packaged segment contents. This utility adds no SELF parser. It executes the exact verified genuine wrapper source in a non-main namespace, loads the supplied bare-SDK ELF from BytesIO, writes SignedElfFile to BytesIO and demands whole packaged-byte equality. This is read-only reproduction for verification, not a normal packaging build and not an emitted executable. The wrapper stores original segment bytes and unchanged program headers in its container; exact whole reproduction plus original→SDK executable equality establishes preservation for this exact profile only. Alternate wrapper options/source profiles refuse.

A small bounded ELF64 little-endian x86-64 gate checks full program-header bounds, all file spans and total segment-read budget, uint64 VMAs/memsz, known permission bits, power-of-two/congruent alignment, nonoverlapping load memory and file spans, and at least one file-backed executable load. Executable-load VMA/filesz/memsz/flags/content SHA are compared from original to SDK; other-byte equality and SDK stamp semantics are not claimed. Offsets/PHDR index may differ while exact executable VA extents and contents remain equal. Genuine wrapper reproduction uses the complete SDK bytes, including metadata.

Producer rows must be named nonzero declared FINAL-LINK-BOUNDED-FUNCTION ranges inside exactly one file-backed executable PT_LOAD. Exact address-convention text retains final ELF virtual addresses. Aliases may overlap, and no symbol completeness is claimed. This verifies range placement; absent .symtab it cannot independently prove the declared FUNC type. No offset rebasing, crash-compatible sidecar, module-base assumption or capture pairing is emitted.

Reads are bounded and stable across dev/inode/size/mtime plus full SHA rechecks. Artifacts≤64MiB, packaged≤65MiB, source≤512KiB, producer/output≤8MiB, PHDRs≤256, total referenced segment bytes≤64MiB and rows≤65536. Duplicate JSON keys refuse. Optional receipt requires explicit SHA; missing receipt produces INPUT_REQUIRED and zero symbols. JSON outputs use exclusive creation inside this folder and refuse source clobber. Ordinary local-filesystem model; not malicious directory-race hardening. All writes are own metadata/tests only, with no current B7 dependency.
