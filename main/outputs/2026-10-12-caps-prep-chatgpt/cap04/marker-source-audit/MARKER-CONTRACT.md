## Existing verifier comparison

`cap04/verify_milestones.py:18–51` accepts normalized declarations with one run/clock/build SHA, finite timestamps and cited decoded source lines. It requires exactly one coverage/module_start/observer_armed/loadmap_entry/begin_play, coverage from process start and lossless through all events, LoadMap ordinal 1, and strictly increasing milestone times. These coverage assertions are **supplied, not independently attested**. Raw mode at 55–71 intentionally returns INCONCLUSIVE even when discovery/refusal/search terms appear. FL-MAP order 1 must not be mechanically converted to normalized LoadMap ordinal 1. WORLD-EV first-delivery must not be converted to engine entry. Current marker text alone leaves missing identity, clock, coverage and entry semantics.

## Minimum generic instrumentation required for an honest proof

1. A capture boundary established before process activity, with persistent run identity, exact loaded-module/build association, monotonic clock identity/units, capture-start event and sequence/drop accounting through the end of the measured interval. A late-attached runtime cannot retroactively attest process-start losslessness; an external startup observer or an established startup barrier is required.
2. Module-entry and separate runtime-ready events on that same clock/run/build record. The verified ready callback seam can identify host initialization only; observer readiness must be its own event after all required observation paths are actually admitted.
3. A first-invocation counter at an admitted true LoadMap entry seam, active before the first possible invocation. Its ordinal must include every invocation, not merely callback registrations or events since delayed arming. Pair entry/exit with invocation identity and nesting/thread accounting if exits are also used. Emit explicit failed/partial arm status and record each registration ID; do not certify observer-armed from one successful side.
4. A true BeginPlay-entry event on the same clock with clear ownership and entry semantics; retain inferred WORLD-EV as a distinct event type. Record callback attempt/success/error separately if callback delivery itself is a proof requirement.
5. Preserve raw capture bytes and decoder/source hashes, final sequence/drop counters and capture-end boundary; only then construct cited normalized evidence. Strict ordering requires adequate clock resolution; equal timestamps remain inconclusive under the existing verifier.

These are required semantics, not a proposed target ABI or patch. The source gives callback/helper locations but does not verify a process-start capture seam, safe early entry admission, or final-link/execution association; therefore staging a source replacement here would be speculative.
