# Local whole-chunk intake — Mac-only

intake.py is a staged metadata adapter, not an acquisition tool. It accepts explicit already-local complete decoded logical-chunk .bin files only. Each job pins the existing base-input-audit.json SHA256, the Zen reader SHA256, and each input SHA256. The audit pins the overlay parser and Leon mod identity receipt. An exact owner-TOC SHA/container ID/row/chunk-ID selector must identify a unique audited row; logical length and whole BLAKE3-20 IoHash must match before any payload parsing. Same-offset wrong-owner, partial headers and empty jobs refuse.

Type6 ContainerHeader uses the existing pinned parser, retaining all v5 restrictions. Type1 Zen export decoding additionally requires a supplied hash-verified store from that exact audited owner and package membership; without it the row is OWNER_STORE_REQUIRED, with no inferred version or decoded exports. PackageImport indices are resolved only against that store's imported-package array. Output contains metadata, expected public-hash presence and selected mod export name/public-hash projections. ScriptImport class refs remain unresolved by this adapter; its output makes no compatibility, material-parent, complete closure or native shader claim.

The existing retained chunk0 ContainerHeader replay passed: 38,439 package entries checked, four audited required/downstream package rows projected, 2,484,269 admitted job/input bytes, every source unchanged. This is real store evidence only; no base export chunk was supplied or claimed. No asset UCAS read, range extraction or payload copy occurred.

The tool does not parse large TOCs, read UCAS files or acquire missing chunks. Audit capture/provenance and completeness limits remain unchanged.
