# Optional serialized Tick witness in the native C++ path

The selected native scan source now has an explicit route from an original
mapped Tick no-match to the reviewed serialized ELF witness resolver. It retains
a private file copy and the exact mapped owner, validates actual immutable bytes
and each relocation-aware proof witness under one read lease, and publishes only
a bounded mapped RX candidate. The original report remains intact. Existing
factory signatures, default policy and absent-file behavior are unchanged.

The additive context and program-factory overloads accept already-owned file
bytes. They do not acquire a game file or discover/register process mappings.
A path, hash, asserted bias or caller boolean cannot establish correspondence.
SCE executable flags, file-only loader metadata, existing TLS, unrelated imports,
modified BSS and stricter RELRO are covered by the owned host fixture.

Host verification passed 81 assertions through genuine C++ and Rust endpoints.
It checks private-copy/owner lifetime, exact snapshot identity, lease-safe
callbacks, mutation refusal and original success/ambiguity/error authority.
No fixture instruction or captured instruction was executed by this scanner test.

The SDK compiled seven affected/new C++ units and freshly composed 379 individual
inputs into 360 runtime units plus three bootstrap units, 15 fixed dependencies and
the retained activation object. The 117,254,296-byte AMD64 relocatable object has
SHA256 `cf93b8f5b528d0bc8307d76255b1958fbcb992e990f2633e78e8016f75ebfbe0`.
Its 197 native undefined symbols are unchanged, and all 18 Rust C exports remain.
The selected NameTypes conversion fallback, initializer retry, notification
cancellation, affinity and activation owners are preserved.

The compact receipts bind the full retained local receipts by hash. Verification
uses the retained pinned SDK, individual native inputs, host owned-memory object,
owned FDE control objects and prior host dependency inventory; those binary/tool
inputs are intentionally excluded from source publication. Generate the owned
ELF fixtures with `tests/make_fixture.py`, then use `verify_host.py` with a fresh
output name. `build_runtime.py` requires explicit final Rust and host receipt
paths and a fresh output directory. Frozen historical outputs are not replaced.

The Rust parser still has explicit bounded relocation/encoding limits. This
result asserts a file-derived candidate with validated mapped witnesses, not
live-wide uniqueness, engine identity, a callable Tick ABI or game-thread
readiness. An actual production live-image supplier is still absent. No PRX or
target action was performed. The separately proven standalone DLL diagnostic's
PS5 execution is not evidence that this UE integration ran on target.

Independent review found no material C++ source/host issue. Final native hash
closure is recorded in REVIEW.md. The only diagnostics are the
retained Rust naming warning and ten existing C++ header/source warnings listed
in the compact receipts.
