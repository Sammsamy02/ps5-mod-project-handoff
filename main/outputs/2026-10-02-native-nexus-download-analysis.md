# Native Nexus file download and archive analysis

The ordinary-SDK app now connects its existing game/mod/file selection interface to process-owned download and analysis jobs. A configured private account context injects the Nexus bearer internally; the provider-issued archive URL is transferred without account headers. The downloaded archive stays unchanged and is scanned through the real native archive implementation. Game paths and mod IDs do not select translation recipes.

The actual desktop-app owned TLS fixture passed 26 checks over 21 requests: PKCE login, five catalog routes across two game domains, file selection, queued job completion, unchanged real archive hash, idempotency and intent conflict, cookie/CSRF/Origin checks, session isolation, invalid-archive cleanup, free-account authorization refusal and clean shutdown. The real source was the retained 46,974-byte minimap ZIP with SHA-256 `cf3c353b4e8ab0d49214ceaeae5a8989cf58d1b2ce5758673a360d2e463df377`; an independent owned archive exercised multi-chunk transfer and another domain. Fake credentials and a local service were used. The production artifact was not altered by the fixture's private TLS socket shim.

The current host and PS5 app compositions compile and link from 64 identified project inputs. The host artifact contains 21 objects and 13,728 recorded include entries; the PS5 artifact contains 22 objects and 11,158 entries, with zero host headers. Current sources, objects and include bytes were verified again after the builds. This PS5 artifact has not executed on the console.

Additional focused checks passed: 65 job controls and 43 real archive controls with ASan/UBSan, the authenticated catalog component controls, 18 retained dependency controls, 47 shared builder/configuration/framing/asset tests, and 13 selection UI checks. Independent reviews found no concrete blocker in the auth, jobs, analyzer or integration changes. These controls establish the used local operations and their stated boundaries.

Archive testing found and fixed a real reader gap: libarchive accepted footerless ZIPs when complete local records survived. The caller now requires complete ordinary central-directory/footer structures. Ordinary ZIP LZMA is retained; actual ZIP64 forms are explicitly refused. Some footer-like ZIP comments can confuse the retained reader and are refused on inventory inconsistency. Parser CPU, internal allocation and blocking calls have cooperative limits.

Jobs are explicitly enabled by a verified archive profile and an existing app-owned 0700 scratch directory. Eight records live for one process, with 0600 exclusive generated archive leaves. The serial main loop attempts HTTP 202 before running the job; an admitted intent can continue if response transmission fails, and polling is unavailable during synchronous work. Files remain privately owned until shutdown. Cleanup failure retains ownership and fails shutdown instead of releasing borrowed auth/runtime dependencies.

This slice does not install mods, persist accounts/jobs, process a free-account NXM handoff, install prerequisites, port UE4SS or translate DLLs. Candidate PAK/IoStore/INI/Lua/DLL names supply no engine compatibility. Every public analysis keeps runtime and installation false. The full PS5-only manager goal remains active.
