# Compatibility implementation checkpoint

The project is implementing reusable compatibility components. The first test game can change; engine/format adapters must stay game independent. No game runtime mod has been demonstrated, and the complete PS5 Nexus sign-in, browse, download and install flow is unfinished. Broad support remains a research goal; the earlier proposed support table is not a list of demonstrated capabilities. The latest [Townfall trial](2026-10-01-townfall-mod-trial.md) records the unchanged Leon bundle staged with exact readback, awaiting its visible result. The [native PAK writer](2026-10-01-native-pak-writer.md) adds verified shared byte preparation, and the [IoStore reader](2026-10-01-native-iostore-reader.md) adds shared inspection of captured container descriptors.

Current priority is the unchanged real-mod in-game trial and shared automatic bundle intake. Library/UI work and unrelated app infrastructure remain paused. On October 1 the user confirmed the PS5 online; bounded read-only FTP checks succeeded. The user's latest selection is Silent Hill: Townfall and Skyrim as test targets. Townfall's metadata identifies PPSA33286, version 02.003.000; the user confirmed it reaches the title screen, and FTP exposes its running app0 mount. Skyrim's build and containers remain unverified. Detection and compatibility must use reusable byte/engine rules and automatic target discovery, without hand-prepared per-mod recipes or title-ID branches. The old Stellar Blade dump path is unavailable, and the inspected sandbox listing did not expose that game's mount.

The [current container report](2026-09-30-unreal-container-survey.md) records the captured archive/profile and original-asset evidence. Two concrete generic PAK compatibility fixes are committed: large unselected metadata no longer inherits the selected output cap, and uncompressed selections can use the existing 4 MiB ceiling. Current focused host checks pass 10,232 existing checks plus 21 large-None cases / 4,138 checks; both callers compile/link for PS5 without console execution. The latest offline path-hash probe matches all 4,544 captured pairs and all three generated pairs, with independent controls. Those are parser/tool results, not engine mounting, asset cooking or Nexus mod compatibility.

The new PAK decoder reads one caller-selected encoded record, including independently selected 32/64-bit fields and compressed-block geometry. It allocates no memory and returns owning scalar metadata with bounded caller-owned block storage. Codec names are metadata only. It does not locate a mod file, decompress an asset, extract anything or write to the game. [Detailed experiment](</WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/native-pak-entry-decoder-experiment-1.md>).

The new Lua adapter resolves opaque receiver/member identities through trusted provider callbacks and marshals one Int32 input/return in an owned little-endian frame. Ten host groups / 364 checks passed, including descriptor rejection, stale/foreign receivers, provider denial, instruction/time/memory abort recovery and cleanup. The matching native ELF linked but was not executed; its inspection diagnostics are retained. Fixture objects are not Unreal engine objects. [Detailed experiment](</WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/ue4ss-lua-binding-experiment-1.md>).

The latest loader-source comparison identifies a rule a shared file-override backend must preserve: [ME2's pinned lookup](https://github.com/soulsmods/ModEngine2/blob/4f701ccd0e2f6ddb106f17050dfd7fca036bb244/src/modengine/ext/mod_loader/archive_file_overrides.cpp#L59) selects the first existing configured root, while [me3's pinned mapping](https://github.com/garyttierney/me3/blob/989b522214e39c83d701f4182c4f0a86ad79a30a/crates/mod-host-assets/src/mapping.rs#L107) replaces earlier keys with later package entries. [ME2 limits multiple-mod support to nonconflicting files](https://github.com/soulsmods/ModEngine2/blob/4f701ccd0e2f6ddb106f17050dfd7fca036bb244/README.md#L67), so observed first-root behavior is not a supported merge contract. me3 [sorts before filtering disabled packages](https://github.com/garyttierney/me3/blob/989b522214e39c83d701f4182c4f0a86ad79a30a/crates/cli/src/db/profile.rs#L117) and [appends profile packages after CLI packages](https://github.com/garyttierney/me3/blob/989b522214e39c83d701f4182c4f0a86ad79a30a/crates/cli/src/commands/launch.rs#L263). These are source findings, not executed console results. The new [shared file-override selector](2026-10-01-file-override-selection.md) exposes both precedence policies without title-specific branches. It takes already-resolved package order; neither it nor the core planner imports those upstream loader rules or establishes a game hook.

The Nexus catalog previously hid every adult-marked record despite already reading the provider's account preference. It now permits those records only when the verified OAuth profile explicitly enables them, checks that preference again for the next operation and reuses the current operation's verified profile for download authorization. Unknown or disabled preferences, unknown content flags, unpublished and unavailable records remain hidden. Four regression tests were observed failing before implementation; all 12 client tests and 8 download tests then passed. These are offline synthetic provider tests, not live account access or console downloads. An initial temp-directory test failure was environmental; a worker also observed no-space errors. Root removed the ignored redundant compiler archive after verifying its pinned hash, preserving extracted tools and experiment evidence.

The corrected PAK metadata pipeline feeds the encoded-entry decoder from the exact primary bytes whose SHA1 the reader verified, without rereading that span. Independent archives revealed that both secondary presence fields require four bytes; earlier one-byte synthetic fixtures and sources are retained as historical evidence. The smaller payload API remains available. The new [candidate API](2026-09-30-pak-candidate-integrity.md) selects a directory row and additionally validates both secondary hashes, the complete reference graph, physical-header reconciliation and selected stored SHA1 before publishing bytes. All eight actual outputs match retained originals; empty/two-block and late-failure controls pass.

The [native Nexus metadata port](2026-09-30-native-nexus-metadata-port.md) passes 21 metadata/routing tests and 2 C-interface tests and links for PS5 with target-only headers. It constructs the six fixed-origin metadata endpoints for arbitrary validated game domains. Its executable remains unexecuted, and the decoder is not yet connected to native HTTPS or the UI.

The fresh curl8.18/Mbed TLS transport experiment reached an actual startup crash when its entropy source deliberately refused a request after PSA initialization. It remains ineligible for console promotion. Curl's [upstream fix](https://github.com/curl/curl/pull/21441) removes the failing null-handle diagnostic call. The newer-release agent task stopped after an automated cybersecurity risk-filter failure; its preparation is preserved and its upgrade remains unverified. That rejected task was not retried. Independent archive development continues.

The bounded directory parser, Zlib codec and candidate-integrity components are included in the read-only PAK library. Their composed operation uses one aggregate read budget and complete private-result publication. The promoted source closure passes focused host checks and PS5 compile/link; target executables remain unexecuted. The next console experiment requires the selected playable game's profile/original assets and an observable engine mount plus asset origin. A native VM or archive byte comparison still does not establish mod compatibility. Game/system writers and payload-store promotion retain the strict review boundary in the [experiment process](ps5-mod-bridge/EXPERIMENTS.md).

The [controlled HTTPS checkpoint](2026-09-30-native-https-console-checkpoint.md), [PAK reader results](2026-09-30-pak-reader-results.md) and [Lua dependency results](2026-09-30-ue4ss-lua-portability.md) retain earlier observations. October 1 work adds the shared selector, prepared lookup, host scale checks, a strict PS5 pure-selector link and the [generic Bethesda header inspector](2026-10-01-bethesda-header-inspection.md). A private linker profile corrects the pure selector's `PT_DYNAMIC` warning while preserving code/imports and the canonical SDK; this remains static evidence. Subsequent ordinary read-only FTP captures located Townfall's manifest-listed containers, an unencrypted-index PAK v11 footer and a global IoStore v8 header; the PAK primary index matches its declared digest. The canonical reader validated all 4,699 entries and extracted the captured SaveData.png, PS5Engine.ini and DefaultEngine.ini with exact byte/SHA256 matches and physical-header SHA1 checks. Pinned repak packed those originals into a separate 69,724-byte v11/None PAK; repak roundtrip and the canonical reader independently recovered all three originals. These host checks and the user's confirmed title-screen baseline do not establish extra-container mounting or game acceptance. No new payload, game write, runtime hook, account operation or Nexus download was performed at this checkpoint.
