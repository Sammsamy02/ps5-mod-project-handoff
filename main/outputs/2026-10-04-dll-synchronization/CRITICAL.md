Microsoft declares its AMD64 representation as a pointer, two 32-bit LONGs, two HANDLEs and a pointer-sized spin field under pack 8 ([winnt.h](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/winnt.h)). This service reserves that storage but makes no promises about internal Windows field values. Initialize touches only those 40 bytes; native pthread state lives in preallocated private sidecars keyed by the object's stationary address.

Native pthread ownership identifies the holder; successful recursive entries increment recursion and matching leaves release it. Contending Enter performs the configured spin/recheck loop, then waits on a native condition variable. TryEnter does not wait for critical-section ownership. All operations briefly serialize sidecar metadata. SetSpin returns the previous count; a genuine native sysconf processor query enforces the Windows single-processor zero-spin rule. Provider failure refuses owner creation rather than inventing a processor count.

The owner pins the existing Windows thread domain. Separate module sessions follow EMPTY-before-load / EMPTY-after-unload lifetime rules; every Win64 caller must already be admitted to the domain. Close refuses service pins, holders and active/spinning/waiting calls. Quiescent teardown may retire idle sidecars without touching their saved Windows addresses, permitting cleanup after a module's data has retired. Normal Windows object rules still require no move/copy, no modification, delete before reuse and valid storage throughout use. Exiting while holding, deleting while held/waited, wrong-thread Leave, cancellation or escaping exceptions/longjmp are unsupported caller violations.

APIs without a failure channel fail-stop on unsupported invalid/native failure; SEH/deadlock exceptions are not fabricated.
