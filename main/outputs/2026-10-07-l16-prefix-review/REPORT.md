# l16 constructor-prefix review

The captured l16 launch reached a fresh 32-byte constructor-prefix copyin attempt at `0x63d590`, and the kernel returned the signed Sony error `0xffffffff8002000e`, normalized to EFAULT (14). The runtime correctly refused before calling or binding the native FName constructor. This establishes a copyin refusal for this attempted source range. It does not establish the kernel's underlying reason, the live constructor bytes, a wrong pin, or a wrong FName adapter ABI.

Review scope: local captured evidence and source only. No console or network contact, no executable/config/mod changes, and no probe or engine-call changes. All new artifacts are under this directory. `LOCAL-AUDIT.json` records input existence, hashes, source-edition checks, ELF/profile checks and selected captured events. No missing input was replaced with another run's evidence.

The exact session is `outputs/2026-10-07-l16-full-build/console-test-20261007T183202Z-2318a17f`, harvest `out-1791398546-78152`, PID 106. Local deployment and postlaunch readbacks exist and hash to `34e43b25cb99333e472146ebd518a0d9d8418e8fe762f90084cd88c0c190c121`; the saved receipts identify decrypt-off readback and SELF magic `4f153d1d`. `SESSION.json` preserves the user's report that Townfall was healthy but no menu appeared. The postlaunch process capture lists PID 106 as `eboot.bin`. These are one-launch observations, not repeated validation or a proof of all future game stability.

The source explains the refusal without an adapter call. `UnrealInitializer.cpp:1029–1048` computes `base + ctor.label`, checks static CodeCallOnly classification, calls `fnameabi::signature`, and calls `fnameabi::invoke` only after a successful signature. `NativeFNameChecks.hpp:11–34` validates the range/deadline/fault ledger, obtains a VirtualQuery result, checks full committed executable coverage when that result is available, and always demands a fresh probe. Result 0 returns `constructor prefix copyin fault`. It does not accept matching cached or disk bytes after an unsuccessful fresh probe.

In `runtime_start_bridge_r14_diag_spanpub.cpp:1116–1205`, the probe consumes one preopened sink, passes the address to `sceKernelWrite`, normalizes errors before count arithmetic, and records the entire attempted range on EFAULT. The fault ledger and capture accessor veto overlapping faults. `CopyinSink.hpp:9–19` recognizes both sign-extended and zero-extended Sony error shapes; the captured value is neither a huge positive byte count nor an ambiguous short write. The write failure skips positional readback and returns class 0. This source trace proves the failure precedes native invocation; it does not determine why the kernel refused the source.

Static address and profile consistency were independently checked against the exact saved ELF, `.superpowers/native-observations/townfall-static-executable-2026-10-02/decrypted-eboot.bin`:

- Its current hash is `3b6cfad47dd17fea17d429bce80ae374d1fd2ef8894672cce63f5a26853622fc`, matching the recorded image identity and generated profile identity.
- SeedTable's constructor label is linked vaddr `0x23d590`. LOAD0 starts at linked vaddr zero with file offset `0x4000`, so the prefix's file offset is `0x241590`. At observed base `0x400000`, runtime address is exactly `0x63d590`. ELF file offsets, linked vaddrs and runtime addresses are distinct; no double slide is demonstrated here.
- The 32 saved bytes equal FNameAbiProfile's prefix. The generated ImageLoadProfile PT_LOAD tuples equal the saved ELF program headers. LOAD0's ELF flags are 1 (PF_X only), and the label lies within it. ELF PF_X=1 and VM PROT_EXEC=4 are different flag conventions; the signature's VQ test uses the latter convention.
- The reviewed l16 source/header hashes agree with EDITIONS-l16 pins; the staged bridge source is byte-identical to the l16 source. Static classification at `SeedValidation.hpp:667–683` maps this address to `CodeCallOnly`. That classifier is profile arithmetic, not a new observation of live permission bits or byte identity.

The static X-only LOAD0 expectation is consistent with EFAULT, so execute-only or source-class copyin policy is a plausible explanation. It remains a hypothesis. The existing source itself documents that copyin refusal does not imply unmapped or CPU-unreadable: protected and non-allowlisted source classes can refuse identically. A static file/profile match cannot distinguish these cases or prove the loaded code has those bytes.

The constructor gate already obtains permission evidence through `L13AdmissionOps::query` (`UnrealInitializer.cpp:823–841`). It logs unavailable queries but returns a successful region silently. Although `log_region` exists for pool checks, `fnameabi::signature` does not call it. This launch has no constructor VQ region/protection record. Reaching the probe means the signature did not reject its mapping gate: an available reply would have passed complete committed executable coverage; an unavailable reply is also allowed to reach the fresh copyin attempt. The absence of an unavailable log is consistent with VQ success, but exact live protection, extent and flags were not captured and must not be invented.

An identity-gated original-executable profile is useful for selecting and rejecting stale game/build facts. The staged `worker-shadow-integrate/shadow_arm.hpp:335–389` requires same-capture nonzero base, agreement with the base pin, exact saved-image SHA, first linked LOAD vaddr zero and matching image extent; it also cross-checks required seed labels. Those operations corroborate file identity and address derivation. They do not prove live text bytes or grant CPU text-read permission. The current l16 required-seed path has no per-launch whole-image SHA gate before this signature; its compiled hash strings alone are not executed identity checks. Its shadow fallback explicitly declines to provide live byte proof. Routing cached/original-image bytes through the existing signature after this recorded EFAULT would violate the gate's hard-fault/freshness contract. This review proposes no such fallback or engine call.

**One proposal, report only:** expose the constructor gate's already-issued VirtualQuery result and returned region/protection/flags, together with the static image/profile SHA, linked label, expected base, actually observed base and computed runtime address. Mark static identity as expected/file evidence unless a separate check actually ran. Place the bounded diagnostic at the existing query result seam, before the existing fresh probe, with no second query, new target read, protection change or native call. Preserve query/probe order, fault-ledger veto, shared deadline and all current refusal outcomes. This corrects the demonstrated diagnostic omission. It is not a functional menu fix and is not guaranteed to make copyin succeed.

Risks: logging consumes some of the shared scheduling budget; unchecked string formatting could reproduce the existing mixed-width diagnostic text; and an unlabeled static SHA could be misread as live identity proof. Use numeric fields and bounded ASCII or the existing diagnostic word encoding, preserve cancellation/deadline seams, and distinguish unavailable/expected/observed facts explicitly. No implementation was performed.

Proposed local verification before any separate console decision: drive the same signature gate with available full executable mappings both with and without READ, unavailable queries, malformed/partial/uncommitted mappings, deadline expiry, preexisting faults, fresh EFAULT and fresh mismatch/success. Assert query/probe/native-call counts and identical admission decisions; EFAULT must remain terminal with zero native calls and no cached/disk fallback. Check the diagnostic encodes the returned fields rather than synthesized ones, distinguish PF_X from PROT_EXEC, and assert the linked-vaddr/base calculation and overflow/mismatch refusals. Re-run the existing FName and bridge host suites and the pinned target compile if the diagnostic is later implemented. These are proposed tests, not executed tests of a change. Any live protection result would require separately authorized new evidence; this review used none.
