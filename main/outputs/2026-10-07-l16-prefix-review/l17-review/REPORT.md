# Independent l17 lifecycle review

Disposition: no concrete ownership, race or cleanup integration mistake found in the reviewed lifecycle slice under its documented loader contract. This is a bounded local source review, not console validation, a full composition review or a guarantee that the menu will open.

Reviewed the l16-to-l17 `reports/SOURCE.diff`, the four changed production units (`runtime_start_bridge_r14_diag_spanpub.cpp`, `CopyinStartup.hpp`, `UnrealInitializer.cpp`, `runtime_owner.cpp`), the retained owner interface, and lifecycle/initializer test source and recorded receipts under `outputs/2026-10-07-l17-local-lifecycle`. No source/test edits, test reruns, network or console contact occurred. The parent owns the fresh focused test rerun. Input hashes and end-of-review preservation checks are in this directory's receipts.

The supported ownership ordering is coherent:

- `RuntimeOwner::initialize` publishes its actual `std::this_thread::get_id()` through the bridge enter hook before calling the backend. The bridge gate stores the thread ID itself; its diagnostic hash is only a label. A local scope leaves on backend return and all caught exception paths. `prepare` runs during serialized startup before this worker starts.
- The synchronized owner gate is consulted before foreign probe accesses to nonce, descriptor bank, capture ring, fault ledger or telemetry. Foreign capture clears the caller's output fields and returns no capture; foreign fault query returns a fail-closed value without reading the ledger. Foreign completion/leave does not release resources. Explicit Control D now guards its probe/telemetry block as well.
- An available owner result does not lock the entire operation. That is sound here because only the one initializer may access this state; documented loader startup/stop serialization and the join-before-fallback-release ordering exclude a concurrent prepare or control-thread release. This review does not extend that contract to unsynchronized loader calls or self-destruction on the initializer.
- Startup successfully opens each exclusive generated sink before unlinking that exact owned pathname. Unlink denial logs operation 5 and the error, retains both file and descriptor, and schedules no delayed unlink/reopen. Partial startup acquisition failures release the already owned bank; startup timeout remains bounded as a scheduling deadline.
- Both delayed-probe consumption and bulk release exchange each owned fd to `-1` before the close call. The probe's local completion guard consumes its obligation before release, covers exception unwinding, and is explicitly completed before success publication. A close error cannot leave the numeric fd in the bank or trigger a second close on destruction, completion, leave or stop.
- `consume_required_slot_seeds` installs cleanup at function entry, so a Phase1/2 refusal or an admission/signature/native-boundary/roundtrip failure unwinds through retirement. On success, explicit completion occurs after native output verification and binding and before Phase5 or later initialization. Captures and fault evidence are retained while the initializer continues. The outer initializer owner scope is an idempotent fallback for paths that never enter seed consumption.
- The existing runtime stop path joins/stops the selected owner before fallback descriptor release. On an exception, resetting the selected owner invokes its join-or-terminate destructor before release. This establishes initializer quiescence for the supported stop path; the unchanged interface separately requires loader/engine-hook quiescence for unload.

The l16 failure contract is preserved. NativeFNameChecks, the FName adapter/profile and CopyinSink error normalizer are unchanged. Fresh EFAULT still records an overlapping fault, returns class 0, and makes the signature refuse before the native constructor. Cleanup neither clears the fault ledger nor introduces a cached/disk fallback. After retirement, another initializer probe sees no bank; it cannot recycle a consumed handle. This slice adds no native engine call or permission policy.

The existing green receipt records 44 passing cases each for plain, fatal ASan/UBSan and TSan.

The owner tests exercise the real worker and join code with a fake backend. These tests establish local sequencing and ownership behavior, not Sony unlink/close semantics, game constructor execution, full runtime hook quiescence or a complete built PRX.
