# Native acquisition plans to automatic downloads

The authenticated resident app can admit a mod and its bounded internal Nexus
prerequisites as one acquisition. It recomputes the plan internally and queues
all selected original sources together. The serial host also advances queued
work while its listener is idle, so a group progresses without repeated browser
requests. This is automatic source acquisition and private byte preparation;
runtime compatibility and installation remain unresolved.

## Behavior

POST `/api/acquisitions` accepts exactly the four acquisition-plan fields plus
an `idempotency_key`, within the existing 4096-byte frame and cookie/CSRF/Origin
gates. Roots and explicit choices are canonicalized structurally. The additive
jobs API preserves the existing submit/result layouts and source/generation
operations. Client plans, URLs, credentials and entitlement claims are refused.

One jobs operation calls the actual auth-owned planner through the existing
separate auth context. It admits only a complete, ready same-game closure with
one to eight selected source identities. Unresolved plans return 409
`acquisition_unresolved`; malformed provider or transfer failures queue nothing.
The configured resolver budget spans discovery, private staging and admission.

Every fresh child ID, source record and compact group receipt is staged before
publication. Global remaining capacity must fit the whole group. Checked entropy
failures/collisions, short output, expired session, invalid storage or the final
deadline leave no new records or receipt. Large records use heap staging. Final
gates precede a bounded non-failing POD commit; no archive is transferred during
admission.

A same-cookie canonical replay returns the original ordered child IDs without
rediscovery or entropy, even at full capacity. Changed intent conflicts. Group
keys have a separate namespace; internal child keys cannot replay a public
single-job submission. The response's `accepted` state describes admission.
Current child progress uses the existing jobs routes. Compatibility and version
satisfaction remain unresolved, download/runtime/installation authority false,
and acquisition order explicitly does not establish game load order.

Each worker independently checks live account entitlement, visibility and link
authorization before the credential-free archive transfer and unchanged generic
analysis. Metadata readiness cannot authorize free-account downloads. The host
processes one unit after a response or an idle listener wait, returning to
listener polling between units. It keeps one serial curl/PSA owner; there is no
concurrent polling during a transfer or hard syscall cancellation guarantee.

The existing explicit IoStore generation operation still requires every bound,
successful unchanged source in the configured profile. No successful subset is
implicitly chosen, and this acquisition endpoint does not auto-generate or
install a mixed bundle.

## Remaining full-goal work

The next free-account seam is a session-owned job-resume operation that accepts
a transient file-specific website grant through the existing typed resolver.
The pinned official [Nexus client](https://github.com/Nexus-Mods/node-nexus-api/blob/da9b8eda8a3f381f04d87c7290595066ccbdbc5d/src/Nexus.ts)
documents website-issued free-account keys and the fixed link route. Official
[Vortex source](https://github.com/Nexus-Mods/Vortex/blob/032157db2284db108db38798e82b8b48bb13ac4a/src/renderer/src/extensions/nexus_integration/NXMUrl.ts)
establishes mod/file URI identity and key/expiry/user fields. Strict bounded
native parsing is our admission policy; collections, OAuth, premium/view URI
variants and arbitrary URLs cannot substitute for a bound file grant. Native
resume, PS5 browser interception and production OAuth registration remain
unverified.

Persistent installation, target discovery, real Unreal reflection/game-thread
bindings, UE4SS Lua gameplay, DLL gameplay and the final PS5 account/store UI
remain unfinished. The full goal stays active.

This phase uses owned local providers and saved original captures. It does not
contact the console or production account, write game/system files, retry stopped
actions, or change paused title/UI work. Compile and private preparation evidence
does not establish an in-game result.
