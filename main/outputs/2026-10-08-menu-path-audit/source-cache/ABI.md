## Confirmed constructor mismatch

The pinned game constructor at linked `0x23d590` takes **RDI = writable 8-byte output**, **RSI = UTF-16 input**, and **EDX = mode**. Its word loads and `+2` stride establish UTF-16 width; `0x23d5f0` stores `RAX` through `RBX`, which was copied from RDI. The selected `Function<FName(const CharType*, EFindName)>` caller supplies **RDI = string, ESI = mode** and expects the 8-byte value in **RAX**. It never supplies output storage. Saved [game disassembly](/WORKSPACE/.codex/worktrees/translation-core/what/outputs/2026-10-07-l14-full-build/console-test-20261007T161545Z-abde74a3/constructor-crash-disassembly.txt) and [caller disassembly](/WORKSPACE/.codex/worktrees/translation-core/what/outputs/2026-10-07-l14-full-build/console-test-20261007T161545Z-abde74a3/constructor-callchain-disassembly.txt) establish that mismatch for game fixture SHA-256 `3b6cfad47dd17fea17d429bce80ae374d1fd2ef8894672cce63f5a26853622fc`. Keep the retained Function API and adapt the native boundary with output storage and explicit `char16_t` input.

The pinned target reports `__SIZEOF_WCHAR_T__=2`, `__WCHAR_WIDTH__=16`, `STR(str)=L##str`, and no `FORCE_U16`/`__linux__` macro. [Measured macros](/WORKSPACE/.codex/worktrees/translation-core/what/outputs/2026-10-07-l15-fname-adapter/audit/engine-calls/pinned-target-width-macros.txt) and successful probe assertions prove `sizeof(CharType)==sizeof(TCHAR)==sizeof(wchar_t)==sizeof(char16_t)==2`; ProsperoPlatform.hpp:12–13 and Platform.hpp:1185 enforce the same widths. There are **181 L/STR literal boundary expressions** and **97030 L/STR source/header lines** in the selected project scope, The 181 boundary expressions comprise 131 FName literal expressions (including macro definitions) and 50 local StaticFindObject expressions. The large all-literal list includes generated vtable/layout lookup keys, which are not game string arguments; it is stored in ALL-L-STR-LITERAL-LINES.json. The remaining FName literal expressions use STR. **No active 4-byte character-pointer leak was confirmed.** Existing L/STR expressions are width-correct on this target but do not satisfy an explicit `char16_t`/`u` boundary API policy by themselves. Adapt each native boundary without globally changing FORCE_U16: retained wchar_t/CharType symbols must retain their compiled identity.

## Compiled plain-string copy bug and reachability

The byte-count bug is in the active selected [NameTypes.cpp:204](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-dependency-spike/native-coherent-runtime-1/source/port/unreal/src/NameTypes.cpp:204), not an unselected copy. The selected object and final L14 runtime both define `FName::GetPlainNameString(wchar_t (&)[1024])`. Its [compiled body](/WORKSPACE/.codex/worktrees/translation-core/what/outputs/2026-10-07-l15-fname-adapter/audit/engine-calls/GetPlainNameString-active-body-disassembly.txt) executes `shl RDX,3` at +0x70 before memcpy: eight bytes per character, while TCHAR/wchar_t elements are two bytes. This can overread the source and overrun the 2048-byte destination for long names.

The 4,667-file selected graph contains only its [declaration](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-dependency-spike/native-coherent-runtime-1/source/port/unreal/include/Unreal/NameTypes.hpp:364) and definition; no selected caller or address use exists, and LuaFName exposes no such method. [Runtime relocation evidence](/WORKSPACE/.codex/worktrees/translation-core/what/outputs/2026-10-07-l15-fname-adapter/audit/engine-calls/GetPlainNameString-runtime-relocation-refs.json) has only its .eh_frame self reference, with no caller relocation. Treat this as a **separate follow-up, not a hold on l15 constructor-adapter candidacy** in the current selected graph. The compiled symbol remains unsafe if a future external caller invokes it.

## Remaining risks

- **Other game signatures are unvalidated**: Compiler lowering proves caller expectations, not target ABI. Slot/profile signatures and real parameter layouts must agree before treating any family as game-ABI validated. This audit newly validates no game target other than the locally saved constructor evidence.
- **FName trivialness and nontrivial return drift**: Selected FName is size8 and trivially copyable/destructible. Four compiled entries return FName in RAX (constructor wrapper, FProperty::GetID, UObject::GetExporterName, UStruct::FindPropertyNameFromGuid). Introducing nontrivial copy/move/destruction would change these to hidden-result/invisible-reference conventions and also affect by-value FName parameters and aggregate FPrimaryAssetId/FGuid pathways. Size alone is not enough to establish ABI.
- **Placeholder structured-archive/delegate-sensitive declarations**: UObject::FStructuredArchive::FRecord and FProperty::FStructuredArchive::FSlot are empty enums (lowered i32); FPropertyTag is void*. The game uses must be confirmed before invoking these wrappers. FScriptDelegate/FMulticastScriptDelegate and FURL value parameters lower as invisible-reference pointers due to selected nontrivial types; matching game trivialness is unconfirmed.
- **Explicit UTF-16 boundary form still required**: Current pinned target is width-correct: wchar_t=2, CharType=wchar_t, TCHAR=2, STR=L. This corrects a generic host wchar_t=4 assumption. Existing L/STR boundary expressions remain inventoried; literal width correctness does not make wchar_t* an explicit char16_t* API. Use per-boundary char16_t/u adaptation; do not globally FORCE_U16 because retained compiled symbol/API identities would drift.
- **FName plain-string byte count bug outside direct-call ABI**: GetPlainNameString copies String.size()*sizeof(File::StringType::size_type) (8-byte size_type) into a TCHAR buffer (2-byte element) rather than character bytes. This is a separate existing memory-copy risk, not evidence of a 4-byte pointer crossing.

FName requires special care: the selected type is **trivially copyable/destructible, size 8**. It has value/string constructors but no user-defined copy/move constructor or destructor. Its four direct return entries therefore lower to `i64` in RAX. A future nontrivial FName type would change return/argument handling; size assertions alone would miss that. FName-containing FPrimaryAssetId and the by-value FName sites are included in the per-call table.

The probe compile confirms caller lowering only. It ran no game code, linked no runtime, and establishes no console pass.
