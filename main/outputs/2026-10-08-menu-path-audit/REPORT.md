## Concrete findings and minimum next work

1. **P1: Frame identity and fallback dispatch must be repaired together.** Both Code-8 reads occur before the game-thread callback guard. A null Code can fault, an untrusted prefix can fault or select arbitrary UFunction memory, and the unknown fallback performs unchecked Func or ExecuteUbergraph dispatch. The original expression also subtracts an unsigned sizeof operand. No safe generic fallback is independently captured for an unidentified frame. A repair needs a proved supported hook-entry contract or an independently saved original handler; unsupported installation must refuse before replacing Func. The local guard candidate is a diagnostic experiment only and must not be integrated.
2. **P1: First-carrier game-thread authentication remains a prerequisite.** The selected publisher accepts the first caller and its later raw gate recognizes that same identity. Source comments assert event-carrier game-thread semantics, but the ranked carriers are not a retained measured C4 calibration. Require evidence for chosen carrier entry/thread stability before arming/publishing; do not relabel accepted callback identity as engine-thread proof. The native-frame worker's Invoke evidence is useful for frame fields, not a complete carrier-rate/thread measurement.
3. **P1: Serialize carrier-map mutation and callback use.** The wrapper uses a shared unordered map and callback maps while lazy carrier registration mutates them. The event-carrier mutex serializes installers, but the shared wrapper does not acquire it. Thus its scope does not establish map safety against concurrent game callbacks. Define one installation/removal/dispatch synchronization and lifetime rule; cover simultaneous registration/dispatch and restoration without holding an engine callback across an unsafe wait. This is a source concurrency risk, not a reproduced console crash.
4. **P1/P2: Borrow/retry/lifetime is independent of queue correctness.** Real PS5PadNative's detached one-shot helper may remain Running or Done-negative indefinitely. PS5PadSource's bounded poll retry does not restart that helper. Root owns a separate pad audit; source and test roles were sent there. Add actual-helper SDK seam tests and explicit terminal/recovery reporting, preserving borrowed-handle ownership and quiescence.
5. **P2: Add observable queue terminal states.** Keep current marshal-first queue retention. Make waiting-for-carrier, armed, first accepted dispatch, failed/stale carrier and cancellation outcomes explicit and bounded. Decide how repeated F7 closures before first dispatch should behave; a log at enqueue alone cannot prove completion. The startup started flag should also reflect main-script execution outcome.
6. **Native UMG boundary remains the next menu acceptance gate.** Use the unchanged script with real production reflection/construct machinery in a bounded fake-engine host model to assert the complete requested tree, mandatory failure cleanup, exact viewport arguments and optional pcall behavior. Separately require native reflected signatures/payload/ownership evidence and a real observed menu; host creation success cannot supply those claims.

Useful missing regression tests are deliberately narrow: actual wrapper→actual marshal callback→unchanged F7 script integration using explicit fake engine identities; actual PS5PadNative delay/CAS/negative/hung-helper/borrowed-handle/unload controls; actual property argument marshalling and full original widget graph with failure injection at each mandatory boundary; and real hook-map registration/dispatch/removal concurrency. Avoid a large mock that simply returns success for every reflected method, or a second layout checker that mirrors the profile generator.
