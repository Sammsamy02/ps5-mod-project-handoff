# Isolated per-registration thunk design (not implemented or admitted)

The selected shared wrapper cannot recover a saved original from an unidentified frame without trusting Code-8 or guessing another function. A bounded array of source-compiled ordinary function-pointer thunks can carry the registration identity without inspecting frame identity. Native Func stores one8-byte SysV function pointer; Context/FFrame/result are passed unchanged. Root's native-frame audit independently distinguishes this ordinary pointer from a16-byte C++ member pointer. This design uses no dynamic executable allocation, detour, game text read/write, or per-game literal.

Each `Thunk<Index>(Context, Frame, Result)` calls a generic dispatcher with its compile-time index. The slot owns immutable UFunction identity and retained original pointer. Before Func changes, allocation must succeed, original must be nonnull and distinct from our thunks, callback storage must exist, and the active map entry must be committed. Capacity exhaustion refuses registration before Func mutation. A single generic bound belongs to helper configuration, not a title-specific native layout. Final capacity/budget is undecided and must be checked against the real composition rather than chosen from a host fixture.

Dispatch identifies its original through the slot, never `CurrentNativeFunction` or Code-8. With the selected GNatives-null configuration it forwards the exact Context, frame and result to that original, preserving pre/original/post ordering. A stale/retired thunk forwards its retained original without callbacks. Unknown slot state is an installation/publication bug, so it must be prevented by committing storage before pointer publication; do not install a thunk whose fallback original is unavailable. A runtime refusal that suppresses original game execution is not an acceptable normal path.

Retirement has an ABA hazard: restoring Func does not prevent an engine caller that already loaded a thunk from calling it later. Therefore slots are **not reused** until an independently proved engine quiescence contract exists. Retain original and callback-data ownership for module lifetime. The current map value type/return API can potentially stay unchanged by moving its C++17 extracted map node into slot retirement storage; extracting preserves references, whereas today's erase invalidates them. This must be verified with the actual SDK STL and all direct consumers of GetHookedFunctionsMap. Do not silently alter public struct or container layout.

Unregister removes callback admission and restores Func only when it still points to this slot's thunk; it must not overwrite an intervening third-party replacement. Active and nested dispatch must hold a stable lifetime token. Callback snapshots or a safe deferred-erasure protocol need explicit ordering so reentrant unregister cannot destroy a callback while it is being invoked. No registry lock is held while calling an original or user callback. A bool bIsMidExecution alone is not a complete nested-dispatch counter or lifetime token. Restoration does not establish module-unload safety: unload requires all pointers restored and an externally justified quiescence barrier.

Use one synchronization rule for registration, registry lookup, retirement and callback mutation. Event-carrier installation's mutex currently excludes only other installers, not the shared wrapper. Concurrent registration may rehash the unordered map while dispatch reads it. Lock acquisition and callback execution must not form a cycle with the Lua actions mutex. A future implementation should inspect all direct map consumers and separately test concurrent installation/dispatch, callback reentrancy and retirement.

Before any selected-source integration, tests must establish: null/foreign frame identities still execute the correct independently retained original; two registered functions cannot be confused; original argument identity/order is unchanged; a loaded retired thunk forwards original without callbacks; re-registration cannot redirect an older loaded thunk; unregister from a callback does not free live storage; capacity failure leaves Func/map unchanged; an intervening replacement is preserved; no slot is reused prematurely; and missing/recursive original installation refuses before mutation. Compile genuine target pointer/call controls and inspect symbols/import delta. The existing GNatives clone branch must remain disabled pending its separate native construction contract; do not claim this solves a blanket FFrame or GNatives ABI.

The adjacent RED controls execute the actual original full wrapper, callback implementation, GetFunctionHookData/RegisterPre/PostHook and UnregisterAllHooks with explicit fake engine storage. They demonstrate missing registration identity and retirement ownership. No thunk candidate implementation is present, and these failures are not a claim about observed console behavior.
