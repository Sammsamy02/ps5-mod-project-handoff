# Step 3 legacy browser expectation changes

Scope: test-only adaptation to the plain-language presentation in web/app.js and web/index.html. No production source or installer-controller test edits were made by the navigation worker.

- Renamed download actions to “Download and check”, unavailable action to “Downloads not available yet”, queued toast to “Download requested.”, file detail action to “More info about…”, and unsafe mod message to “This mod cannot be opened here yet”.
- Updated target heading to “Your console game”, refresh action to “Refresh games”, direct-lookup labels to “Nexus mod link” / “Game name from the Nexus link” / “Mod number from the Nexus link”, and target status/summary messages to their player-facing equivalents.
- Target selection still asserts the exact opaque snapshot/title references, current-snapshot confirmation, request bodies, CSRF protection, refresh count, stale clearing and no automatic resubmission. Visible summaries now identify the selected game by display name. Title IDs, exact build hashes and fingerprint provenance are asserted absent from normal title rows and present behind the matching title’s More info.
- Paging still requires all 25 Unicode titles to appear only after all pages and current confirmation, retains transport/cursor/resource/boundary/malformed invariants, and now verifies the title number, exact hash and original large fingerprint byte length behind More info. The existing Unicode fixture was kept.
- Valid analysis reports still prove unverified versus unsupported compatibility, exact desktop/PS5 execution scope, backend/unknown-build/Windows-runtime explanations, read-only archive inventory and unsupported empty-scope installation authority. Technical assertions moved into the corresponding job’s More info; normal jobs instead assert the plain untested/unsupported explanation. Unrecognized reports must remain absent from both ordinary UI and More info, with no manufactured positive compatibility.
- Service records preserve distinct Downloaded / Prepared / Installed states, confirmed legacy records, unsupported-contract refusal before requesting records, malformed-state rejection and stale clearing. Valid runtime reports now assert the friendly label and explicit unverified-current-game status normally, and the original runtime state, PID, installed hash and escaped raw detail behind More info. Preparation blockers remain escaped text behind More info.
- Saved downloads now allow exactly one “More info” control per saved record and no links or mutation controls. The archive hash is hidden ordinarily and available in details. Opening details and polling must still issue zero POSTs and preserve controller focus; retention still requires explicit valid evidence.
- Queue-capacity copy now says to finish current downloads, rather than using host/job terminology. The remaining basket entry/request key, exact request order and no automatic retries remain asserted; opening the diagnostic must not submit anything. The rejection’s original job_limit code is checked behind More info; no restart/guaranteed-recovery claim is allowed.
- Narrow selector changes avoid ambiguity introduced by the new “Continue game” control and the separate “Try again” action. Game-card selectors still identify the exact intended game; error-message checks target the paragraph rather than also matching its retry button. Diagnostic-label matching ignores CSS text-transform case.
- The two legacy account-action setup sequences now use real d-pad graph navigation rather than assuming a continuously held Right reaches and stays on Sign in / Disconnect. Exact focused IDs, protected request counts and official authorization URL checks remain unchanged. No synthetic focus was introduced for these controller steps.
- Two added service-record poll cases use the actual five-second poll with the browser clock: identical records preserve the exact focused More info node; changed records preserve record identity, modal focus and restoration to the replacement trigger after Escape. Reopening must show the latest record generation, and all reads remain free of POSTs/external traffic. These are native keyboard/focus regressions, not claimed as gamepad-only tests.
- tests/ui_controller_tests.cjs and tests/ui_keyboard_tests.cjs accept optional UI_EVIDENCE_ROOT, resolved to an absolute directory. Default historical evidence paths are unchanged; final Step 3 runs will override them to preserve committed Step 1 / 1b screenshots and receipts.
