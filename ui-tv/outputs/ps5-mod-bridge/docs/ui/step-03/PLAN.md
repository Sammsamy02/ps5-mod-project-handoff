# Step 3 — plain words, recovery and remembered browsing

Keep the current app and its public contracts. Apply only to the isolated UI branch.

1. Give each existing known error a plain explanation and next action. A user-initiated retry repeats the failed read; download admission retains the existing request identity. Unknown failures expose only bounded diagnostic code/status, not arbitrary provider bodies. Keep these controls reachable by d-pad.
2. Distinguish pending, empty and failed catalog views. Use skeletons and actual loading state; preserve stale-request rejection and focus ownership. Keep retained downloads and confirmed records, moving technical identifiers/hashes/paths to More info.
3. Persist only bounded public last-game/filter/sort preferences. Session navigation keeps its existing behavior; a new page offers Continue rather than silently authorizing a game target. Storage failures must not stop browsing.
4. Add a readable mod overview using existing text fields, an official mod-page link, and honest own-account/free-download wording. Keep local filtering explicitly scoped to loaded latest mods. Images, full server search, cache reuse and reload-safe NXM continuation are integration dependencies; do not fabricate them.
5. Test at 1080p/4K with controller-only user actions, rerun retained-feature regressions, independently review the diff, inspect each updated screen's screenshot, then commit and hand over.

No console access or original Claude checkout edits. No game/mod writes, installer API additions, credentials in preferences, or real-to-mock fallback.
