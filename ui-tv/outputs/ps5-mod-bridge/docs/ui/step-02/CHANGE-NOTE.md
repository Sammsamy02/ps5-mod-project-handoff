# Step 2 — review, confirm, restore and per-game preview

User benefit: players can see what a mod will change, answer plain Yes/No questions, and confirm before an installer changes anything.

New modules: `web/config.js`, `installer-service.js`, `installer-mock.js`, `installer-ui.js`. App integration changes `web/app.js`, `index.html`, `style.css`. Existing browser fixtures gain only the new script allowlist entries. New service, installer screen and full-app controller suites accompany this step. Source ownership is recorded in `../OWNERSHIP.md`.

The Installed screen now puts Game mods before the older records. It provides PLAN → confirmed APPLY → RESULT, confirmed RESTORE, actual service progress with leave/return, all seven requested error states, and More info. The selected observed console game is synchronized separately from Nexus browsing; clearing or invalidating that selection cannot leave an old install plan. Its picker is locked only while installer work/status is pending. Browsing and other tabs remain usable.

Per-game preview includes on/off, Move up/Move down, conflicts, update notices, per-mod session results and self-test. Setup is a calm one-time message when reported as needed. Existing download analysis, selection/retry identity, account, inventory/paging and installed/service records are retained.

**Default installation is explicitly a mock practice run.** It changes no game/mod files. Real mode uses the shared four calls exactly; no failed real request becomes mock success. Optional progress, running-game, session or setup metadata is not required to accept an otherwise conforming reply. The runtime must enforce game closure at apply/restore. A missing capability file means unavailable. On/off and order mutations are mock-only because the four-call contract does not define them. A real download-to-install adapter must supply the trusted archive handle; the browser does not guess a path from a download ID or a game title from a Nexus domain.

Detailed evidence: `service-note.md`, `ui-note.md`, `controller/RESULTS.json`, `regressions.json`. Full-app 1920×1080 screenshots are in `controller/`; isolated screen-state images are in `screenshots/`. Test receipts record the final counts and tested asset hashes. Browser Gamepad tests cover d-pad + X/O at 1080p and 4K; physical PS5 behavior is untested.

The normal `make test-ui` remains blocked before UI tests by the existing local libarchive dependency URLs versus its commit-pinned HTTPS verifier. Dependency files are unchanged. The browser and static-delivery suites run independently. No console calls, uploads, launches, original Claude checkout edits, or game/mod file writes occurred.
