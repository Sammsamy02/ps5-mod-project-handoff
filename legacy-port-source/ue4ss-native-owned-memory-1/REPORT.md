# Scoped PolyHook owned memory provider

Implemented all four genuine `PLH::MemAccessor` virtual obligations with unchanged signatures/class layout. The separate `OwnedMemory.cpp` is guarded by actual `__PROSPERO__`; it is empty on Windows, whose original provider bytes remain unchanged. The host control macro compiles exactly the same provider body against host mapping APIs and is absent from the SDK command.

The existing ModuleSnapshot validates retained readable extents but explicitly cannot prove mapping permissions. Existing boundedAlloc returns raw addresses without shared lifetime/protection tracking. Neither is automatically registered. This additive service changes no NativeProgramContext or original PolyHook header layout, and does not establish a game memory/hook provider.

`ScopedRegion` registers explicitly caller-owned bytes. A retained owner must really retain the exact described storage; absent owner means synchronous stack/buffer scope. Callers must keep the underlying storage valid and accessible according to the declared permissions and must not externally unmap, resize, free, or change protections while registered. Registration is an explicit ownership contract, not OS validation of arbitrary supplied pointers. Overlaps and invalid extents/permissions throw. Tokens cannot revoke another scope. Both source and destination must cover the entire operation and satisfy R/W permission checks. Unknown addresses, revoked scopes, zero lengths, overflows, and bounds/permission violations refuse with zero safe-read/write byte count. Valid overlap uses memmove.

`OwnedMapping` creates actual anonymous private RW pages using mmap, retains their lifetime, and is the only protectable registration. It does not execute generated code. OS allocation refusal throws. mem_protect rounds both ends to actual owned pages, refuses unsupported flag bits and mixed previous protection, executes real mprotect, and updates tracked state only after success. Munmap cleanup failure terminates rather than silently reporting successful cleanup. Query returns current maximal uniform region metadata and optional retained owner; it does not freeze protections, register a source, or authorize later unchecked dereferencing. Consumers that directly read must retain scopes/owners and prevent concurrent protection/lifetime change; preferred readers use the checked MemAccessor operation.

A service mutex serializes bounded operations, protect, and revocation. No engine callbacks run under the mutex; arbitrary retained-owner destructors run after releasing it. Borrowed storage lifetime remains a caller obligation. The service is not a substitute for process-memory discovery or a guarded game reader.

Validation: focused host real-buffer and real-mmap controls passed with ASan/UBSan. They exercise copy/read/write, unknown/expired registrations, full bounds/overflow/zero checks, unreadable/unwritable regions, overlap registration rejection without revoking the original, retained-owner lifetime, real R and NONE page protection and restoration, per-page state/mixed-old refusal, overlapping memmove, and concurrent registration revocation. The initial missing-provider link is retained in red-1; it failed on absent genuine methods/service definitions. The small own-data SDK consumer compiled and fully linked with --no-undefined; dynamic layout was validated and all 71 genuine imports resolve to SDK libraries. No native consumer execution or console dispatch occurred. Windows compilation itself is unverified.
