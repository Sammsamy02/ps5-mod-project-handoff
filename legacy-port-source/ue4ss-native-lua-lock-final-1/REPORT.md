# Portable Lua close lock balance

The existing native LuaRaw process-lifetime recursive mutex was retained on completed lua_close. A cleanup thread could close its owned Lua state and exit while still owning that mutex; another thread then blocked entering luaL_newstate. The retained actual own-Lua failure/sample is in ue4ss-native-lua-action-lifetime-1/host-3. This successor changes only native platform_locks.c LuaLockFinal to invoke the existing checked LuaUnlock(L) exactly once.

This is derived from the genuine Lua contract: luaconf.h:798–800 invokes Initial after successful main open and on child creation, Final on complete main-state close. lstate.c:241 completes open with the Initial hook as its last step. Partial failed opens call close_state without Final. Child collection uses default luai_userstatefree and does not call Final. lua_close at416 acquires once then calls close_state; complete close at277 invokes Final and lua_close has no trailing lua_unlock. Closing via a child is normalized to its main global state. Releasing this one close-entry acquisition preserves outer recursive acquisitions and leaves the process-lifetime mutex available to other live states/coroutines. It does not destroy, replace, or force-unlock that mutex. Lua's caller obligation to quiesce uses before closing a state remains.

Host-1 passes ASan/UBSan with genuine LuaRaw C APIs over caller-owned states: cleanup thread closes, another creates/evaluates6*7=42 and closes; independent states overlap; child creation/reset/GC and close(child) succeed; three persistent allocation-failure points leave no live allocation; the next thread can open and execute; an explicitly held outer recursive acquisition still blocks another thread after a different state closes until its matching unlock. The earlier no-op Final failure is preserved unchanged.

The actual PS5 SDK native luauser unit compiled with the original exact profile in native-1. This replaces only the native compiled_source. Public Lua headers, state layouts, coroutine hook macros, Windows original luauser.c and LuaMod sources remain unchanged. Native execution and full runtime/game/console behavior were not exercised in this task.
