# Native Lua owned int32 reader

`LuaLibraryOwned.cpp` defines the actual `RC::LuaLibrary::deref_to_int32(const LuaMadeSimple::Lua&)` ABI as an additive native object. Public LuaLibrary/LMS headers and original Windows implementation remain unchanged. Native composition must append only `native-2/LuaLibraryOwned.o`, alongside the real `OwnedMemory.o` provider; the fixture main object is not a production input.

Exactly one Lua integer argument is required. It is a source address label, never permission to access or register that address. Null/negative/unrepresentable labels return nil. The source must already have a genuine caller-owned readable registration covering all four bytes. The function registers only its own stack int32 destination as writable for the synchronous read, calls actual `MemAccessor::safe_mem_read`, requires true and exactly four bytes, then revokes the destination token before any Lua push (which may longjmp on allocation failure). Registration failure also returns nil. Successful signed values include zero; source contents are never used to decide pointer validity. Invalid arguments/read failures use the nil contract without the original Windows fatal logger messages.

All 30 focused cases pass using actual LuaMadeSimple and LuaRaw and the genuine scoped service: positive, zero, negative, both int32 extrema, crossing/one-past bounds, expired/unknown/high/null/negative labels, unreadable/short registered regions, wrong arity and six wrong types, plus eight repeated destination lifetimes. Adapter/LMS/service objects have host ASan/UBSan enabled; the retained genuine LuaRaw host archive is unsanitized. No Lua or memory backend was faked.

Both additive function and native fixture compile against the actual PS5 SDK. The full native caller links with retained real LMS/LuaRaw and the frozen native owned-memory provider; all undefined imports are found in actual SDK libraries and PT_DYNAMIC geometry validates. Compilation asserts pointer/Lua integer/int32 ABI sizes. Native caller code was not executed.

Sources, exact body differences, command receipts, object symbols, provider hashes and integration instructions are retained in this spike. Host controls access explicitly registered C++ owned storage only. No engine or game memory, console contact, hook execution, unchecked dereference, or previously denied mapbase/read payload is involved. Full game pointer authority is deliberately unavailable from this API.
