# Unchanged DLL route: owned guest worker entry, offline

Stage 46 at `/WORKSPACE/.codex/worktrees/translation-core/caps-resume-20261013/caps-team-work/cg-guest-thread-entry-20261013-46` builds on the exact stage-42 loader. It adds a worker-entry primitive for a caller-created host thread. Before calling a Win64 DLL start function, it verifies that the address belongs to an attached module's validated executable range, creates that host thread's guest TEB/static TLS view, sends DLL thread-attach notifications in batch order, enters the module's guest segment, calls the start through the Win64 bridge, and sends thread-detach notifications in reverse order. If an attach fails, it detaches modules already notified. A failed detach returns a distinct dirty result.

The unchanged synthetic PE fixture was exercised on a real Mac host thread. It calls `DisableThreadLibraryCalls`, so its notifications were correctly suppressed while its start function ran behind the injected segment backend. A **copy** of that fixture changed only its synthetic import name to leave notifications enabled; it verified attach/start/detach and two-module ordering, plus rollback when the second module's segment entry refused.
