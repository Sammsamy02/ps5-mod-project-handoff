# Import registry correction: isolated Mac stage

The `cg-import-registry-20261013-12` stage fixes a generic PE import-resolution defect. `WinApiShim::resolve` lowercased DLL names, but `register_module` stored the original spelling. A registered `UE4SS.DLL` could therefore be invisible to an import for `ue4ss.dll`. Registration now uses the same ASCII lowercase key as lookup and ignores null or empty names. The registry copies the module entry under its lock and releases the lock before calling its external lookup function, so that function can resolve another import without deadlocking.

The new host test passed **4/4** cases: case-insensitive module lookup, recursive built-in resolution, missing-export refusal, and invalid registration names. Before the fix it showed the case mismatch and crashed on a null name. The existing x86-64 synthetic PE fixture was rebuilt with the changed shim and passed **11/11** end-to-end checks; its pinned source SHA-256 was identical before and after. No unchanged gameplay DLL was executed.

The [incremental patch](import-registry-increment-20261013.patch) is based on the exact prior TEB stage. The [hash manifest](import-registry-manifest-20261013.json) pins the modified shim and two new test files. A scratch `git apply --check`, application, and byte-for-byte staged-file comparison passed. [Evidence logs](import-registry-evidence-20261013.zip) include both test runs and the fixture hash check. The shared candidate and Claude's work were not changed.

This closes registry lookup behavior only. The built-in export table still stores SysV function bodies and does not yet supply per-signature Win64 trampolines, complete Windows/MSVC behavior, or a dynamic DLL loader. Most measured imports remain unresolved; the loader's static-TLS and GS refusals remain in force. Microsoft documents that [delay-loaded DLLs resolve on first use through a helper](https://learn.microsoft.com/en-us/cpp/build/reference/linker-support-for-delay-loaded-dlls?view=msvc-170). The existing analyzer already reads delay imports, none of the five current unchanged samples has a delay-import row, and this stage does not change the loader's delay-import refusal.
