# Direct GS access audit: Mac continuation

**Status:** Read-only analyzer and conservative loader guard are staged separately. Neither implements Windows TLS/TEB behavior or demonstrates gameplay on PS5. No console, shared candidate, Claude work area, or original DLL was modified.

## Finding

TLS-directory status is insufficient to identify Windows thread-environment access. The unchanged `cap13-feature-probe.dll` has an **empty** TLS directory but three decoded `GS:[0x58]` memory operands; one starts at RVA `0x101c` with bytes `65 48 8b 14 25 58 00 00 00`. The unchanged `dwmapi.dll` proxy has **no** TLS directory but a decoded `GS:[0x30]` operand at RVA `0x161dd`, bytes `65 48 8b 04 25 30 00 00 00`. In both cases the following decoded instruction dereferences the value read from GS. These observations correct the earlier inference that an empty TLS directory implies no GS access.

The new [machine-readable audit](DLL-GS-ACCESS-AUDIT-20261013.json) records the source path, unchanged SHA-256, TLS status, candidate GS sites, and offline blockers for eight native-x64 samples. Candidate counts are 14, 6, 18, 28 and 21 across the five unchanged upstream DLLs; 3 for the empty-TLS feature probe; 1 for the no-TLS proxy; and 0 for a small control. The scan uses Capstone 5.0.7 over file-backed executable sections. Linear disassembly may interpret data as instructions or miss code entered at another offset. A zero count is **not** proof that a DLL never accesses GS. If Capstone is absent, the offline dossier blocks admission as unscanned.

## Staged changes and verification

- [Incremental analyzer patch](pe-analyzer-gs-audit-increment-20261013.patch) applies after the previously published universal-admission patch, using the [exact-base manifest](pe-analyzer-gs-audit-manifest-20261013.json). It adds `gs_access` observations and an independent `direct_gs_access` dossier blocker. Focused suite: **38/38 tests**. Existing analyzer regression: **31/31 checks**. The patch was applied to a scratch copy and produced byte-identical staged files. [Evidence ZIP](pe-analyzer-gs-audit-evidence-20261013.zip).
- [Incremental loader guard patch](pe-loader-gs-guard-increment-20261013.patch) applies after the previously published loader-hardening patch, using its [exact-base manifest](pe-loader-gs-guard-manifest-20261013.json). The loader refuses any `0x65` byte in a file-backed executable section before mapping, regardless of TLS metadata. Host tests first reproduced unsafe admission with empty and absent TLS directories; after the guard, preflight is **27/27**, the existing synthetic fixture still passes **11/11** execution checks, and two unchanged real-TLS samples retain **5/5** expected-refusal checks each. macOS x86-64 `clang++ -fsyntax-only -Wall -Wextra -Werror` exited 0. The patch was applied to a scratch copy and produced byte-identical staged files. [Evidence ZIP](pe-loader-gs-guard-evidence-20261013.zip).

The loader guard deliberately treats every executable `0x65` byte as a possible x86 GS prefix, including bytes that are actually immediates or embedded data. It can therefore refuse compatible code. It also does not address dynamically generated code or provide the Windows TEB and per-thread static TLS state those DLLs require. The first audit patch is pinned to the pre-guard loader. An additional [alignment patch](pe-analyzer-gs-guard-alignment-20261013.patch) and [exact-base manifest](pe-analyzer-gs-guard-alignment-manifest-20261013.json) re-pin the registry to the guarded loader in isolated stage `cg-gs-aligned-20261013-08`. Its [aligned evidence](DLL-GS-ACCESS-AUDIT-ALIGNED-20261013.json) verifies that loader pin and unchanged hashes for all eight inspected binaries. The aligned focused suite passed **38/38** and the alignment patch reproduced byte-identical staged files in scratch; see the [alignment evidence ZIP](pe-analyzer-gs-guard-alignment-evidence-20261013.zip). The patches remain unintegrated into the shared candidate.

## Next engineering gates

2. Apply the guarded loader and aligned analyzer patches against their exact bases, recheck source pins in the integrated checkout, then test the same unchanged DLLs through loader preflight and the Windows/MSVC CRT and UE4SS ABI layers. The current five upstream DLLs still refuse real static TLS.
3. Complete the generic #3 executable detour and restoration machinery and the automatic three-gate PC-to-PS5 target proof. These are independent of this GS finding.
4. On console access, separately verify #1 user-visible read behavior, #3 patch/restore, and an unchanged gameplay DLL's intended effect for its authenticated build. No Mac test substitutes for those observations.
