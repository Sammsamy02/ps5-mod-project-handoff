# Stage 51: current guest stack output writes, offline

Stage 51 at `/WORKSPACE/.codex/worktrees/translation-core/caps-resume-20261013/caps-team-work/cg-guest-stack-write-20261013-51` is based exactly on isolated DLL stage 49. The shim now accepts an output pointer in the **current thread’s caller stack** when a guest TEB binding is active and the pointer lies between the current shim frame and the pthread-reported stack top. It rejects wrapping ranges, another thread’s stack, and stack writes outside guest entry. The existing explicit write map remains the route for mapped PE data and caller-owned heap allocations.

Mac stack bounds come from `pthread_get_stackaddr_np` and `pthread_get_stacksize_np`. The pinned PS5 SDK exposes `pthread_attr_get_np` and `pthread_attr_getstack`; stage 51 compiles and links those calls, but their behavior with a switched guest GS base still needs console testing. This stage does not publish `CreateThread` or other new Windows imports. It does not claim that arbitrary stack pointers or heap allocations are safe.
