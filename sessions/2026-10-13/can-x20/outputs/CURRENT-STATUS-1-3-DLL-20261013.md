# Current status for #1, #3, and unchanged Windows DLLs

## Goal and answer

The goal is to make memory reads (#1), code patch/restore (#3), and unchanged Windows gameplay DLLs (#13) as ready as possible offline, without changing Claude's #2/#4–12 work, the shared candidate, kernel code, or original DLLs. The runtime should use reusable code and automatically derived build facts rather than game-specific source edits.

**Status: still not a console-only wait.** #1 and #3 need console behavior tests and have remaining generic engineering. The DLL path now has a Mac-tested guarded mapper and an isolated PS5 GS backend candidate, but the default production backend still refuses entry until a console GS round trip is verified. No unchanged DLL has run or produced its intended gameplay effect on PS5. “Every DLL in every game” cannot be guaranteed from these tests: a DLL can depend on Windows/CRT behavior or PC build facts that have no verified PS5 equivalent. The correct generic behavior for an unsupported or ambiguous case is a precise refusal.
