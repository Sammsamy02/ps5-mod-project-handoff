# Automatic function, type and hook correspondence

Research note, checked **2026-09-29**. Proposed design, not an approved specification or implemented capability. No device access, executable probes, dependencies, proprietary source acquisition or third-party contact occurred. Stellar Blade remains the first test; the objective remains automatic translation across titles and mod categories without production mod-ID rules.

## What existing tools establish

- **Ghidra Version Tracking** automates exact symbol/data/function matching, disambiguates duplicate instruction matches using operands, and propagates reference/implied matches with score, vote and conflict controls. Its “accepted” state concerns analysis associations and markup; it is not certification that a replacement hook preserves gameplay behavior. [Upstream AutoVersionTrackingTask](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/VersionTracking/src/main/java/ghidra/feature/vt/gui/actions/AutoVersionTrackingTask.java).
- **BinDiff** matches function/control-flow graphs and reports similarity separately from algorithm confidence. Its manual explicitly warns that equal mnemonics can conceal different operands, immediate values and addresses. Thus high similarity can miss changed constants, accessed members or callees. [Author's manual](https://www.zynamics.com/bindiff/manual/).
- **Diaphora** provides graph, byte, pseudocode/microcode heuristics and batch automation; its strategy exports features once, orders heuristic queries by reliability, then uses call-graph propagation. These are reusable candidate generators, not a native-console semantic adapter. [Upstream README](https://github.com/joxeankoret/diaphora), [maintainer's strategy, edited 2023-12-20](https://github.com/joxeankoret/diaphora/wiki/Matching-Strategy).
- **Ghidra BSim** offers compiler/architecture-tolerant candidates using decompiler-derived features, intentionally omitting some constants, register names and types. Its own evaluation guide warns that even similarity 1.0 can import incorrect datatypes when definitions changed. [Upstream introduction](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/BSimTutorial_Intro.md), [evaluation guide](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/BSimTutorial_Evaluating_Matches.md).
- **patternsleuth** is a shared Unreal address-scanning/test system. Its object-array resolver combines patterns, operand relationships, string cross-references and single-result checks; it includes separate PE/ELF handling for one shutdown resolver. That is evidence of reusable discovery across binaries, not demonstrated PS5 coverage or discovery of arbitrary private functions. [Upstream README](https://github.com/trumank/patternsleuth), [object-array resolver](https://github.com/trumank/patternsleuth/blob/master/patternsleuth/src/resolvers/unreal/guobject_array.rs).
- **Reflection** can provide names, inheritance and typed properties/functions. UE4SS's JMAP documentation describes offsets, sizes, flags and *approximate* vtable layouts. Epic documents tagging members for reflection; native members outside that system need other evidence. Editor metadata must not be assumed present in shipping games. UE4SS documents compiler-dependent signatures and custom member/vtable layouts. [JMAP](https://docs.ue4ss.com/dev/lua-api/global-functions/dumpjmap.html), [Epic structs](https://dev.epicgames.com/documentation/unreal-engine/using-structs?application_version=4.27), [Epic properties](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties), [UE4SS compatibility](https://docs.ue4ss.com/dev/guides/fixing-compatibility-problems-advanced.html), [custom layouts](https://docs.ue4ss.com/custom-game-configs.html).

All URLs were inspected on the research date; floating branches need commit pinning in any later experiment. No reviewed source demonstrates universal source-to-PS5 correspondence.

## Proposed reusable pipeline

**1. Inventory operations, not mod identities.** From package source/bytecode/native analysis, create requirements for function calls, callbacks, globals, field reads/writes, virtual dispatch, patches and generated code. Preserve provenance to the exact source instruction or declaration. Dependencies contribute their own requirements. An inventory can be incomplete for binary-only code; unresolved indirect calls and computed accesses must remain explicit. Nexus ID/name may identify provenance, but cannot select a private translation rule.

**2. Analyze both exact builds.** Fingerprint the PC host version the mod expects and the installed target version, including executable/modules, data-schema hashes and engine revisions. Ingest accessible binaries and available symbols, unwind information, reflection/type dumps and relocation databases. A source Address Library ID must first resolve to its source-build function; it is not a target address. Engine references can bootstrap common services but cannot stand in for either game's customized build.

**3. Build a correspondence graph.** Nodes represent functions, types, members, virtual slots, globals and hook sites; edges carry call, inheritance, field-access and control/data-flow relationships. Seed candidates with qualified symbols/reflection and shared engine resolvers. Add Ghidra/BinDiff/Diaphora/BSim candidates, then propagate only from checked anchors. Store competing candidates, feature provenance, contradictions and unrepresented effects. Agreement among tools using the same graph/string evidence is correlated, not independent confirmation. Reused signatures constitute engine/runtime rules; inferred mappings constitute exact-build knowledge reused across mods.

**4. Check contracts before producing bindings.** For functions, compare parameter roles, return representation, side effects, ownership, thread requirements, error/exception behavior and callees. For types, independently map inheritance/subobjects, size/alignment, field identity/type/width, enum meaning, containers, bitfields and virtual slots. Names and compatible signatures establish useful structure but not equal meaning. Reject contradictions instead of offsetting them with a higher aggregate score. Permit “no counterpart,” inlining, splitting and merging; do not force a bijection. Region mappings may be possible but require separate evidence.

**5. Resolve hook semantics separately.** Matching the containing function does not map `function + 0x1A6`. Derive the source hook's operation and phase, then locate the target region whose operand/data-flow and lifecycle conditions correspond. Its contract includes callback inputs, live object roles, original operation order, branch conditions, register/stack/flag obligations and reentrancy. Before any later application, recheck exact target bytes, instruction boundaries, overwrite conflicts and whether displaced operations can be preserved. Vtable replacement requires the actual target slot and adjustment rules. A unique byte pattern proves a unique occurrence, not the correct callback timing.

**6. Validate observable effects and cache the evidence.** Distinguish `candidate`, `structurally checked`, `behaviorally tested within contract`, `ambiguous` and `absent`. A usable result includes the evidence scope and source/target/tool versions. Compare normalized object state, return values, event order and effects on controlled scenarios; timestamps, addresses and nondeterminism need declared normalization. Unit/emulation evidence cannot replace later in-game tests. Every build/backend change invalidates affected mappings and their dependents. Static similarity and finite behavioral tests do not prove unrestricted semantic equivalence.

## Direct memory access is a separate translation obligation

An ABI-correct call can return a target actor pointer while the PC plugin subsequently reads the wrong field offset. Ghidra's p-code supplies explicit loads/stores and data-flow analysis machinery; it does not automatically know the field's identity. [Primary p-code manual, updated 2026-01-16](https://ghidra.re/ghidra_docs/languages/html/pcoderef.html).

Investigate two shared routes: rewrite/lift accesses into typed target operations, or preserve guest-layout objects with boundary synchronization. Both require pointer provenance, alias/identity preservation, subobject adjustment, allocation/lifetime rules, virtual dispatch, container representations and concurrent updates. A shadow object must not become a stale snapshot or accidentally escape to native code. Raw copies, pointer arithmetic, unions, callbacks, inline assembly and newly emitted code can defeat simple field-offset replacement. Source-available mods may be rebuilt against generated bindings; binary-only modules still need these obligations covered. Source availability does not validate the bindings. Unmodeled reachable operations block a claimed complete translation; they motivate expanding reusable backends.

## Measurable acceptance experiments after approval

These are proposed gates; none has been run.

| Experiment | Measurement / pass condition |
| --- | --- |
| Known-reference correspondence | Compile permitted open reference programs across compiler/optimization/ABI variants. Keep debug truth hidden from the resolver; separately include real exact-build pairs when accessible. Report correct/incorrect accepted mappings, abstentions and recall by function/type/hook class. Initial unattended gate: zero incorrect accepted mappings in the declared corpus, with counts; this is not proof of zero future errors. |
| False-positive traps | Include duplicated thunks, equal graphs with changed constants, swapped same-type fields, renamed enums, altered call targets and missing counterparts. Every contradicted or ambiguous candidate must be rejected/abstained; report any incorrect acceptance. |
| Direct-access preservation | Exercise aliasing, nested objects, arrays/bitfields, virtual calls, destruction/recreation and callbacks; compare expected state/effect traces. Every accessed field and virtual slot needs a resolved contract. |
| Hook-site preservation | Change instruction spacing, compiler allocation, inlining and control flow. Require the correct logical phase and operands, preserved original behavior and rejection when no equivalent site exists; measure accepted/rejected sites. |
| Unseen mods and builds | Freeze backends, withhold independently authored packages and game updates, then run without mod-ID branches, private replacement scripts or manual output repair. Report whole-package success and unresolved operations. Manual ground truth is evaluation input only. |
| Native gameplay and performance | Once the host prerequisite is established, test load/unload, level transitions, saves, input/camera states, conflicts and rollback. Record effect differences, failures, translation/startup time, peak memory and frame-time percentiles against baseline; budgets need approval before measurement. |

Optimize later by caching immutable feature exports and verified graphs, resolving only the required dependency closure, indexing candidates, and precomputing call/access bridges. Whole-binary scans belong in preparation rather than frame callbacks. Benchmark these choices; no speed claim is currently supported.

## Missing inputs

Exact expected PC build and installed PS5 title/update identity; accessible source and target binaries/adequate metadata; mod/dependency corpus including native and generated-code cases; a separately maintained evaluation oracle; and an established console host with the necessary inspection/execution capabilities. A JMAP or symbol dump from one build alone cannot derive private members or certify the other build. Console access and experiments remain outside this research task. Stellar Blade can validate a first correspondence backend; a second title/build and different runtime family are necessary before claiming generalization.
