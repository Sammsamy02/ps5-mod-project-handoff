# Generic bounded container-reader proposal

Research proposal for the next reusable format milestone, derived from actual bounded Stellar Blade metadata samples and current core interfaces. This is not an implemented backend or permission to install. The first test target supplies evidence; game names or Nexus mod IDs do not select production parser paths. Root will shape a separate design/implementation plan before code changes.

The existing `inspect_binary` accepts a span/prefix and classifies PAK mostly by extension; UTOC remains opaque. The native DDS-only C ABI caps available input at 8 MiB. Observed AMPR metadata is16,765,348 bytes (16.765 MB,15.989 MiB) and UTOC is22,876,847 bytes (22.877 MB,21.817 MiB); declared logical UCAS files reach tens of GiB. A provider-based API must inspect bounded ranges rather than ingest entire archives or change the DDS interface's cap.

## Proposed source contract

A versioned C-compatible descriptor supplies struct size/ABI version, uint64 logical size, caller-owned context, scoped snapshot identity and checked `read_at(context, offset, destination, requested, actual)`. Caller keeps handles alive for inspection; core owns destination storage, serializes callbacks, retains no provider pointers and contains C++ exceptions. Each request is at most64 KiB; offset and requested length are checked with subtraction against exact logical size. OK requires exact requested bytes; short read, unavailable, I/O, timeout, cancellation, changed source and provider-contract errors are distinct. Providers are trusted code and must honor caller-buffer bounds; an ABI cannot validate arbitrary dangling pointers or malicious memory writes.

A frozen registry resolves only approved logical paths and paired source descriptors; there is no arbitrary file-open/write callback. Native providers use ordinary owned read-only handles; memory/desktop providers serve owned development tests. Read-only handles alone do not freeze externally mutable content. Snapshot validation and identity scope must document what is actually stable; an atomic immutable-source guarantee must not be inferred from size/mtime or range hashes. Recheck identities between phases and at completion; any detected mutation invalidates results/cursors.

Reports preserve path, exact64-bit size, provider/snapshot identity scope, parser/schema versions and offset/length/SHA256 for each observed range. Optional complete SHA256 is explicitly whole_file; a descriptor/range digest is never a full-file hash. Logical identity includes manifest identity, file ID/path/size, mapping version and participating volume identities. Cache keys bind all pairs, limits/options/codecs and identity scopes; metadata-only cache entries cannot grant writer/game acceptance.

## Provisional resource model

Candidate defaults per container bundle:64 KiB maximum read,64 MiB metadata-source size,128 MiB aggregate bytes read (including rereads and physical/logical reads),8 MiB live temporary memory,4096 provider reads and8 million record visits. Candidate format ceilings:65,536 AMPR files,2 million chunks,64 volumes;65,536 PAK entries;262,144 IoStore entries and1,048,576 compressed blocks;1024-byte logical paths. They cover observed counts but require fixture calibration. Limit exhaustion is resource_limit, not format corruption.

Charge integer arithmetic, iteration, comparisons/sorting, decoded bytes, strings and serialization to explicit work/memory budgets. No allocation scales with declared UCAS size. Reuse bounded workspaces across phases; avoid retaining the1.39 million chunk table. Compact summaries and identity-bound cursors provide up to256 entries/256 KiB JSON per page. A page is not the complete inventory. A bounded arena/output strategy needs actual implementation evidence; the present owning JSON interface does not prove this future bound.

## Separate storage and engine readers

AMPRIDX3 must validate24-byte records, UTF8/NUL/path bounds,16-byte hash slots and documented probe/hash semantics. AMPRPAK4 must verify128-byte header CRC and stream the remaining manifest for payload CRC/full metadata SHA; validate complete section geometry, flags/reserved fields, file/chunk ownership and sizes, canonical paths and safe volume names. Match file IDs/path/size with the index. AMPRCFG1 is separately CRC/build-bound. Matching AMPRDAT3 headers must prove manifest pack IDs/build/flags/exact sizes and payload bounds before logical reads.

The confirmed namespace declares five same-stem UCAS paths, but manifest file/chunk records and volume bytes are unverified. Resolve packed logical UCAS only after those mappings and corresponding volume checks. Loose entries need approved registered physical sources. RAW/raw-LZ4 decoding must validate exact decoded size and bounded cross-block/partial reads. Absence of an optional CRC sidecar must not be confused with v4 metadata corruption; payload-integrity scope stays explicit. Default metadata inspection reconstructs no UCAS/asset body.

PAKv11 is an independent container reader: seek footer, validate primary/secondary ranges and SHA1, parse bounded FString/encoded entries, enumerate names only after complete directory-index validation. IoStorev3 streams TOC/chunk/40-bit offset-length/block/directory/partition records and validates pairing with logical UCAS providers. Format version numbers are not engine/game compatibility. Unknown version/flags/codecs and missing pairs remain unresolved; no key/decryption work is introduced. Represent arbitrary binary identifiers/malformed strings losslessly without assuming UTF8 JSON strings.

Result facts distinguish metadata_complete, entry_inventory_complete, paired_sources_validated, payload_integrity_verified and identity_scope. Keep ABI/transport errors separate from malformed/checksum/unsupported/parser findings. Budget interruption or absent pages adds unresolved inspection.complete. Header/CRC success never becomes complete content validation or installation support.

## Owned fixture acceptance and sequence

Deterministic memory/fault providers cover uint64 overflow, short/unavailable reads, contract/count violations, mutations between phases, malformed CRC/layout/ownership/paths and binary-safe JSON. Small generated AMPR fixtures cover packed/loose, multiple volumes, RAW/LZ4, final partial blocks and cross-block reads, comparing logical bytes to owned originals and an independent pinned parser. PAK/IoStore fixtures cover index hashes, encoded entries, duplicate identifiers, directory pages, unknown codecs, missing pairs and partitions. Procedural metadata at those exact observed byte sizes checks actual read/memory/work bounds without giant eager buffers. Pagination and cache invalidation must be deterministic; malformed/incomplete results remain blocked. Sanitizer and native owned-fixture checkpoints establish only reader/runtime behavior.

Sequence: provider/budget/identity ABI → generic detection/status integration → AMPR index/manifest metadata → matched volume/RAW-LZ4 logical provider → PAK metadata → IoStore metadata/pairing → paged inventory/cache → native owned-fixture validation. Choose source adoption before copying upstream GPL-3.0-or-later code and pin any LZ4 dependency. Full serializers/writers, preserved bytes through writers, reversible overlays/rollback, asset semantics, runtime hooks and exact game/build acceptance stay separate prerequisites.

Primary anchors: [AMPR format](https://github.com/drakmor/ampr_emu/blob/cfa85df379f6eeeb165d7badf9b648e266fe77b7/include/ampr_emu_pack_format.h), [AMPR portable core](https://github.com/drakmor/ampr_emu/blob/cfa85df379f6eeeb165d7badf9b648e266fe77b7/include/ampr_emu_pack_core.h), [AMPR validation](https://github.com/drakmor/ampr_emu/blob/cfa85df379f6eeeb165d7badf9b648e266fe77b7/tools/ampr_pack_format.py), [PAK reader](https://github.com/FabianFG/CUE4Parse/blob/28f385e622468c4ab84997d596b46bb1c3adfcfa/CUE4Parse/UE4/Pak/PakFileReader.cs#L296), [IoStore pairing](https://github.com/FabianFG/CUE4Parse/blob/28f385e622468c4ab84997d596b46bb1c3adfcfa/CUE4Parse/UE4/IO/IoStoreReader.cs#L65). ## Design feedback still required before implementation

The independent resource audit identified six requirements. The current DDS ABI bounds input, not live memory: owning subresource JSON and its dumped string can coexist, including on size queries. Do not reuse that serializer as proof of the proposed8 MiB live-memory bound. The new provider/container API must reserve/check allocations and encoded output before constructing them, including failure/query paths; cap diagnostics and provenance, retain omitted counts, and count destination/NUL/scratch/DOM overhead. Entry count alone cannot cap JSON: escaped1024-byte paths can make256 entries exceed256 KiB.

Choose an explicit lifetime model before code: either begin/page/end with providers alive through end and bounded session state, or stateless pages that resupply/revalidate descriptors. The initial call-only lifetime and later pagination text are alternatives that still need reconciliation. Bind cursors to every source/options/limits/parser identity and position; carry cumulative work/read budgets across pages and sizing retries, release state on end/cancel/error, and avoid whole-manifest rescans per page.

Specify sequential64 KiB pass/cache/lookup schedules. One callback per1.39 million chunks would exceed4096 reads; full-table rescans per inventory entry are unacceptable. Peak accounting includes native provider caches, ownership/offset maps, sort copies, strings, raw/stored LZ4 buffers, output and provenance across all phases. Check physical off_t range before converting uint64 offsets; reserve budget before reads/decode/allocation. Counts covering observed files do not prove memory/work feasibility.

Distinguish immutable_snapshot from checked_only source stability. Read-only handles, size/mtime, a streamed digest of mutable bytes or CRC/build consistency cannot prove a coherent immutable snapshot across later rereads; mutations may revert. Cache/session reuse needs an actual stated stability guarantee, otherwise facts remain scoped and revalidated. Resolver alias/case rules must prevent swapping a participating source.

Callbacks need cooperative deadline/cancellation inputs and native provider behavior; read-count/byte budgets cannot stop a blocking/nonreturning callback. Exception containment cannot recover arbitrary memory corruption or dangling context writes. Providers are trusted code. Measured peak allocations, reads, pass visits, comparisons and decode traces on large owned native fixtures must establish eventual bounds. None of these future limits is proven by the seven small native fixtures.
