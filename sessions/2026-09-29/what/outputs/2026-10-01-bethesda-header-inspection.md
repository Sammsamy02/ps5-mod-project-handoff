# Generic Bethesda plugin header inspection

The existing package inspector now recognizes `TES4` bytes before filename extensions. The same code can inspect matching renamed plugins without a game name, title ID, mod ID or hand-prepared mapping. This adds actual header/dependency analysis; it does not install, edit or translate plugins.

The conservative profile tries known 20- and 24-byte root layouts and requires an initial twelve-byte HEDR. Layouts and field positions are grounded in pinned [Mutagen format definitions](https://github.com/Mutagen-Modding/Mutagen/blob/417e22f6c502f8e3b37d46d4a933e60d18c644bb/Mutagen.Bethesda.Core/Plugins/Meta/GameConstants.cs) and [xEdit's TES5 definitions](https://github.com/TES5Edit/TES5Edit/blob/9fb016884bec138ea6c7b872cec831537d464c3e/Core/wbDefinitionsTES5.pas). Requiring HEDR first is narrower than xEdit's unordered root schema. Header layout identifies a structural candidate, not the game, edition or platform.

Owning `facts.tes4_header` metadata contains raw flags, field/version bits, declared record count/next ID and ordered MAST/DATA pairs. Master names retain their bytes as hex, with an additional display string only for printable ASCII. Their encoding, available masters, load order and FormIDs remain unresolved. The raw names never become filesystem destinations.

Declared root bodies are capped at 64 KiB; at most 1,024 subrecords, 256 masters and 4,096 aggregate name bytes are admitted. Declared ranges must fit the logical source and captured bytes. Missing/duplicate HEDR, late truncation, invalid pairing and exhausted limits publish no positive header metadata. Compressed roots and XXXX extensions are explicitly unsupported in this profile. Unknown bounded fields remain opaque. Inspection opens no files and writes nothing.

Successful inspection is header-only. `semantic_inventory_complete` remains false, and translation, independent master resolution and remaining-record requirements stay unresolved. Later records may contain scripts or other dependencies; this inspector cannot declare a mod script-free. Full-plugin validity, resource compatibility, SKSE/DLL behavior and PS5 game acceptance are unproved. It is not yet registered as a native format adapter.

The same 14 focused tests first produced 13 failures and then passed after implementation. They cover renamed files, both layouts, owning names, exact bounds and late rejection without partial facts. A fresh strict C++20 core regression passes **179 tests, zero failures**. The exact canonical inspector also compiles for PS5 with strict warnings and zero diagnostics, producing an x86-64 relocatable object; it was not linked or executed. Source review found no actionable defect in this scope. No original Skyrim plugin was captured.

Receipts, RED/GREEN logs, independent core checks and native compilation are retained under `.superpowers/native-observations/bethesda-header-validation-2026-10-01/`; review is `bethesda-header-review-2026-10-01.md`. Townfall and Skyrim are current test samples. The next mod-consumption result requires actual build/original records, a verified loading route, a visible change and restored baseline. Reusable format rules must carry to other matching games without adding per-mod recipes.
