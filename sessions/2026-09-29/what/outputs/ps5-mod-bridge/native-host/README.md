# Ordinary SDK native status host

This is the first native application checkpoint for the console-only private mod manager. It uses C `main`, the unchanged community SDK v0.43 runtime and ordinary BSD/libc imports. It implements status/report/shutdown and reusable shared DDS/hash inspection through a C ABI. It now embeds the game-independent controller UI at `/app`, with exact `/app.js` and `/style.css` assets; `/` remains the diagnostic page. Installation, Nexus account access, downloads, conversion and game changes are unavailable.

The embedded app is a `console_preview`: all live services remain disabled and title inventory reports unavailable. Static assets bypass the 8 KiB JSON buffer, use a separate same-origin CSP and enter the build identity by their exact bytes. A fresh desktop build and owned browser fixture loaded the app with no external requests or page errors. The current app also compiles and links for PS5 with the explicit verified selected-toolchain input described below. It has not run on the PS5. The format-dispatch, captured-metadata decoder and read-only single-candidate source capture have separate PS5 compile/link evidence, without execution or actual provider integration. The refreshed embedded paging UI is compile/link checked; native paging remains disabled and uses the unavailable v1 preview response.

Native builds can pass `--llvm-selected-root /path/to/verified/selection` alongside the explicit Mbed/framework archives. This option accepts only the repository-pinned LLVM 21.1.8 selected map: 299 exact regular members, bounded reads, no links/specials/extras, and an executable archiver. The default retains full-archive verification. The selected manifest, compiler/tool hashes, SDK ZIP/tree, ABI macros and used include closure remain checked; no download or host-tool fallback occurs. The verifier change has its own recipe/cache identity and rebuilds the same crypto source/configuration. Input location is private build evidence, outside semantic dependency identity.

The separate [read-only PAK library](pak/README.md) now stages generic unencrypted v11 metadata and raw None/Zlib payload bytes. Its tracked sources pass independent upstream archive/original-file comparisons and PS5 compile/link checks. It is not yet connected to this status host or installation flows; its target executables remain unexecuted.

The separate [archive preparation library](archive/README.md) scans unchanged downloaded ZIPs, groups container members automatically and materializes selected bytes into private ordinal storage. Five real archives pass independent host payload/manifest comparisons. Its native build includes a caller-local dynamic-segment repair and a private filesystem error adapter. Standalone native payloads now extract the unchanged stamina ZIP and automatically prepare the unchanged Leon container trio on the PS5; all original members and manifests passed independent FTP readback. The integrated status host and gameplay installation remain unfinished. See the [archive checkpoint](../../2026-10-01-native-archive-pipeline.md).

A separate owned-data Lua property fixture now has PS5 execution evidence: eight cases, 9,353 checks and no failures, with its exact result independently read back. This covers synthetic Lua bindings and Boolean mask semantics over fixture-owned data. The actual Unreal reflection/game-thread provider and downloaded-mod execution remain unavailable. The SDK's default CRT initializes loader-provided privileged state. Application code uses ordinary process, socket and entropy APIs. It adds no privilege patch, custom resolver, process enumeration or syscall assembly. This artifact is **owned-process socket-spawn only**; never inject it into a game or shared process. `_exit` is called after owned socket cleanup in native builds. The freestanding diagnostic remains a separate artifact with separate rules.

The offline builder verifies the existing sibling native-probe SDK archive and selected LLVM 21.1.8 tool hashes, validates ZIP members before extraction, and verifies clang++ against the pinned clang bytes and uses the unmodified SDK C and C++ compiler wrappers. The existing bootstrap verifier checks bundled dependencies before each build. It neither downloads dependencies nor contacts a device. A development build requires an explicit private unicast PS5 IPv4 address; the default never binds every interface. Routes are exact: `GET /`, `GET /version`, `GET /report`, `GET /core`, and `POST /shutdown`. Every route requires the exact bound authority in `Host`; localhost aliases are not accepted. Requests have at most 4096 header bytes and one response per connection. There are no bodies, Transfer-Encoding, pipelined requests, query parameters, filesystem serving or permissive CORS. The last 100ms of the absolute two-second accepted-connection deadline is reserved for an error response. The development lifetime also bounds connection work.

Shutdown requires `Content-Length: 0` and `X-Modbridge-Shutdown: 1`. If present, `Origin` must exactly match `http://<bound-address>:<port>`. Duplicated framing/Host/Origin/control headers fail. This browser-origin gate does not authenticate arbitrary LAN clients. The metadata page uses a keyboard-focusable button and a CSP-hashed script; its status text is rendered using `textContent`.

The C interface in `core_bridge.h` returns owning, complete JSON into caller memory. `length` is required and excludes the NUL terminator; success requires `capacity > length`. A null output requires zero capacity and a null input requires zero available bytes. Size query or a small buffer returns `MB_CORE_BUFFER_TOO_SMALL` with the complete required length and empty output. Invalid argument, internal exception and input limit errors leave zero length and empty output. The 8 MiB available-input limit is checked before dereferencing input. DDS malformed/unsupported/truncated outcomes remain valid JSON and preserve unresolved writer and game acceptance requirements. Large inspection JSON requires the caller to allocate a suitably bounded larger buffer; there is no upload or remote inspection route.

Startup also collects one cached metadata-only `observations.entropy` record. Nonzero return, nonzero captured errno, zero progress, short and oversized results fail the checkpoint; only return zero, errno zero and exact length 32 pass. The bounded startup checkpoint now adds cached `observations.drbg`. It creates one attempt budget with limit four, performs the unchanged strict raw32 prerequisite, clears those bytes, and then initializes one private entropy/CTR-DRBG workspace. The source callback provides exactly32 per accepted poll with threshold32, SHA-512 block64 and gather capacity128.
