## Important findings

1. **Default redirects defeat exact-endpoint refusal and route confinement.** [Lines 10 and 19](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:10), with acceptance at lines 42–47. `build_opener(ProxyHandler({}))` still installs `HTTPRedirectHandler`. A service listening on the owned 8085 port can answer `/report` with a redirect to a refused port; the resulting `URLError(ECONNREFUSED)` is recorded as if 8085 itself refused the connection, permitting deployment over an existing service. The same automatic redirects can send upload/dispatch/shutdown traffic to a different route or origin. A redirected GET load route can issue another load request while the journal still says `count:1`. **Action:** reject every redirect before following it, and accept refused-port evidence only from the exact original owned endpoint. Preserve original/final endpoint and HTTP status evidence; a 3xx is an answered service and must fail preflight.

2. **Approval and ownership barriers are removable assertions.** [Lines 35–38](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:35), also lines 51, 53, 80–82, 113. Under `python -O` or `PYTHONOPTIMIZE`, these `assert` statements are omitted. An existing approval JSON with `approved:false` or a mismatching artifact/build can then reach manager/FTP operations; the one-dispatch and pre-shutdown identity assertions also disappear. The currently absent approval file still raises during its read, but absence is not sufficient once the review marker exists. **Action:** use explicit fail-closed checks that raise named errors for approval, artifact hash/size, phase ownership, unique upload, dispatch marker, report identity, and shutdown marker. Optional diagnostic assertions may remain; authorization checks must execute independently of optimization.

3. **Persistent state is not bound to the currently approved artifact.** [Lines 18 and 79–84](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:79). `dispatch()` trusts only the saved `stored_readback.matches_reviewed` boolean and catalog membership of `stored_path`. It does not compare the saved upload/readback SHA256, byte count, build ID, or filename with the current manifest/approval. If an earlier build was uploaded/read back but not dispatched, then the public artifact is replaced and approved, this function can load the earlier saved path after approving only the new local artifact. Report rejection would happen after the wrong ELF has already been dispatched. **Action:** initialize and validate a phase identity containing full SHA256, build ID, size, filename, target authority, and stored path; reject any mismatching existing state before device requests. Before dispatch, require the recorded upload/readback identities and byte count to match that exact current identity rather than relying on the boolean alone.

4. **Socket timeouts and byte caps do not enforce total transfer/readiness budgets.** [Lines 19–24](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:19), lines 59–68, 88–91, 116–125. `r.read(limit+1)` and FTP `retrbinary` can continue receiving occasional bytes before each socket timeout. The FTP callback limits total bytes to the reviewed ELF size, but never checks a monotonic deadline; a slow 1,973,432-byte readback can greatly exceed the intended operation bound. The outer ten-second readiness loop cannot interrupt an in-progress HTTP body read that keeps making partial progress. Similar logic affects shutdown polling. **Action:** define total HTTP/FTP/phase deadlines, check them through the transfer loop, and cap every underlying wait by the remaining time. Include headers/control replies and final FTP response handling in the budget. Persist the actual deadline/elapsed/failure evidence. A socket timeout alone should be described as an inactivity timeout, not a total operation bound.

5. **Shutdown can report stale refusal as current endpoint closure.** [Lines 116–124](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:116). Once an iteration sets `closed=True`, a later successful HTTP response or `HTTPError` does not reset it. If the first probe refuses while the owned PID still appears, and the next probe answers while the PID is absent, the loop can break with `closed=True` and publish `endpoint_closed:true` despite the later endpoint being reachable. **Action:** reset closure evidence for every iteration, record that iteration's response/refusal, and accept only fresh direct refusal plus fresh owned-PID absence from the successful observation cycle. Any HTTP response, including an error response, establishes reachability and clears closure.

## Minor findings

1. **Several failures are not persisted as phase outcomes.** [Lines 65–70](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:65), 95–108, 115–127. FTP transfer errors, malformed/wrong-identity reports, failed checkpoint assertions, or shutdown transport errors can leave only an earlier attempt marker and a terminal exception. For example, `readiness_errors` and the received report are not saved before `validate_report` can reject them. The code does not print a false pass, but a saved receipt cannot independently distinguish those failures. **Action:** persist a bounded `status:failed` phase record with the exact check/error and available endpoint/status/byte/hash/PID evidence before re-raising. Preserve the dispatch marker and never automatically retry a possibly delivered load. Rejecting an identity must not adopt it for shutdown.

2. **Single dispatch is correct for a serialized timeout path, but lacks an exclusive durable claim.** [Lines 17 and 79–87](/WORKSPACE/.codex/worktrees/translation-core/what/.superpowers/native-observations/drbg-console-gate.py:17). The marker is written before `http(route)` and retained when that call raises, which correctly blocks a later normal serialized invocation. Two simultaneous invocations can nevertheless both observe no marker and dispatch; in-place `write_text` also supplies no explicit crash-durability guarantee. **Action:** either make root's exclusive single-process execution an explicit enforced precondition, or use an exclusive phase claim plus atomic, flushed state persistence. Do not describe the current file write as a concurrency/crash-durable at-most-once mechanism.

## Controls that are sound by inspection

Every exposed action calls `approved()` before its preflight/device work; module initialization reads local inputs and creates an opener without issuing a request. Under normal non-optimized execution, the approval matches the current artifact/build and local hash/size. Preflight rejects a directly answered report endpoint, non-refusal connection failures, and version mismatch; Important 1 concerns redirects obscuring the actual endpoint.

Upload uses a deterministic owned basename, rejects existing same-basename catalog entries, records the attempt before POST, then obtains the actual catalog path instead of inventing a deployment directory. FTP is ordinary anonymous connection/login/PWD/RETR/QUIT only. The readback has a reviewed-size cap, exact byte count, and SHA256 equality before a success message; Important 4 concerns elapsed time. There is no FTP service start/stop, autoload edit, game-file write, arbitrary manager command, PID kill, or generic process-control route in the original source.

The serialized dispatch path records a marker before manager load, captures load transport errors, does not redispatch on readiness failure, and distinguishes manager transport acknowledgement from native checkpoint success. Native success requires the current build/origin/profile/authority, cached report equality, seven passing core checks, expected raw32/DRBG metadata, and a manager list containing the reported PID. Report-derived ownership is saved before later checkpoint checks, allowing cleanup of an identified failing owned host without treating its checkpoint as passed. Shutdown refreshes the report identity before posting the fixed owned shutdown route; it does not send PID-based termination commands. Its receipt distinguishes endpoint/PID observations from unavailable waitpid status and reconnects normally to FTP afterward.

The public manifest and local verification were read solely to establish the operational artifact/profile expectations above.
