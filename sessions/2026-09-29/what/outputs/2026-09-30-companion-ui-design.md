# Private Nexus companion and controller interface

This implements the shared account/catalog/download user flow locally before the native host is validated. The final product remains a PS5 application with reusable translation backends across Nexus; a desktop web host is development evidence, not completion of that goal. Reported hardware: firmware 13.60, Payload Manager (fork/version unknown), Stellar Blade update 01.014.001.

The companion owns provider credentials, OAuth state/PKCE, renewal, metadata, quarantined downloads and nonexecuting analysis. The browser owns only presentation and public navigation IDs. Games, Activity and Installed use the same API across Nexus game domains. Catalog games are separate from detected console titles; detection and deployment are unavailable until measured. Current jobs stop at analysis with unresolved target compatibility.

Serve the interface and API on one explicitly configured loopback origin. Validate Host and Origin, use a random HttpOnly SameSite session plus a session-bound CSRF token for mutations, refuse cross-origin access and bound input bytes and elapsed request time. Serve only the named UI assets, never arbitrary directories. Provider errors remain fixed safe messages; tokens, NXM authorization, signed CDN URLs and internal file paths never enter browser records. A website authorization URL is permitted only for the configured official Nexus OAuth flow. A public Nexus source page can be opened for free-download authorization; protocol interception on PS5 is not implemented.

Configured OAuth starts a one-use short-lived session and returns the official authorization URL. A valid callback is exchanged and its live user identity checked before replacing the previous account. Redirect the browser to a clean local URL. Cancel, invalid callbacks, network errors and missing registration preserve existing credentials. Private personal API-key use remains available through the command companion; no public release registration is required for that route.

Background jobs bind explicit game/mod/file IDs and an idempotency key. Serialize provider/account operations under the current sequential credential-store assumption. A bounded job queue downloads to a private quarantine directory, verifies bytes/hash and passes the owned archive to the core. Report downloaded and analyzed separately; never infer prepared, installed or correct gameplay from them. Free-account missing NXM authorization becomes a website-action state, not a successful download. Persist safe job receipts; after restart an interrupted job remains interrupted, without pretending resumable downloads exist.

TV controls include arrows/D-pad/stick focus, Cross/Enter action, Circle/Escape Back, L1/R1 sections and Options details. Only standard browser gamepad mapping is used; actual PS5 input is unverified. Restore public game/mod/file navigation after Nexus return, reject stale asynchronous responses, prevent duplicate mutations, and explain account/compatibility states in plain text. Details show mod facts rather than raw implementation JSON. Installation records require confirmed transaction and hash evidence.

Validation uses owned fake provider records, localhost HTTP/TLS and local archives. No real credentials, live Nexus download, console contact or game files are needed. Core G1, provider refresh/header deadlines and host/UI are independently reviewed. Console browser TLS/OAuth return, loader ABI, private console storage, asset conversion, UE4SS, Mod Engine 2 and automatic native mappings remain separate requirements.
